# Paths that spend real money

A handful of tests, evals and server features call a paid model or a paid cloud service. This guide lists every one, what arms it, and why none of them can run from `pnpm test`, `pnpm verify`, pre-push or CI. `AGENTS.md` keeps only the one-line rule and points here.

## Evals

The eval harness lives in `packages/evals` (README there). `pnpm evals:local` runs the `core` suite on a real model through the `claude` sign-in on your own machine, so it spends against your own Claude subscription. The `real-provider` tier is the exception to every sentence in this paragraph: it runs the cross-runtime `chat` suite through OpenCode on OpenRouter, bills an OpenRouter account rather than a Claude plan, needs `DORKOS_EVALS_PAID_PROVIDER=1` beside `OPENROUTER_API_KEY`, and refuses `--isolation docker` because eval containers have no network. A `--runtime codex` leg is the same shape on a different bill: `DORKOS_EVALS_PAID_CODEX=1` beside `CODEX_API_KEY`, and no docker either. Credentials resolve in a fixed order: `ANTHROPIC_API_KEY`, then `CLAUDE_CODE_OAUTH_TOKEN`, then your local sign-in; the run prints which one it used. No credential at all is a runner error, never a pass. The `docker` isolation tier is the exception: its container is sealed off from your home directory, so it needs one of the two variables and says so.

## The paid paths

**Eight paths in the repo spend real money, and each needs its OWN decision beside its OWN key.** The shape is always the same — the decision is one thing, the key is the instrument, and a key alone arms nothing, because plenty of people leave one exported and having a key is not the same as deciding to spend. Seven of the decisions are flags. The other, DorkOS credits, is a person's choice in the app's Runs on list (ADR `261001-000811`; Codex and OpenCode per ADR `261002-221210`): a session runs on credits only when a person picked them, or was told DorkOS picked them on a new link, and refuses rather than running on anything else when it cannot have them. Its environment variable can only switch credits off.

Every one of them reads its flag at MODULE scope, so no other file's `vi.stubEnv` can blank it (credits read their kill switch the same way, and can only be chosen on a computer linked to a DorkOS account, which no test's temporary data directory is); the Community gate is a standalone executable no test imports, and checks every arm before its first process, profile or network call; the Community's post checks hand theirs to the worker only in the server entry (`apps/server/src/services/spaces/main.ts`), which no test starts. **None of these twenty-one names reaches any task `pnpm test`, `pnpm verify`, pre-push or CI runs**, and none may: turbo runs strict and strips whatever a task was not told to pass, which is the only reason those commands have never been exposed. There is exactly one deliberate exception — `ANTHROPIC_API_KEY` on the `e2e` task, which none of those commands runs — and `packages/evals/src/runner/__tests__/paid-provider.test.ts` pins it by path so the carve-out cannot grow, while walking the WHOLE parsed `turbo.json` for the other names (`globalEnv`, a package-scoped `pkg#task` override and `test:watch` expose a variable just as effectively as the three keys an earlier version of that test checked). Bare vitest strips nothing, so on those paths the flag is the whole protection. And a fake key is not a safe way to run the Anthropic one: the test server inherits your `claude` sign-in and bills that instead, measured with a deliberately invalid key. The harness smoke is the one path that can PROVE which credential paid — Claude Code reports `apiKeySource` on its session-init message, and a turn served by anything but the named key fails the run.

The gate follows the **money**, not the tier name, and it answers WHICH bill a run reaches so the refusal names the right key. `--tier claude-code-cheap --runtime opencode --model openrouter/…` spends on OpenRouter, so it demands `DORKOS_EVALS_PAID_PROVIDER` exactly as `--tier real-provider` does; `--runtime codex` on any tier spends at OpenAI, so it demands `DORKOS_EVALS_PAID_CODEX` instead (`paidPathFor` in `packages/evals/src/runner/credentials.ts`).
