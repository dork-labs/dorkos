The real `gh api … --jq` prints a null result as an empty line, a string raw and
anything else as compact JSON. Eleven fixture suites ran the filter through plain
`jq -r`, which prints `null` and pretty-prints objects, so a script could pass
its suite and still misread the real empty answer (#4429: daily-release read "no
hold issue" as unreadable and refused every day). Each stub now runs the filter
through one `gh_jq` helper that matches gh byte for byte. All eleven suites stay
green, so none of their scripts had the #4429 bug; `test-daily-release.sh` is
left to #4429, which fixes that script and its stub. Test-only: no workflow,
gate or run time changes. Revert if a stub's output ever differs from what the
real gh prints for the same answer.
