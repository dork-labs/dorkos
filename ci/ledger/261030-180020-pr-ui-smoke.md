A new always-run job, `ui-smoke` (.github/workflows/ui-smoke.yml), runs the
browser specs tagged `@smoke` (98 tests in 70 files) on a pull request whose
diff touches `apps/client/` or `packages/ui/`. Any other PR, and every
merge_group build, gets a green in seconds that says it did not run. The queue's
own browser suite is unchanged.

Why: browser specs run only in the queue, so a UI break is first seen as an
ejection, and the entries stacked on it fail with it. #3159 on 2026-10-30 did
exactly that on three @smoke specs (375/390px overflow) and cost #3263 and
#3278 a queue cycle each.

Why this metric: the change exists to move UI breaks out of the queue, so the
honest number is the queue's browser-shard failure rate. Its price is the
job's wall time on UI PRs, which the PR records. Revert, or narrow the paths, if
the queue rate does not fall while UI PRs pay that time, or if the job's own
flake rate on PRs passes 2%.
