First step of DOR-5098 (every merge gate in the cloud, then auto-merge at PR open), ticket
DOR-5103. Today `hold` stops a merge only because `.temp/coord/arm.sh` and merge-tail refuse to
arm a held PR. Both run on one laptop. Once `scripts/open-pr.sh` turns on auto-merge when a PR
opens (DOR-5107), nothing local is in the path, so `hold` has to block on its own.

`.github/workflows/not-held.yml` runs `scripts/not-held-check.sh` on every PR open, push and label
change, and on every merge-queue entry (the entry's PR comes from the queue ref). It fails while
`hold` is on and prints the `hold:` reason when there is one. It reads labels and comments with a
read-only token and runs main's copy of its scripts. It has no path filter and no job-level `if:`,
so it never passes by being skipped.

It lands advisory. It becomes a gate when Dorian adds `not-held` to the ruleset's required checks.
Before that, confirm it has reported on PRs and on queue entries.

Hygiene, not an experiment: it enables auto-merge rather than moving a metric itself. The metric
it serves is `tracked.green-to-armed` (baseline p50 21.4 min, Nov 17–19, target 0 once PRs
auto-merge). Revert if it goes red on a PR with no `hold` label, or if it fails to report on a
merge-queue entry.
