DOR-5124, under DOR-5098. Since #4198, main requires `not-held`, `release-window` and `pr-gates`,
and `open-pr.sh` turns on auto-merge when a PR opens, so nothing arms a PR any more.

- Deleted: `merge-tail.yml` and `arm-door.yml` (both disabled in GitHub since Nov 18 and Nov 23),
  and the arming decision `should-arm-automerge.sh` with its input builder and both fixture suites.
  `scripts/arm-door.sh` stays, because `pr-gates` runs its decision code.
- Kept: merge-tail's second duty, re-requesting a Claude review lost to an infrastructure failure,
  now `review-redispatch.yml` with the same decision (`should-redispatch-review.sh`), the same app
  and the same code. It was off with merge-tail. It matters more now: `pr-gates` waits on the
  review's Security verdict, so a lost review would leave a PR waiting for ever. Its access probe now
  fails the job, since it is the workflow's only duty.
- `AGENTS.md`, `contributing/ci.md`, the merge guard's message and `dependabot.yml` no longer
  send anyone to `arm.sh`. The local `.temp/coord/arm.sh` is untracked and left in place.

Baseline (Nov 23): lost reviews re-requested: none (merge-tail off since Nov 18).
Target: a PR whose review died to an outage gets a fresh review within one delivered tick, with
no person, and no PR waits on `pr-gates` for a review that never came.
Evaluate: Dec 1.

Revert the redispatch half if it loops labels or the app's probe goes red every tick.
