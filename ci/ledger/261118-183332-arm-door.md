The local arm script is the one place that runs every gate before a pull request is queued:
Security's label at the head, QA's and the designer's sign-offs, and a verify proof or a logged
waiver. Nothing on GitHub held those. Every agent acts as one login, so a bare `gh pr merge --auto`,
a GraphQL enqueue or merge-tail's schedule queued a pull request exactly as the script does. #3913
merged that way with no Security label, and #3934 went in eight seconds before QA's.

The change: `.github/workflows/arm-door.yml` runs on `merge_group: checks_requested`, the one event
every queue entry raises whoever queued it, and `scripts/arm-door.sh` decides on what the head
carries, not on who queued it:

- **Pulled** when the head has no `security-reviewed` label added at or after its commit (every PR,
  the same rule the release range check applies; docs PRs get a light label quickly, and if docs
  are ever exempted both checks change in one PR), or no verify proof: the arm script's
  `arm-record` stamp naming one (local `pnpm verify`, PM waiver, docs-only, green CI), a docs-only
  diff, or every required check and all six test shards green at the head (never for a PR touching
  `.github/`). So a careful merge by a person from the GitHub page goes through.
- **Commented** when the gates are met but the head has no `arm-record` stamp: the arm script's other
  gates were skipped, and the author is told once per head. Counted by
  `tracked.unarmed-queue-entries`, reported beside the target.

It fails open: anything it cannot read keeps the entry, with a warning and one comment. It stays
green and is not a required check, so its own errors can never eject anything or jam the queue.
The ruleset is unchanged.

**merge-tail** (disabled since 2026-11-18) is held to the same gates: what it queues stays only with
Security's label at the head and a proof the door can see (docs-only or green CI, since merge-tail
writes no stamp), and gets the unarmed comment. The door does not check QA's or the designer's
sign-offs, so merge-tail stays off until it runs the arm script's gate code.

Limits: a stamp is not a signature (any session holding the shared login can post one; per-role
GitHub Apps, DOR-3183, are the real fix), and it never expires on its own (the arm script withdraws
it when it pulls a PR or an arm does not take).

Revert, or narrow it, if it takes out a pull request whose head did carry both gates (a misread
label or check-run time) more than once in the window.
