The local arm script is the one place that runs every gate before a pull request is queued:
Security's label at the head, QA's and the designer's sign-offs, and a verify proof or a logged
waiver. Nothing on GitHub saw it. Every agent acts as one login, so a bare `gh pr merge --auto`, a
GraphQL enqueue or merge-tail's schedule queued a pull request exactly as the script does, and two
did in two days, found only by tracing transcripts.

The change: the arm script stamps the head with an `arm-record` commit status (agent, session,
proof) just before it enqueues. `.github/workflows/arm-door.yml` runs on
`merge_group: checks_requested`, the one event every queue entry raises whoever queued it.
`scripts/arm-door.sh` decides whether the head's newest `arm-record` is missing or not `success`;
if so, the door logs a warning and tells the author once per head. It is **comment only**: it never
takes an entry out, it stays green, and it is not a required check, so it can never jam the queue.
The ruleset is unchanged.

Taking unstamped entries back out is a separate decision, because it changes how a person merging
from the GitHub page and outside contributors merge, and every doc that says "arm with
`gh pr merge --auto`". If that is decided, it needs its own entry: merge-tail (disabled since Nov 18)
must run the arm script's gates or be exempted first, or the two would fight.

The target is one: a named, visible skip should make the next one rarer, not impossible. Limits: a
stamp is not a signature (any session holding the shared login can post one; per-role GitHub Apps,
DOR-3183, are the real fix), and it never expires on its own (the arm script withdraws it when it
pulls a PR or an arm does not take).

Revert if it posts on a pull request the arm script did arm (a stamp lost between the status write
and the queue's read) more than once in the window.
