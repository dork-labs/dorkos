The prerequisite for DOR-5107 (auto-merge at PR open, under DOR-5098). arm-door asks whether a
head has its sign-offs only once the PR is in the merge queue, and pulls it out when one is
missing:

- Security's `security-reviewed` label, added after the head;
- QA's `qa-real-data` label, where the PR needs it;
- the designer's `design-ok` label, where the PR needs it.

Today a person or the local arm script waits for those labels before queueing. With auto-merge at
open, GitHub would queue every PR as soon as its required checks went green, and arm-door would
bounce it.

`.github/workflows/pr-gates.yml` asks the same question on the PR, on every open, push and label
change, and on queue entries. `scripts/pr-gates-check.sh` builds arm-door's payload, runs main's
`scripts/arm-door.sh verdict`, and drops only the verify-proof reason, because the other required
checks are that proof. It fails closed, where arm-door fails open.

The check lands advisory. Once `pr-gates`, `not-held` and `release-window` are required, `open-pr.sh`
can turn on auto-merge and `arm.sh` can retire.

Hygiene, not an experiment. It serves `tracked.green-to-armed` (baseline p50 21.4 min, target 0).
Revert if it disagrees with arm-door on a queue entry, or goes red on a PR whose labels are all
fresh.
