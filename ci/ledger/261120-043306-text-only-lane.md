DOR-4834. DOR-4833 changed the company's address: one string in `packages/shared/src/company.ts`
and the tests that assert it. Every package imports `@dorkos/shared`, so the pull request ran six
test shards and four smoke shards (about 200 job-minutes on its first push) and its queue build would
run the full six-shard unit sweep, the six-shard browser suite and first-run, for a change no test
outside the files it touched can see. `scripts/no-code-scope.sh` only skips prose paths, and only on
the pull request.

The change: `scripts/text-only-scope.mjs` parses both sides of every changed `.ts/.tsx/.js/.mjs`
file with the TypeScript compiler and walks the two trees token by token. It qualifies a change only
when the trees are identical except inside string literals, template literal static parts and JSX
text (comments are trivia and drop out), and every other changed path is Markdown. It refuses, and
every suite runs as before: security paths (read from security-gate.yml, not copied), `.github/`,
`scripts/`, lockfiles, migrations, config files, added, deleted or renamed code, a mode change, any
other file type, a string in code position (module specifier, property name, type, `case`,
comparison, directive, tagged template, decorator, any JSX attribute but `aria-label`,
`aria-description`, `title`, `alt`, `placeholder`), a string that looks like a URL, path, scope,
identifier or command, a changed placeholder, or anything it cannot parse or decide. It runs from the
base commit on `pull_request` only (not into `release/`).

Scope is the pull request alone. A `merge_group` build never runs the classifier: its decision step
answers "not text only" without looking, so the queue runs the full six-shard unit sweep, test-binary,
the six-shard browser suite and first-run exactly as on `main` before this lane, the same way the
docs-only skip (`scripts/no-code-scope.sh`) only skips on pull requests. The queue stays the safety
net under a wrong "text only" verdict: what the lane lets a pull request skip, the queue still tests
before anything lands. browser-shard and first-run no longer depend on the decision at all.

When it qualifies: test-shard-count gives one shard, which runs `scripts/text-only-tests.sh`
(`vitest related` per owning package, over the changed files plus every test that quotes a changed
string's old text) and test-binary stands down. browser-test runs the specs under `apps/e2e/tests`
that quote the old text on one smoke runner, or no browser job when none does, and the fan-in accepts
that. typecheck, lint,
copy-spec-drift and the other test.yml jobs (community-pg, community-packaged, codex-sandbox) run as
always, and the main canary runs everything.

Measure: per text-only PR, the job-minutes of test and browser-test on the pull request (target: a
DOR-4833-like PR finishes both in minutes, about 15 job-minutes per push instead of about 200; its
queue build costs what it did before), and the count of runs whose log says "Text-only lane". Text-only PRs are a small share of
merges, so the scored per-PR mean barely moves; expect `inconclusive` there and read the direct
counts.

Revert if a queue ejection or a red main canary traces to a change this lane let skip the full suite,
or if any run with a code change in its diff logs "Text-only lane".
