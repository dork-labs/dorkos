DOR-3223 closes a missing quality gate: a security-reviewed label survives a push,
so it cannot prove that Security reviewed the code entering the queue. This is
hygiene, not a speed experiment. CI Steward's 2026-10-20 snapshot reports healthy
collection and a headroom tripwire; this change makes no claim to improve those
numbers or change the existing gates.

The security-gate PR and queue verifiers run only base code, with job-level
contents/statuses/pull-requests read permission. Only the separate security-review-initialize pull_request_target
initializer writes statuses and audit comments, from the exact trusted base SHA.
The workflow's path list is Security's 2026-10-22 04:56 list and covers .github/.
A sensitive head starts pending unless Security already approved that exact SHA.
An automatic "no security paths" success cannot approve a sensitive live diff
against another base. Audit comments record state changes without target_url text.

The queue walks the group's base/head chain through paginated queue entries,
classifies each live diff, checks each head status, and rechecks membership and
heads. Missing, incomplete, ambiguous or stale membership fails closed. Fixtures
include a candidate branch replacing both its workflow and script with exit 0:
the pinned-main/base fixture must still refuse its unapproved queue head.

Security's follow-up identified that an ordinary named check can replace its own
YAML from the candidate tree. Enforcement therefore requires an organization-level
"Require workflows to pass" rule sourcing .github/workflows/security-gate.yml
from dork-labs/dorkos at refs/heads/main. This PR changes no live ruleset and adds
no required named context. ci/required-checks.json remains the existing named
status-check set; the generated docs match it. The strict RequiredChecksSchema
cannot represent required workflow sources, and the current census does not
validate them. Promotion is blocked on extending that model and live comparison;
ci/security-gate-promotion.md gives the coordinator the exact rollout and proof.
Do not call this gate enforced until the pinned-main workflow rule is active.

This PR also bootstraps before its base contains the verifier. Its base-source
job will fail on the missing script/fixtures until the reviewed code lands; it
must not fall back to executing candidate code. The initializer likewise becomes
available on main only after merge. The author must not approve their own SHA.
Security review, hold and auto-merge-off remain in force for this PR.

The queue's MergeQueueEntry.baseCommit/headCommit correspondence and rebuild timing
are still unproven until a captured real multi-entry queue/event pair confirms
them. Revert an incompatible queue model rather than weakening missing-data
refusals. Separate agent identities (DOR-3181 / posture item 22; related boundary
DOR-3183) still own approval provenance: shared owner credentials can post a
status even though verifier workflow tokens cannot. No Administration permission
or new credential is introduced.
