`typecheck` runs about a dozen policy gates (retired words, copy length, the copy
a browser spec quotes, one-shot routes, boundary, config migration, NUL bytes,
dead doc paths, the repo-wide scripts suites, the census and the ledger checks)
before `tsc`, so a red `typecheck` can mean anything (DOR-4949).

Three steps, so no gate is ever off a required check:

1. **This change.** A new `policy` job in typecheck.yml runs the same steps, with
   the same triggers and no path filter. `typecheck` keeps them for now, because
   `policy` is not required yet. It costs one more runner for those steps (no
   tsc, no build), about the length of the scripts suites.
2. **After `policy` has reported green on pull_request and merge_group:** an
   agent PR adds `"policy"` to `contexts` in `ci/required-checks.json`, with one
   census-allowlist `step-if` entry for `policy`'s "CI Steward ledger coverage"
   step (the same reason `typecheck` has). Then a person adds the status check
   `policy` (integration: GitHub Actions) to ruleset 19893973 ("main: merge
   queue"), beside `typecheck`.
3. **After the ruleset has it:** an agent PR removes the policy steps from
   `typecheck`, which keeps the typecheck step and the ratchets (knip needs the
   build `turbo typecheck` leaves), and updates its gates.yaml purpose.

Hygiene, not an experiment: step 1 moves no gate and adds no required check.
Revert by deleting the job.
