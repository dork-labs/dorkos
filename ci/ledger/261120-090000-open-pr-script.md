On 2026-11-20 a coordinator brief told agents to open security-path PRs with `hold`, while
`.temp/coord/arm.sh` refuses `hold` and never lifts it. Nobody's name was on those holds, so 19
PRs sat for 9 hours. The rules for opening a PR lived in prose (the creating-pull-requests skill
plus briefs), and prose drifts.

They now live in `scripts/open-pr.sh`, pinned by `scripts/test-open-pr.sh`: the open-PR cap, the
review label from the security-gate path list, `skip-changelog` and `needs-design` from the diff,
the provenance line, and every label at creation. `hold` goes on only with `--hold "<reason>"`,
which also posts `hold: <reason>`; gate labels cannot be passed through. In Claude Code,
`.claude/hooks/pr-create-guard.mjs` refuses a bare `gh pr create` (and REST or GraphQL PR
creates). For every harness, including Codex and OpenCode, the advisory `hold-reason` workflow
goes red when `hold` is on and no comment starts `hold:`. It is not a required check.

Hygiene, not an experiment: `tracked.green-to-armed` is not computed by the collector yet, so
there is no baseline to move. Revert if the guard blocks a `gh pr` command other than create, or
if `hold-reason` runs cost more than they catch.
