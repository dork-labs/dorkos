# Resource and local-tool seams

`LocalResources(config, pathPolicy, workingDirectory)` performs no IO in its constructor. All roots come from the host. The working directory must be absolute; relative grants resolve against it. Grants must resolve to existing filesystem roots. Canonical targets follow symlinks before parent segments, including dangling links and missing destinations. These checks constrain file tools; they do not provide an operating-system sandbox or unrestricted shell authorization.

`load()` assembles outer-to-inner ancestor AGENTS.md, agent AGENTS.md/SOUL.md, supplied memory/context, already encountered nested instructions and a body-free skill catalogue. It also acknowledges pending nested instructions. The facade must call it before **each model request** and share the same Resources instance with its tools. Do not call `load()` inside a tool to acknowledge instructions.

`beforeFile()` discovers only applicable nested instructions. Pending instructions remain pending until `load()`; a first write/edit, or a write following a read in the same tool batch, returns an error with `{retryRequired:true, mutated:false}`. After the next prompt refresh the model can retry. Read/search results carry complete pending instructions in structured output. Instructions never add grants.

Skill roots are highest priority first. Traversal is sorted; a SKILL.md directory ends traversal for that skill. Canonical directories prevent cycles, and canonical files are consumed at their first root appearance, even if a name collision loses. Qualified names use `namespace:name`; the first qualified-name occurrence wins. Distinct physical files can expose the same local name under distinct namespaces. Missing roots are skipped; invalid metadata, denied paths and oversized resources fail clearly. Individual resource files are capped at 256 KiB. Disabled skills stay in host metadata but are absent from the automatic catalogue and rejected by `load_skill`. Relative resource paths resolve beside the canonical skill file, stay inside its directory and remain grant-checked. Script execution belongs to builder.

`createLocalTools` returns read/write; `{builder:true}` adds exact edit and literal search. Default bounds: 1 MiB per file/write, 16 KiB text output, 256 KiB complete instruction output, 1,000 searched files and 4,000 traversed directory entries. Text truncation is explicit; oversized files/instructions are refused. Exact editing rejects empty, absent and multiple matches, including overlapping occurrences, and preserves unchanged bytes. All operations receive the caller's cancellation signal. File and resource reads reject nonregular files before opening, then use nonblocking, no-follow opens and validate the held handle. Writes validate the held handle before truncation. Final file opens refuse leaf symlinks; targets are revalidated after instruction callbacks. File grants are not protection against an adversarial process continuously replacing parent directories.

`createWebFetchTool` requires host URL policy. HTTP(S) URLs without embedded credentials are checked before the first request and every manual redirect. Defaults: 1 MiB response, 16 KiB text output, five redirects and 30-second timeout. HTTP errors, policy refusal, malformed arguments, oversize bodies and cancellation return tool errors. A waiting async policy also settles on cancellation. No search service, browser dependency, vendor configuration or automatic credential discovery is involved.

All implementation is original; no upstream source was extracted for these modules.
