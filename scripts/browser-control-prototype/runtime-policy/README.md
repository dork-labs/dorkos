# Native metadata option experiment

**Proposed, rejected for full coverage.** This is an isolated feasibility leaf. It is not an installed dependency patch, production activation or readiness approval. No manifests, lockfiles, frozen prototype modules or installed packages change.

Run the retained probe with `node scripts/browser-control-prototype/runtime-policy/run-identity.mjs "$PWD"`. It deliberately exits **1** for the observed shared/service worker identity failure. Run the harness checks with `node --test scripts/browser-control-prototype/runtime-policy/identity.test.mjs`; those tests verify the candidate is rejected rather than treating its failure as production success.

## Owned fixtures and cleanup

Two fake HTTPS origins bind only 127.0.0.1 on distinct ephemeral ports. A generated localhost/127.0.0.1 SAN certificate supplies one recorded SPKI SHA256 fingerprint. Native Chromium receives only `--ignore-certificate-errors-spki-list=<that fingerprint>`; no global ignoreHTTPSErrors, general certificate switch or operator/system trust change. The [pinned Chromium declaration](https://raw.githubusercontent.com/chromium/chromium/153.0.8010.12/services/network/public/cpp/network_switches.cc) defines exact-key matching and requires a user-data-dir; Playwright owns the temporary profile. This exception is fixture-only and must never enter production policy.

The subprocess launches the exact executable with `chromiumSandbox:true`, records actual `ChildProcess.spawnargs` sandbox/certificate flags and refuses `--no-sandbox`. Actual sandbox-enabled launch succeeded; this is not an OS sandbox audit. There is no fallback. The native baseline preserves MacIntel/10_15_7 legacy conventions while its actual native descriptor reports arm/64/macOS26.6.2 and Chromium153/GREASE brands. No Google Chrome brand is invented.

Cleanup is available before configure/acquisition. The parent records its worker PID/birth, receives the launched browser root identity, snapshots attributable descendants before stopping the worker (including failed acquisition), deduplicates identities and waits until every recorded live/non-zombie identity is gone. Exact-identity termination is the last resort. No broad/name/group signaling occurs. A cleanup observation failure remains unverified; no invented zero process count. If the whole-table observer fails, graceful close still runs, followed only by strict PID/birth checks and termination of already recorded identities if necessary. The original observer error is rethrown after cleanup; the runner records `cleanup.status=unverified`, `inventoryComplete=false` and `allGone=null`, preserving any earlier candidate FAIL. The Node-only observer-failure regression makes `ps -axo` fail while exact `ps -p` identity checks work; it failed against the original helper because the worker remained live, then passed after this correction. A separate Node-only healthy-path check retains complete recorded-inventory success. No Chromium remeasurement follows from these cleanup checks.

## Smallest next candidate, proposed only

First prove the **unchanged native identity mode** across the same complete target/lifetime matrix with no UA or metadata override. This uses the existing supported Chromium/Playwright APIs and never changes identity after target creation. It is an explicit native runtime option, not silent fallback from failed Chrome-compatible mode; the reduced HeadlessChrome token remains disclosed. It does not satisfy a promise of Chrome-compatible normalization by itself.

Chrome-compatible mode remains blocked. A next option must supply context-wide native identity before the service-worker script request, not merely install metadata after attachment. Prefer a reviewed upstream browser/context policy capability if one can cover that boundary; no such complete pinned API has been established here. Evaluating an actual branded Chrome runtime would remain separate, private-profile-only, with its actual native identity and full matrix; branding alone is not proof it removes HeadlessChrome or preserves every target.

Any future target-level candidate must extend Playwright's existing owned attachment paths, with one lifecycle authority, rather than introducing a competing autoattach/debugger client that steals Page or worker sessions. Its target-resume barrier cannot certify a script request that already occurred. A custom private bridge, late worker override, browser launch UA string or JS getter shim is not accepted by this experiment. No production default changes follow from these findings.
