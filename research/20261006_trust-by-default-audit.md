# Trust audit: every gate on what an agent can do

Read-only audit of `dorkos` at `54279137c` (2026-10-06). Scope: `apps/server`, `apps/client`,
`apps/community`, `apps/desktop`, `packages/*`, `packages/cli`, plus docs, meta, contributing,
AGENTS.md and ADRs.

Classes used throughout:

- **A. Trust gate.** Exists because we do not trust our own agent. Default: remove or open.
- **B. Accident/runaway guard.** Loops, cost, machine-speed ping-pong, bugs. Default: keep as a
  notice + pause anyone can lift, at a generous threshold.
- **C. Outsider security.** Strangers, unauthenticated callers, injected content, third-party code,
  the public internet. Keep.
- **D. Privacy/ownership.** Whose data is whose.
- **E. Dev-repo hygiene.** Repo hooks for coding agents working on this repo. Not product.

File counts are `grep -rl` over `apps/` + `packages/` (`.ts`/`.tsx`, no `node_modules`/`dist`):
"src / test". They measure blast radius, not exact diff size.

---

## 0. Bottom line

1. **The product already half-believes this.** The litepaper's "Autonomous by Default" section
   (`meta/dorkos-litepaper.md:258-260`) says it. The `full-power-defaults` programme (DOR-1431,
   shipped 2026-08-23) made Full power the recommended onboarding choice. The repo's own CI
   runs this way: ADR `260919-174348`, "Merges are fully autonomous; machine gates are the only gates".
2. **The gates mostly do not hold against the agent they target.** The code says so itself:
   `services/core/approvals/decision-authority.ts` ("local-trust"). With login off, the shipped
   default, "there is NO cryptographic distinction between the person at the keyboard and an
   agent running `curl`". `permission-enforcement.ts` says the same about Blocked. So the A gates
   are friction for honest agents. They are not a barrier to a misbehaving one. Removing them
   gives up very little real security.
3. **Even "Full power" asks a lot today.** The Full preset (`packages/shared/src/permissions/permission-presets.ts:74`)
   still sets packages, settings, safety, permissions and reach to Ask. Every destructive
   action asks. Agent-made schedules park at `pending_approval`. Connectors need per-agent
   grants. Extensions an agent writes need a person's approval. External chat initiation is off.
   Notify is capped at 10/h, posts at 3/turn and reactions at 20/h. Reply limits are on.
4. **A fresh install that skips the door is far stricter.** It runs on the hidden "Unchanged"
   table (`permission-presets.ts:120`): Rooms is Blocked. On Claude Code and OpenCode,
   `runtimes.defaultTrustStop: null` falls through to each runtime's own `default` mode, which
   asks before every edit and command. Codex's `default` is read-only and never asks
   (`codex/runtime-constants.ts:94-95`). Cross-project agent messaging is denied, because mesh
   writes a catch-all cross-namespace deny (`packages/mesh/src/topology.ts:97`).
5. **The audit trail is not yet the safety net it has to become.** Fix it before removing gates
   (see §4).
6. **About half of the restriction code is not class A.** It defends against strangers,
   third-party code, loops, or the exposure perimeter. "Trust our agents" must not quietly become
   "trust whatever reaches our agents". The most dangerous mistake is making every _session_
   start at full power, rather than every _agent we own_. Sessions started by a Telegram
   stranger, an email, a webhook or an A2A peer must keep seeding nothing.

**Code that assumes a gate exists:**

- The tier choke point is load-bearing for C consents: hooks, global plugins, marketplace links, connector destructive and template installs all reach a person through `approval_required`. Removing tiers wholesale removes those.
- `mcp-tool-gate.ts` throws at server build for a tool with no tier. Removing tiers needs a replacement census, or the registration check dies too.
- Room and relay loops terminate only through `CascadeGuard` / `TurnBudget` / `RelayTurnCeiling` / envelope `maxHops`. An `always`-engaged agent pair has no other brake.
- `permissionSeedForOrigin` returning `'none'` is what keeps bridged messages, `externalAuthor` room turns and connector events from inheriting the operator's power. A naive "every session starts at autonomy" bypasses it, because a new row seeds from config.
- `config-write-policy.ts` is the only thing stopping `config_patch({auth:{enabled:false}})` or a planted tunnel authtoken from an agent that just read a hostile web page.

## 4. Prerequisite: make the audit trail real first

The new model replaces "ask first" with "everyone can see what happened and act". Today:

1. **Allowed calls on the ~45 hand-registered MCP tools are not recorded** (`mcp-tool-gate.ts:43-49`, stated as a known gap). Only the registry's `act` calls are attributed.
2. **Identity is optional.** `X-DorkOS-Agent` can be omitted (`middleware/agent-identity.ts` "never rejects"). With login off, an agent's action can arrive unattributed.
3. **Activity retention is 30 days** (`index.ts:1401`, `DORKOS_ACTIVITY_RETENTION_DAYS`).
4. **Agents cannot read other sessions' transcripts.** Message search is owner-only and "reachable by no agent" (`routes/search.ts:31`). So agents cannot do the reviewing.
5. Shell commands live only in runtime-owned transcripts (Claude JSONL, Codex threads, OpenCode store), with no unified "what did agent X do today" view.
6. Pause levers exist but are scattered: room halt, binding `enabled`, task pause, per-agent stop. There is no single "pause this agent everywhere" anyone can press.

Do these before (or with) phase 1. See `research/20261006_audit-trail.md` in this same batch.

## 6. Top 5 places where removing a gate would be dangerous

1. **Origin-based power seeding** (`session/origin/turn-origin.ts:202-245`; binding `permissionMode: 'default'`, `relay-adapter-schemas.ts:643`; `dmPolicy` allowlist `:150`). If "full power by default" is implemented as "every new session row starts at `autonomy`", any Telegram DM, Slack message, inbound email via a connector event, webhook or A2A call gets a shell on the machine. Trust attaches to _our agents acting on our instructions_, never to the message that woke them.
2. **The exposure and credential perimeter** (`config-write-policy.ts` for `auth.*`, `tunnel.*`, `mcp.*`, providers; `exposure-guard.ts`; `source-write-policy.ts`; `extensions.trustedSources`). An honest agent that reads one hostile web page or email can be talked into `config_patch({tunnel:{authtoken:…}})` or turning login off. That converts "trusted agent" into "anyone on the internet". These are Owner-role settings, and the exposure guard gets _more_ important when agents run at full power.
3. **Third-party code consent** (hook projection `harness/hook-approval.ts`; global plugin consent; marketplace-origin extension approval and isolation; package-content schedule clamp). Trusting our agents does not mean trusting a stranger's `hooks.json`, and "an agent installs a package" is exactly how stranger code would arrive. Keep these approvals, now as the main remaining use of the approval card.
4. **Loop terminators** (`cascade-guard.ts`, `turn-budget.ts`, `turn-ceiling.ts`, `budget-enforcer.ts` + `inbound-turn-budgets.ts`). These are not distrust. Two agents on `always` in one room, or a relay A↔B pair, will reply to each other at machine speed with real token cost. The only thing stopping that today is a refusal. Convert to pause + notice, and make sure the lift cannot come from an agent inside the loop. Never set them to unlimited.
5. **Irreversible external actions and outbound reach** (`connectors.execute_destructive` per-call approval, `execution-broker.ts:232`; browser egress private-network guard; `canInitiate` into _shared_ chats). The audit trail can show that an agent deleted a customer's email or posted in a client's Slack channel. It cannot undo it. And connector reads are the main channel for injected instructions. Recommend a decision between an undo window plus notice and an injection-taint rule (ask only when the turn ingested outside content). Silently dropping the gate is the wrong answer.

Honourable mention: **separation of duties.** If "agents can decide approvals" is implemented without "never the requester", an agent can approve its own perimeter change.

## 7. Recommended order

1. **Decide and write it down.** One ADR, "Agents are trusted by default; outsiders and third-party code are not". It supersedes the A-set in §2.5, amends `260727-181825` rule 1 and the frozen-preset rule, and states that this posture _is_ applied by migration (overriding `260822-235759` A1). Update `.claude/rules/safe-defaults.md` in the same PR, because every future default gets judged against it.
2. **Audit trail first** (§4): attribute and record every allowed call on both MCP servers and the REST surface; make identity mandatory for agent-originated calls; lengthen retention; give space members read access to transcripts and activity; add one "pause agent everywhere" lever.
3. **Flip defaults with no deletions:** Trusted preset, `defaultTrustStop: 'autonomy'`, open mesh, agent schedules arm immediately, `canInitiate` on for the operator's own DM, every-agent connector access on connect, local agent-authored extensions auto-approved. Add a migration for existing installs plus a one-time notice. Rewrite onboarding and the door. Pin the C invariants with tests _before_ this lands: outsider-origin seeding stays `'none'`; perimeter fields stay Owner-only.
4. **Remove the pure friction:** the 428 ritual and ack field, unattended confirm dialogs, notify/reaction/posts/canvas caps, blocked-request limiter and `request_permission`, cross-runtime cap, `control_ui` refusal, the `alwaysAsks` and destructive post-rules for in-circle actions, operator-only on A fields, runtime/model/NOPE cards, mesh visibility filter, community "agents cannot join channels".
5. **Convert B guards to notice + pause:** cascade guard, room and relay budgets, envelope budget (raise thresholds, surface dead letters). Ship with an eval of the two-agents-on-`always` loop that proves it still stops.
6. **Roles:** replace person bars with Owner/Admin/Member checks (agents get accounts with a role; default = owner's role for in-circle actions, never Owner-only perimeter). Approvals become "anyone with the role except the requester".
7. **Collapse the permission machinery** once phases 3 to 6 have held for a release: delete presets, the Unchanged table, the upgrade sweep, arrival narrowing and always-suggestion. Keep the choke points as audit points and keep the slim approval service for C consents. Per AGENTS.md, leave no dead code behind.
8. **Docs, meta, copy** alongside each phase (not batched at the end): `docs/guides/permissions.mdx`, `tool-approval.mdx`, `action-approvals.mdx`, threat model, brand-foundation security posture, litepaper l.95/158/165, the etiquette mechanism clauses (E8/E16b/E18a), and AGENTS.md l.11 and l.147.
