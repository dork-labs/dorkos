## 1. Stage-by-stage path from edit to main to release

```
 EDIT (Claude Code session, usually in a worktree)
 │  PreToolUse(Bash)  : file-guard, git-guard, process-guard      [3 node spawns / Bash call]
 │  PostToolUse(W/E)  : typecheck-changed (workspace tsc, 9/24 ws),
 │                      lint-changed (eslint 1 file), check-any-changed  [blocks via exit 2]
 │                      (+ typescript-lsp plugin diagnostics, user-level)
 │  PostToolUse(Write): spec-status-sync (specs only)
 ▼
 TURN END (Stop)       : create-checkpoint (worktree only), check-docs-changed,
 │                       format-changed (prettier --write), flow-loop ×3 (settings.local)
 ▼
 [optional] /git:commit : FULL pnpm lint + FULL pnpm typecheck, git add -A
 ▼
 git commit ── lefthook pre-commit (sequential, not piped):
 │               db-migrations(schema glob) → dir-size → format(prettier --write staged)
 │               → turbo lint --affected → turbo typecheck --affected   (base origin/main)
 │            ── post-commit (symlink, not lefthook): changelog-populator.py
 │               writes a seeded fragment, prettier, amend --no-verify
 ▼
 [review loop BEFORE a PR exists — creating-pull-requests / flow VERIFY]
 │  self correctness trace → gate (pnpm verify or vitest/lint/typecheck/build)
 │  → fresh adversarial reviewer (Opus via workhorse, REVIEW.md) → fix → re-review
 │  … loop until nothing blocking (no round cap) → squash to 1 commit + 1 fragment
 ▼
 [optional] /git:push : FULL lint + FULL typecheck + FULL pnpm build
 ▼
 git push ── lefthook pre-push (piped, stop on first failure):
 │             1 formatting: prettier --list-different vs merge-base
 │             2 tests: watchdog(300s stall / 7200s cap) turbo test --affected --concurrency=1
 ▼
 PR OPENED (non-draft) ─────────────────────────────── ~16–23 jobs
 │  required-on-PR: typecheck(FULL) lint(FULL) test(affected, 4 shards + community-pg)
 │                  browser-test(instant PASS-THROUGH) credential-free-build(affected, serial)
 │                  db-check fragment-present no-fragment-under-skip-label version-outranks-base
 │  advisory      : site-build(scoped) openapi-fresh(scoped) copy-spec-drift harness-windows(scoped)
 │                  review(Claude, once) scripts-test/CLI Smoke/Desktop Renderer/Desktop Smoke (paths)
 │                  Evals (label run-evals)
 │  re-review only via `re-review` label / @claude / dispatch (never on push)
 ▼
 merge-tail.yml (cron */10) → should-arm-automerge.sh (13 ordered SKIP rules)
 │  → gh pr merge --auto (MERGE_TAIL_TOKEN PAT) → enqueued
 ▼
 MERGE QUEUE (merge_group on gh-readonly-queue/main/pr-N-<sha>) ─── 11 workflows, ~19 jobs
 │  typecheck(FULL) lint(FULL) test(FULL 4 shards + assert-tests-executed + shard-union)
 │  browser-test(FULL 3 Playwright shards) credential-free-build(affected vs group base, cold)
 │  db-check fragment validity version-outranks-base site-build(always) openapi-fresh(always)
 │  harness-windows copy-spec-drift
 │  critical path ≈ credential-free-build 33–55 min
 ▼
 SQUASH onto main (PAT-attributed, so push:main workflows DO fire)
 │  push:main → db-check, CLI Smoke Test (5 jobs, unfiltered), scripts-test (paths),
 │             Desktop Smoke (macOS, paths)            — none of them can gate anything
 │  Vercel Git integration → apps/site ignore-build.mjs → db:migrate + turbo build site
 ▼
 RELEASE (/system:release, manual)
    bump VERSION + 4 package.jsons → compile fragments → release PR (skip-changelog)
    → queue → tag vX.Y.Z on squash SHA → npm publish cli + cloud-api → draft GH release
    tag push fans out in parallel:
       desktop-release (macOS signed+notarized, Windows unsigned) → publish-release (GITHUB_TOKEN)
       publish-docker (wait-for-npm → buildx amd64+arm64 → GHCR + Docker Hub mirror)
       update-homebrew (FAILS every time: HOMEBREW_TAP_TOKEN unset)
```

## 3. Local git hooks (`lefthook.yml`, lefthook 2.1.12)

### pre-commit (`lefthook.yml:1-70`)

The commands run sequentially with no `piped:`, so a failure does not stop the later ones. They run in alphabetical order.

| Command                 | Filter                        | Runs                                                                            | Scope                                                   |
| ----------------------- | ----------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `db-migrations` `:7-12` | `packages/db/src/schema/*.ts` | `npx drizzle-kit generate` + `git add packages/db/drizzle/`                     | only when a schema file is staged                       |
| `dir-size` `:13-15`     | none                          | `scripts/check-dir-size.sh` (error when a directory gains a file at 25 or more) | staged, plus a repo census that only warns              |
| `format` `:3-6`         | code, doc and config globs    | `prettier --write {staged_files}`, `stage_fixed: true`                          | staged                                                  |
| `lint` `:16-66`         | none                          | `TURBO_SCM_BASE=origin/main turbo lint --affected`                              | affected across the whole branch plus uncommitted files |
| `typecheck` `:67-70`    | none                          | `turbo typecheck --affected` (`dependsOn ^build`)                               | same. 41 s cold measured for cli (`:37-40`)             |

There is no `commit-msg`, `post-checkout` or `post-merge` hook. A stale `prepare-commit-msg` shim sits in `.git/hooks`. The **post-commit** hook is a plain symlink to `.claude/git-hooks/changelog-populator.py`, outside lefthook: it seeds a fragment, runs prettier, and amends with `--no-verify`.

### pre-push (`lefthook.yml:72-273`)

`piped: true` (stops at the first failure), `follow: true`.

| Priority | Command                 | Runs                                                                                                                                       | Bound                                           |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 1        | `formatting` `:103-128` | `scripts/pre-push-format-check.sh`: `prettier --list-different` on files changed since the merge-base. Fails closed if prettier is missing | 0.3–4.5 s                                       |

**Nothing typechecks or lints at pre-push.** The claim at `lefthook.yml:204-215` that pre-push "shares its cache with CI" is false: CI has no remote cache and passes different vitest arguments.

## 4. `pnpm verify` and other pre-PR scripts

`package.json:16`:

```
pnpm test:scripts && pnpm lint:root
&& export TURBO_SCM_BASE=origin/main && turbo run typecheck lint --affected
&& turbo run test --affected --concurrency=1 -- --run
```

- `test:scripts` (`:17`) runs **unconditionally**: `typecheck:scripts` plus 23 bash fixture suites, `node --test`, the docs-coverage-map check and the scripts vitest. CI runs the same suites only when `scripts-test.yml`'s paths match.
- **Six CI-required gates never run locally** (not in verify, no hook): `format:check` (`lint.yml:136`), `check-banned-words.sh` (`typecheck.yml:161`), `check:vocab-gate` (`:180`), `check:boundary` (`:229`), `check-nul-bytes.sh` (`:239`) and `check-dead-doc-paths.sh` (`:248`). A green `verify` does not mean a green `typecheck` or `lint` context.
- `knip` (`package.json:28`) is not wired to any hook or workflow.
- `/git:commit` (`.claude/commands/git/commit.md:46-54,86`) runs **full** `pnpm lint` and `pnpm typecheck`, then `git add -A`. `/git:push` (`push.md:32-42`) runs full lint, typecheck **and `pnpm build`**, including the Next site. Both come before the lefthook hooks, which then re-run affected-only versions of the same checks.
- `turbo.json`: strict env mode, `concurrency: 15`, `cacheMaxSize 10GB`, no `remoteCache`. `test` and `typecheck` depend on `^build`; `build` depends on `generate:api-docs`. Any full `turbo test` or `turbo typecheck` builds server and client (a Vite build), because cli, desktop, obsidian and evals depend on them.

**How many review passes a typical /flow change gets before merge:** about 5 layers, which is roughly **10–18 reviewer runs** for a multi-task spec: 2 per task × 3–6 tasks, 1 self-trace, 2–3 adversarial rounds, 1 CI review plus 0–2 `re-review`s, and an optional human. A single ad-hoc change gets about 4–6. Everything except the CI review is Opus-tier. **GitHub requires no human approval**, so merge-tail lands a green PR without one; the flow human gate is a convention.

**Drift in the installed flow plugin:** INST is v0.5.0 with `autonomy.default: "auto"` and every loop `enabled: true` (`INST:config/config.json:65,75-100`). MKT is v0.6.0 with manual and all loops off. ADR-0276, ADR 260728-112203 and `contributing/flow-engine.md:152-174` all assume autonomy is off.

### 6.3 Caching summary

- `setup-node cache: pnpm` caches the pnpm store, but every job still runs `pnpm install`.
- `actions/cache` is used only for Playwright (`browser-test.yml:316-321`) and credential-free's `.turbo/cache` (`credential-free-build.yml:442-448, 645-650`).
- buildx `type=gha` is used in publish-docker.
- There is **no turbo remote cache** (no `TURBO_TOKEN`/`TURBO_TEAM` secret, stated at `lint.yml:65-73`, `desktop-renderer.yml:112`).
- Cache scoping: a branch can read its own ref's caches and the default branch's. Linux pnpm (690 MB) and macOS pnpm (655 MB) caches exist on `main` because push-main workflows save them. **No Windows pnpm cache or Playwright cache exists on `main`**, because harness-windows and browser shards never run on push, so every PR and queue ref re-downloads and re-saves them (735 MB and 268 MB each).
- The total is pinned at the 10 GB limit.

## 7. Claude automated PR review

- **Action:** `anthropics/claude-code-action@v1`, a floating major tag (`claude-code-review.yml:584`). **No `--model`**, so it uses the action's default. Auth is `CLAUDE_CODE_OAUTH_TOKEN`, a subscription OAuth token.
- **Turns:** `--max-turns` 50, or 100 when more than 30 files changed (`:215-221, :530-546`). Job timeout 25 min. Tools are `Bash,Read,Grep,Glob` plus the inline-comment MCP and a trusted `review-gh.sh` taken from main. No Agent tool (DOR-1948). `--setting-sources user` (`:824-829`).
- **Fires on:** `opened`, `ready_for_review`, `reopened`, and `labeled` only with `re-review`. It skips drafts, forks and `skip-review` (`:259-266`). It **never runs on push**, and not at all on a CONFLICTING PR (`:114-124`); dispatch covers that case.
- **Labels:** `review:light` and `review:deep` only change prompt behavior. The model reads the labels itself (`:660-666`), and adding one does not trigger a run. `re-review` triggers a run and is cleared automatically (`:1114-1133`). `skip-review` skips.
- **Blocking?** It never submits APPROVE or REQUEST_CHANGES (`:714`). The `review` check is not required and never reports on merge_group. It gates merge-tail only **indirectly**:
  1. A red `review` check makes merge-tail skip the PR (`SKIP failing-checks`), but only until the next push. The check-run belongs to the old head SHA, and the head commits of merged #1917, #1918, #1919, #1922 and #1923 have none.
  2. Unresolved inline threads make merge-tail skip the PR (`SKIP unresolved-threads`), and this does persist across pushes.
- **What green means:** the classifier result is `completed` **and** a bot comment matching the verdict pattern was posted after the start time (`:139-156, :959-965`).
- **Dependabot:** every Dependabot PR gets a red review ("non-human actor", run 34852304867). Dependabot PRs carry `review:light`, not `skip-review`.
- `claude.yml` (`@claude`): `--max-turns 30`, `contents: write`, no hardening flags, no timeout.
- Observed over the last 30 runs: 14 success, 9 skipped, 4 cancelled, 2 failure. PR runs average 2.7 min, max 6.

## 8. Merge queue, arming, and execution assertions

- **ADR `decisions/260728-112203-merge-queue-replaces-branch-currency.md`:** the queue replaces `strict` (`:53-58`). Every required check must report on merge_group (`:66-68`). Fragment coverage is decided at PR time and validity re-runs in the queue (`:70-75`). merge-tail arms every 10 min (`:77-82`). The ADR says **batch size 1** (`:84-87`); the live ruleset batches up to 5 with ALLGREEN. Among its negative consequences, it admits it "lands code without a human at the moment of merge" (`:115-118`).
- **ADR `0276` (auto-merge on approval with a recovery ladder):** shipped in the flow plugin behind autonomous mode. In this repo, merge-tail does the arming (`:14-16`). Autonomy is on in the installed plugin (§5), so the ladder may also be live.
- **`merge-tail.yml`:** cron every 10 min, concurrency `merge-tail` with no cancelling. It uses `MERGE_TAIL_TOKEN` and **exits 1 if a queue exists but the PAT is missing** (`:119-137`), because a merge group created by GITHUB_TOKEN gets no checks and jams the queue. It walks `gh pr list --limit 100` → `gh pr view`/`checks` → GraphQL `mergeQueueEntry` + `reviewThreads(last:100)` → `should-arm-automerge.sh` → `gh pr merge --auto --squash` (`:146-241`). There is no explicit re-arm logic: the next tick re-arms anything the queue dropped.
- **`scripts/should-arm-automerge.sh:77-121`:** the first match among these rules wins, in order: not-open → draft → already-armed → already-queued → hold labels (`hold`, `do-not-merge`, `do not merge`, `wip`, `blocked`) → DIRTY → mergeability UNKNOWN → CHANGES_REQUESTED → unresolved threads → no checks → any fail → any cancel → any pending → ARM. BEHIND is fine, and an empty reviewDecision still arms. It is pinned by 27 fixtures (`scripts/test-should-arm-automerge.sh`). **A PR with no Claude review at all still arms.**
- **`scripts/assert-tests-executed.sh`:** on merge_group only, per shard (`test.yml:408-410`). It asserts every `test` task in the turbo summary was a cache MISS, and that the task count equals the number of `apps/*` + `packages/*` manifests with a `test` script (`:82-116`). This defends against the 280 ms "FULL TURBO" replay and against `--filter` typos. It deliberately avoids `--force` (`:26-30`). `assert-shard-union.sh` catches a package with zero collected files across shards.

## 12. Redundancy, serial chains and gaps

### Run 3 or more times on the same change

1. **Typecheck: up to 7 times.** Per-edit hook, then `/git:commit` (full), pre-commit (affected), `/git:push` (full), `verify` (affected), PR `typecheck` (**full**), PR `credential-free-build` (affected), queue `typecheck` (full), queue `credential-free-build` (affected). The PR full run and the queue full run check almost the same tree, minutes apart.
2. **ESLint:** the same pattern, plus lint in credential-free-build on both events. The PR `lint` job is full.
3. **Prettier: 5 layers.** Stop, pre-commit, pre-push, PR `lint`, queue `lint`.
4. **Unit tests: 5–6 times.** pre-push (affected) and `verify` (affected, replayed from the same local cache), PR shards (affected), PR credential-free (affected, serial), queue shards (full, `--retry=1`), queue credential-free (affected vs group base, cold). **In the queue the same package suites run twice in parallel**, once sharded and once serial at `--concurrency=2`, and the serial copy is the critical path. The credential-free header concedes that turbo strict env mode already strips most hosted variables (`:77-85`).
5. **`^build` of shared, server and client:** about 11 independent cold builds per queue entry (4 test shards, 3 browser shards, typecheck, site-build, openapi-fresh, credential-free, community-pg), with no artifact hand-off and no remote cache.
6. **CLI build + server boot:** credential-free-build (PR + queue) and cli-smoke (PR paths + push-main).
7. **db-check** runs on PR, then queue, then push main. The push leg can't gate anything.
8. **`generate:api-docs`** runs twice in the queue (openapi-fresh, and site-build through `build`'s `dependsOn`).
9. **Review:** per-task two-stage, then adversarial loop, then CI Claude review, then re-review. All of it is pre-merge, and none of it is enforced by GitHub.
10. **Local full runs:** `/git:commit` and `/git:push` run full lint and typecheck (and a full build), and then lefthook runs the affected versions again.

### Serial work that could run in parallel or be split

- **credential-free-build is one job doing install → build/typecheck/lint → test → CLI build → boot**, 33–55 min in the queue. It is the longest required check, and its own header already sketches a sharded fan-in (`:215-252`).
- `community-pg` (Postgres + Chromium install + Playwright) is on the required `test` fan-in for every PR, including docs-only ones.
- `site-build` installs before deciding to skip (`:137` before `:176`).
- cli-smoke runs `build-tarball` and then 4 separate runner spin-ups; the two bare legs could share one runner, and so could the two Docker legs.
- Local pre-commit is sequential (lefthook default). lint and typecheck are independent and could run in parallel.

### Hygiene and correctness gaps

- **Six CI-required gates can't be run locally** through `verify` or a hook (format:check and the 5 typecheck-job scanners).
- **Jobs with no timeout** (6-hour default): changelog ×2, version-outranks-base, openapi-fresh, scripts-test ×2, merge-tail `arm`, `claude`, all 5 desktop-release jobs, and update-homebrew.
- **No concurrency block** on changelog-fragment-check or operating-skills-version-check, so superseded PR and label-event runs are never cancelled.
- **Node version drift:** docs-openapi-check and scripts-test use 22; everything else uses 24.
- **Stale documentation:**
  - AGENTS.md's CI section doesn't list `credential-free-build` or `db-check` as required, and never mentions queue batching of 5.
  - creating-pull-requests describes pre-queue behavior.
  - ADR 260728 says batch 1.
  - `browser-test.yml:19-39` cites the Free-plan cap, but the org is on Team.
  - The test.yml header predates `community-pg`.
  - `.claude/README.md:131` says pre-push runs the full suite.
  - `contributing/marketplace-installs.md:632-634` says no test workflow exists.
  - There is no CI guide in `contributing/` at all.
- **Release automation is broken:** update-homebrew has never succeeded (missing secret), and the cask path is dead because GITHUB_TOKEN publishes the release.
- **A red Claude review is erased by any push.** Dependabot PRs always get a red review.
- **Cache thrash:** 10.3 of 10 GB. Caches saved on PR merge refs and queue refs can't be reused, and no Windows pnpm or Playwright cache exists on main.
