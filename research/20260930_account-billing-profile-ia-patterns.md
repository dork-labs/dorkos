# Account, billing, profile and workspace IA

## Research Summary

Across local-first tools with an optional cloud (Obsidian, Zed, Raycast, Docker Desktop, VS Code, Ollama, JetBrains) the dominant pattern is: **the app is complete without an account; one "Account" entry inside local Settings shows signed-out/signed-in state; money (billing, invoices, payment methods, spending limits) lives on a web dashboard, not in the app; and a live credits meter sits next to the AI feature that spends it** (status bar, toolbar widget, per-reply chip). Team SaaS (Linear, Notion, Vercel, GitHub, Supabase) splits settings into _you_ (profile, preferences, notifications) vs _the workspace/org_ (members, billing, usage), and bills at the org/team level. The best discovery surfaces are contextual (the moment an AI key is missing or a feature needs the cloud), skippable at onboarding, and honest about cost; the worst examples (Figma license-request nudges, Cursor's mandatory sign-in) are where users complain.

## Key Findings

1. **Local-first apps put "Account" inside Settings, not as a top-level destination.** Obsidian (Settings → General → Account), Raycast (Account tab, first), Warp (Settings → Account). The account entry has a _signed-out_ state that is just a short explanation and a "Log in" button. No nag elsewhere. Docker Desktop and VS Code add one persistent, low-key sign-in affordance (Dashboard top-right; Accounts icon bottom of the Activity Bar).
2. **Money lives on the web; state lives in the app.** Zed, Cursor, Obsidian, Raycast, Ollama, JetBrains and VS Code/Copilot all send billing, invoices, payment method and spending limits to a web dashboard. Warp is the exception (Billing and usage inside the app, buy credits in-app). The app shows _plan name + meter + "Manage" link_.
3. **The credits meter lives beside the thing that spends it.** Copilot's status-bar icon shows usage %; JetBrains' header widget shows subscription quota and top-up credits as two separate bars with "add more"; Warp shows a per-reply credit chip. Settings holds the detailed view. Claude.ai and JetBrains both keep _included allowance_ and _prepaid top-up_ as two distinct balances, which users find clearer than one blended number.
4. **BYOK-vs-credits is presented as a provider choice, not a paywall.** Cline lists its own credits as one option (recommended, first task free, no card) alongside BYOK. Zed's free plan is BYOK and Pro adds hosted models. Ollama marks cloud models with a `:cloud` suffix in the same model list. The paid route is one row in a list the user was already looking at.
5. **Team SaaS splits "you" from "the workspace", and billing belongs to the workspace.** Linear's four settings groups (Account / Features / Administration / Your teams), Notion's account-then-workspace sections, Supabase moving usage from project to org, Vercel's scope switcher, GitHub's twin billing pages. Billing is admin-only and often has its own role (Tailscale "Billing admin").
6. **Spend controls are standard and opt-in.** Monthly spend limit (Zed, Cursor), budgets with 75/90/100% alerts (GitHub), auto top-up off by default with explicit threshold + amount (OpenRouter, Claude extra usage auto-reload).
7. **Forced sign-in is the notable outlier and is tolerated only where the account is the product.** Cursor requires sign-in on first launch because plan and model access hang off it; Tailscale because identity is the network. NN/g: login walls "defy the reciprocity principle" and should be used only when users benefit significantly.

## Detailed Analysis

### Profile vs account vs workspace vs billing: the vocabulary that has settled

- **Profile**: how others see you (name, avatar, handle). Only matters when there are other people (rooms, teams). In single-user local apps it collapses into Account.
- **Preferences**: device/app behavior (theme, keybindings, notifications). Never requires an account. Linear files it under Account; Notion separates it.
- **Account**: the identity you sign in with, plan, sign out, delete account, security (sessions, 2FA, tokens).
- **Workspace / Team / Org**: shared container with members, roles, shared resources and **billing**. Solo paid users usually get an implicit personal workspace (Vercel personal scope, GitHub personal account) so the billing model is the same shape at 1 and at 50 seats.
- **Billing / Usage**: plan, payment method, invoices, credits balance, spend limits, auto top-up. Usually split into _Billing_ (money in) and _Usage_ (money out), which Vercel, Supabase and Claude.ai all do.

### Where the avatar/account menu sits and what it holds

Convention: top-right avatar on web SaaS (GitHub, Vercel, Docker Desktop's Sign in button), bottom-left in sidebar-led apps (VS Code Accounts, Claude.ai, ChatGPT; Linear and Notion put a _workspace_ menu top-left and fold the user into it). Typical contents, in order: identity header (name, email, plan badge), Settings/Account, Billing or Usage (sometimes), Help/What's new, theme, Sign out last. For a sidebar app like DorkOS, the bottom-left slot is the idiomatic home. NN/g's menu guidance (clear labels, familiar grouping, show where you are) applies but NN/g has no dedicated avatar-menu study that this research could find.

### Signed-out and local-only states

Good examples keep the signed-out state quiet and informative: Obsidian's "Log in" row under Account; Raycast's Account tab with "Sign in"; VS Code's Accounts icon with a small badge only when an extension asks. Docker is explicit that signing in "unlocks" more but default use needs none. The anti-example is gating unrelated features behind sign-in (Cursor hides VS Code import until you sign in).

### Discovery at the moment of need

The highest-intent surfaces observed:

- **No AI key configured** → provider list with "use our credits" as one option (Cline, Zed, Ollama `:cloud`).
- **Limit reached** → in-editor notice with the two ways forward: enable pay-as-you-go or upgrade (Cursor), buy add-on credits (Warp), top-up from widget (JetBrains).
- **Feature that inherently needs a server** (sync, publish, remote access) → the settings page for that feature explains the service and offers sign-in (Obsidian Sync/Publish sections).

### Defaulting to the paid layer after sign-up

Observed mechanisms: signing in to Cline's provider makes it the active provider; Zed Pro makes hosted models available in the same model picker; Copilot uses your account the moment you sign in via the Accounts menu. The pattern is "signing in selects it, and the choice stays visible and reversible in the same picker", not a silent switch of an existing BYOK setup.

## Anti-patterns

- **Login wall before value** (Cursor first launch; NN/g "Login Walls Stop Users in Their Tracks").
- **Upsell disguised as help, cost hidden, reject harder than accept**: Figma forum: prompts are "frequent and intrusive", users "not clearly told that what they are clicking carries a cost", "far easier to approve than to reject", "Finance gets surprise invoices".
- **One blended balance** that hides whether you are burning included allowance or paid top-up (JetBrains changed to two bars; Claude separates plan vs extra usage).
- **Meter only on the web**: Cursor users learn they hit the limit via a notification after the fact, with no graduated warning documented.
- **Auto top-up without a cap** (OpenRouter explicitly has none beyond threshold+amount).
- **Silently rerouting BYOK traffic to paid credits** after sign-in (no vendor observed doing this; flagged as the obvious trap).
- **Upgrade badges on every surface** (Notion/Figma-style persistent "Upgrade" buttons in the sidebar), which fit consumer SaaS, not a control-panel tool.

## Candidate IA models for a local-first app with an optional cloud account

**A. "Account is one Settings page" (Obsidian/Raycast model).** Settings gets an Account section first in the list. Signed out: one paragraph on what the hosted account adds (run agents without your own AI subscription, reach this computer from your phone, share with a team) and "Sign in / Create account". Signed in: identity, plan, credits balance, "Manage billing" (opens web), sign out. No avatar menu until signed in. Lowest surface area; weakest discovery.

**B. Bottom-left account slot + Settings split (VS Code/Claude.ai model).** Persistent sidebar footer slot: signed out shows a neutral "Sign in" or local-user name; signed in shows avatar + plan + a small credits figure. Menu: Profile, Settings, Usage & billing (web), Help, Sign out. Settings grows sections: _You_ (profile, preferences, notifications), _This computer_ (runtimes, keys, tunnel, data dir), _Account_ (plan, credits, spend limit, auto top-up). Good balance for a control-panel app.

**C. Personal account + workspace, billing at workspace (Linear/Vercel/GitHub model).** Every signed-in user gets a personal workspace; Teams are additional workspaces with members, seats and shared billing; a scope switcher appears only once a second workspace exists. Settings: Account / This computer / Workspace (admins only: members, seats, billing, usage). Scales to seats cleanly; overkill for solo users unless the switcher is hidden until needed.

**D. Capability-led discovery, account as a quiet backstop (Cline/Zed/Ollama model), layered on B.** No standalone upsell. The hosted account appears as a row where the need arises: the runtime/model picker ("Use DorkOS credits" beside "Use my Claude subscription / API key"), the phone-access setting ("Reach this computer from your phone" with the tunnel option), the team invite flow. Onboarding offers sign-in as one skippable step, framed by outcome. After sign-up, credits become the default _only for runtimes with no working credential_, shown in the same picker, reversible. Meter lives beside the chat composer or in the status area (two numbers: included vs top-up), with low-balance warnings at fixed thresholds and auto top-up off by default with a cap.

Recommended starting point from the evidence: **B + D**, with C's workspace scoping introduced only when seats ship.

## Research Gaps & Limitations

- Exact current avatar-menu contents for Zed, Vercel, ChatGPT, Slack, Figma, 1Password, Cloudflare and Anthropic Console were not re-verified; rows marked unverified.
- No NN/g or Baymard study specifically on avatar/account menus or settings IA was found; guidance is inferred from general menu and login-wall research. Apple HIG / Material were not fetched.
- Low-balance warning thresholds are poorly documented everywhere except GitHub budgets.
- Claude.ai details come from third-party guides and a GitHub issue, not Anthropic docs.

## Contradictions & Disputes

- In-app vs web billing: Warp keeps billing in the app; most others push it to the web. In-app is more convenient; web keeps payment UI (and app-store rules on desktop) out of the client.
- Forced sign-in: Cursor and Tailscale require it, justified by the account being core to the product; everyone else in the local-first set does not.
