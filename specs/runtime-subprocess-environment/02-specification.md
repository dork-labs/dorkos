# Runtime environment protection — specification addendum

**Status: Approved for implementation by the operator after independent checkpoint5 PASS0 on 2026-09-08.**

Base: 03f68928b427e7a533055dbdfa2b3dac457c5714. Tracker: DOR-1904 (00475767-6272-45ef-bf3a-3baa47911fe7). Parent: [white-label-connections](../white-label-connections/02-specification.md). This addendum narrows credential exposure; all existing account/grant/turn/hosted authorization remains unchanged.

## Overview and scope

Every DorkOS-owned launch of Claude, Codex or OpenCode receives an explicit projected environment, including launches with no agent identity, no Connections injection and no extra variables. The projection preserves deliberate runtime requirements and excludes ambient server-only secrets. The same policy covers runtime login/probe/provisioning subprocesses that currently inherit the server environment. No server-wide process.env mutation, OS sandbox, general terminal rewrite or unrelated database migration.

Existing declaration comments claiming Codex never sets env are stale (core/credential-env.ts and shared/config-schema.ts); correct only comments touched by this work. No credential custody architecture or provider permission changes.

## Architecture

Add a pure SDK-neutral module at apps/server/src/services/runtimes/shared/runtime-environment.ts. Input: parent Record<string,string|undefined>, runtime kind, purpose (turn, warmup, auth-probe, version-probe, locator, login, provision, process-inspection), validated exact-name custom inheritance, explicit runtime-owned overrides and selected model credential fragment. Output: a fresh complete environment object. Do not return undefined on any branch. Do not retain or log input/output values, variable-value hashes or credential references. SDK imports remain confined to their existing adapters.

Layering: (1) baseline names from parent; (2) runtime authentication/config profile; (3) custom exact names from parent; (4) validated selected model credential and fixed adapter-owned overrides. Reserved names are absent from all inherited layers. Only an explicit internal override builder may add a DorkOS-minted agent/turn credential or OpenCode sidecar password; custom configuration never names those reserved controls. Passing a raw arbitrary object as trusted overrides must not bypass classification: validate its names against the purpose/runtime's finite allowed override set. A reserved rejection is a safe configuration error naming at most the public variable name, never its value.

Names are normalized for Windows case-insensitive environment semantics. Reserved matching and duplicate detection are case-insensitive on every platform so MCP_API_KEY/mcp_api_key cannot evade the policy. Preserve the actual recognized source spelling for PATH/Path where needed; emit one canonical entry per case-insensitive name on Windows. Refuse ambiguous differently cased custom names. No wildcard, regex, prefix allow rule or value-based secret heuristic.

## Baseline and custom-variable contract

Initial exact-name baseline for review: PATH, HOME, USERPROFILE, HOMEDRIVE, HOMEPATH, APPDATA, LOCALAPPDATA, XDG_CONFIG_HOME, XDG_DATA_HOME, XDG_CACHE_HOME, XDG_STATE_HOME, TMPDIR, TMP, TEMP, SystemRoot, WINDIR, COMSPEC, PATHEXT, USER, USERNAME, LOGNAME, SHELL, LANG, LANGUAGE, LC_ALL, LC_CTYPE, TZ, TERM, COLORTERM, NO_COLOR, FORCE_COLOR, CI, DO_NOT_TRACK; SSH_AUTH_SOCK, SSH_AGENT_PID, GIT_SSH, GIT_SSH_COMMAND, GIT_ASKPASS, SSH_ASKPASS, GIT_CONFIG_GLOBAL, GIT_CONFIG_SYSTEM, GIT_TERMINAL_PROMPT; HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, NO_PROXY and their lowercase spellings; SSL_CERT_FILE, SSL_CERT_DIR, NODE_EXTRA_CA_CERTS, CURL_CA_BUNDLE, REQUESTS_CA_BUNDLE. Preserve absent entries as absent, and do not invent HOME or PATH defaults. Proxies and SSH agents convey intentional operator authority; they are not harmless metadata. Their existing behavior is preserved, with values never logged. No proxy target validation or routing change is included.

NODE_OPTIONS, runtime preload options, GIT_CONFIG_COUNT/KEY_n/VALUE_n, package-manager token variables and arbitrary tool-specific names are not blanket baseline families. Operators can explicitly opt into legitimate custom names unless reserved. GITHUB_TOKEN/GH_TOKEN are dual-use CLI credentials, not baseline: require explicit owner inheritance for the intended runtime. This is documented as a compatibility change, not a claim that Git operations requiring those tokens remain automatically authenticated. Existing SSH agent, Git config files and credential helpers continue to work.

Add runtimes.environment.inherit with exact arrays for claudeCode, codex and opencode, each default []. This contains names only, not values or references; bound each list to128 names and names to128 ASCII identifier characters, reject duplicates/case collisions, NUL, empty names, wildcards and reserved names. Names present but unset are simply omitted; no value diagnostic. Classify every list leaf operator-only in core/operator/config-write-policy.ts so config_patch cannot grant itself extra ambient secrets. Treat these lists as withhold in tokenless config_get/config_patch projections to avoid exposing operator secret-variable naming; owner settings/config remains canonical. Reuse existing owner config mutation checks, including login-off same-user limitations. No new route or settings page is necessary: normal owner configuration supports this advanced names-only escape hatch. Document an exact names-only configuration example using SYNTHETIC_TOOL_SETTING.

## Authentication and config preservation

Use core/credential-env.ts's current resolution order: a resolved selected credential overrides permitted inherited model authentication; a missing reference keeps supported host/delegated login fallback. Keep Claude account pin from claudeConfigDirEnv after projection and preserve the transient-account lock invariant. Preserve MCP_TOOL_TIMEOUT floor and CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS; inject only freshly minted identity/Connections fragments, never stale ambient DORKOS_AGENT_TOKEN or DORKOS_CONNECTOR_MCP_*.

> **Note (2026-09-11):** the MCP_TOOL_TIMEOUT floor named above was retired. The floor existed only to stop an inherited value cutting an in-session approval hold short, and it could only be applied to every MCP server in the subprocess at once — so it overrode the operator's setting for the external server they had lowered it for. SDK 0.3.268 lets the in-session `dorkos` server declare a per-call timeout of its own, which it now does (`apps/server/src/services/runtimes/claude-code/mcp-tools/index.ts`, derived in `mcp-tools/tool-timeout.ts`). MCP_TOOL_TIMEOUT is now projected through unchanged. The rest of this paragraph stands.

The exact automatic profiles, selectors, custom-mode migration and source citations are frozen in [04-provider-profiles.md](04-provider-profiles.md). They supersede checkpoint2's unresolved provider catalog. Implement those finite lists; no prefix allow rules. Preserve SDK authentication precedence, the Claude account-pin deletion case, Codex's complete-env/shared-client behavior and OpenCode's shared-sidecar three-key union. Unknown parent variables require explicit owner opt-in. Runtime-owned settings/auth files remain trusted; project/provider config cannot itself authorize extra parent inheritance.

Codex's shared-client cache must invalidate safely when projection policy changes; the next newly launched turn cannot reuse a permissive environment solely because its binary path matches. Existing custom MCP server env/header values stay attached to that server, not a broader parent scope. A changed OpenCode sidecar projection requires a safe existing lifecycle restart or documented server restart, never global env mutation or killing active turns.

## Server-only reserved catalog

Keep an explicit reasoned catalog, with tests enumerating actual current server/site secret inputs and intentional dual-use exceptions. At minimum: MCP_API_KEY, BETTER_AUTH_SECRET, NANGO_ENCRYPTION_KEY, NANGO_SECRET_KEY, COMPOSIO_API_KEY, NGROK_AUTHTOKEN, DATABASE_URL, CRON_SECRET, GITHUB_CLIENT_SECRET, GOOGLE_CLIENT_SECRET, LINEAR_API_KEY, LINEAR_WEBHOOK_SECRET, RESEND_API_KEY, POSTHOG_PERSONAL_API_KEY; all known DORKOS-managed cloud/Connections/auth/encryption variables and internal turn/agent controls are inherited-denied. Enumerate concrete current PostgreSQL/Neon/Vercel credential names actually supported by the deployment rather than pretend that a prefix scan proves coverage. Reserved classification is separate from default unknown withholding.

Explicitly selected model credentials may read an owner-chosen existing CredentialProvider reference and emerge only under the appropriate model variable; the new custom inheritance list never resolves secret references. Unknown custom variables can contain secrets; opting into one intentionally entrusts its value to that runtime. An operator could deliberately duplicate a server secret under an allowed custom alias; preventing that is not a promised property. Protect known server credential-reference source names if a supported server-only credential uses env:<NAME>; do not broaden model resolution authority.

## Risks and review gates

Unknown custom tools may need explicit names; this is intentional and must be visible. Allowed proxy/SSH/config values can themselves convey credentials or executable configuration, and runtime-owned config files can add credentials after spawn. Server-secret filtering reduces accidental exposure but does not isolate processes running as the same OS user or defend against an operator deliberately forwarding a secret. The exact catalogs are specified in 04-provider-profiles; independent review/root freeze and the append-only migration identifier remain gates; implementation must not invent unverified auth modes or expand to unrelated subprocess domains.
