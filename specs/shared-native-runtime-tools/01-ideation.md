Preserve the actual granted level, visible started-level line, caller identity and every existing authority boundary. - **Maturity:** Adapt the existing detailed preparatory design into official IDEATE; do not treat it as an approved specification. The coordinator explicitly resumed the original delegated preparatory context. `.dork/flow/tmp/native-tools-plan.md` is historical input, not the source of current counts, APIs or authority decisions. The coordinator owns the IDEATE claim, tracker changes, stage transition and dependency records. This document stops before SPECIFY.

The coordinator recorded a typed DOR-2067 → DOR-4481 dependency. Its strict objects, defaults, metadata and retirement of `portableInputShape` are consumed, not reimplemented here.
- **Assumptions:** The registry is the declaration and invocation authority. Runtime storage remains runtime-owned. A caller's home, actual desk, room seat, current turn and billing choice are server facts. Full and marks follow current source and accepted decisions; old message-origin/teammate lowering is not revived. The current preview runs the agent at its owner's level regardless of message origin.

- **Completion boundary:** Session creation alone does not close DOR-4481. Every required outcome in the refreshed inventory must be delivered or explicitly decided with owner, consequence and reopening condition. A proposed exception is not acceptance.

### Hand-input parse census and migration compatibility

The current 39 hand declarations were separately inspected through their **actual gated production shapes**, not inferred from DOR-2067's registry census. `.dork/flow/tmp/4481-ideate/hand-input-probe.ts` walks every field/wrapper/check without invoking handlers or evaluating default factories. The measured tree has 219 visited nodes: 94 optional, 101 string, eight enum, seven boolean, four nullable, two number, two array and one literal. These dated counts include gate-added optional approval arguments and repeated field positions; they are census evidence, not a permanent allowlist.

The only value-changing schema checks are the three string `trim` overwrites in `session-start/input.ts`: optional title, reason and claim. There are **no observed schema transforms/pipes, outer preprocessors, coercions, defaults, prefaults, catches or lazy nodes** in these hand shapes. A raw field map also has no outer object transform to preserve. Source search of the hand-tool definitions corroborates the traversal. Imported current enum schemas are included by walking the constructed nodes. This finite no-find does not imply future schemas or arbitrary Zod transforms are idempotent.

The parse-only control uses actual session_start fields, whitespace in all three affected values, and current `splitApprovalToken`/`hashApprovalInput`: one SDK-style parse and a second strict-object parse produce identical trimmed values and identical approval-input digests after removing a synthetic token. `trim` is idempotent; no non-idempotent input incompatibility was found in the present 39. This is not a handler/approval-consumption proof or a successful launch. DOR-2067's separate 29 registry-default/11 coercion/two canvas-pipe evidence must never be substituted for this hand census.

Migration keeps the current fields and idempotent trims in a full strict object, then leaves the **original executable schema parse inside registry.invoke**. It must not add a generic parsed-input bypass or revive portableInputShape under another name. Keep handler fallbacks in the handler: for example tasks_create currently fills omitted target with global **after** gate hashing. Moving that fallback into a new schema default would change what the approval binds and is not a mechanical migration. Any newly introduced transform/default factory/prefault/outer preprocess must prove raw → SDK parse → original registry parse equivalence on both MCP projections, with exact approval hash and handler values; if it cannot, redesign that domain's schema/normalization before freezing SPECIFY. An idempotent, domain-owned representation is preferable to a second validation authority.

### Optional availability is separate from parity

With every handle present, the positive census lists all 39. Removing one handle at a time from the actual hand factory gives these observed omissions: adapterManager → four chat-connection controls; traceStore → two diagnostics; bindingStore → four routing tools; meshCore → eight team tools; extensionManager → five tools, while `get_extension_api` remains. Removing taskStore, relayCore, bindingRouter, runtimeRegistry or activityService does **not** remove names in this census; relevant handlers may instead return their existing service-unavailable error. Preserve each domain's actual contract intentionally rather than assuming absence always means omission. The new registry domain's assertDeps/boot admission must model the chosen contract explicitly and be tested with enabled positive controls. A disabled service is never a per-runtime waiver.

**High-confidence cause:** native server construction intentionally projects registry declarations only; these 39 still have only hand registrations. Runtime hints in a handler do not advertise that handler to native clients. **Related prerequisite:** the native principal provides identity and lifetime but not all live session-start/task/extension/event-surface facts. Advertising the verb without those facts would make parity unsafe or leave approvals stranded.

## 5) Research

### Alternatives and recommendation

1. **Reuse public `/mcp`: reject.** Its sessionless/Owner client contract is different; broadening its auth grants is not native parity.
2. **Import Claude factories into the native listener: reject.** Violates SDK confinement, preserves Claude session assumptions and risks duplicate policy/envelopes.
3. **Add a permanent third hand-tool descriptor/gate projection: reject.** Fixes listing while retaining three sources of drift; conflicts with the accepted registry direction.
4. **Migrate domains to the existing registry: recommend.** Extract neutral owning services/policy, preserve stable MCP names, declare actual audiences, and delete old hand registration in the same domain slice. One gate and one handler path remain. Cost: action-id compatibility, caller context and all domain outcomes need deliberate incremental work.

### Caller context: extend the existing turn boundary, reuse existing facts

Use the process-owned turn binding/ownership and shared turn-power records as the foundation. Do **not** create another permanent permission state store or generic authority flag. Resolve identity/home/desk from the existing principal and identity service. Resolve marks, chosen Full, unattended state and turn serial from the existing shared services wherever authoritative. Fill only missing **live adapter facts** through server-local closures attached to the same exact active-turn lifecycle: actual effective mode id/semantic level, Claude Auto confirmation when applicable, current event/approval sink and cancellation. API spelling and minimum field set are to be frozen in SPECIFY after tracing each implementation; this is a recommended extension of an existing seam, not an invented approved interface.

Re-read per invocation and immediately before a sensitive launch/commit using the existing service's policy. A latest-turn cache or stored Full row alone does not authenticate an active call. Codex prepared settings, OpenCode live asks, Doe `turn.mode`, and Claude chosen Full/Auto fallback must map faithfully; pending changes must not manufacture power. Canonical rekey/aliases, turn replacement, setup failure, interrupt, warm background work and terminal cleanup must invalidate or transfer only the facts the existing ownership contract permits. Codex thread keys must resolve to the current turn, never a previous lease. Caller-supplied runtime/cwd hints remain **target selection** subject to existing policy, never caller identity/level selectors.

Keep registered home and actual working directory explicit. Current native context.cwd is home by design; changing it globally would alter existing capabilities. New session/task provenance uses home for identity/config and canonical desk where the existing handler expects the real work location. A room's files are not an owned agent desk. Preserve existing canonical room/session and agent-home checks.

Current source deliberately lets a chat **set to Full** carry marks without lowering its child to a cancelled teammate/origin tier. Reuse `chosenFullAutonomy`/`choseFullAutonomy`, `outsiderStartCeiling`, `startCarriesWords`, `markedTurnRunsAtFull`, current person-set restrictions and semantic mode comparison; do not transcribe stale ADR comments as new policy. Lower-level/unknown cases still fail closed under existing rules. Full never becomes an Owner token, access to secrets, or permission to write front-door settings. Preserve the existing exception for a marked turn doing an outward or irreversible connected-app action (DOR-3683), and the retained secret/self-raise/person-set-limit refusals; extracting a shared caller must not erase those checks.

### Shared invocation, approval compatibility and UI

- Keep original input parsing in `registry.invoke`; projection validation does not substitute for it. Use DOR-2067's full strict object and approved token projection. Preserve SDK loading metadata and surface digest. No `invokeParsed`, direct shared-handler bypass, duplicate hand gate or nested MCP result envelope.
- Each new capability id must use its owning domain; keep MCP names stable. Move legacy action settings through `RENAMED_PERMISSION_ACTIONS`/schema normalization and the existing upgrade sweep. Test saved Blocked/Ask/Allowed under both old/new keys, including current-key precedence. `request_permission` resolves the MCP alias through the registry even when the action is hidden.
- Canonical action rename must preserve `session_start`'s protected-folder pre-gate refusal before Ask/Always allow and handler-side check. Pending approval tokens bind action and exact parsed input: keep existing identity where supported, otherwise reject obsolete pending approvals clearly and durably, requiring a fresh ask; never silently reinterpret a token or lose its refusal.
- Extend shared registration/invocation to supply the native live `InSessionSurface` and abort signal from the current verified turn. Reuse `CapabilityApprovalHold`, ApprovalService delivery claims, card events and late verdict routing. All four runtimes must hear grant/deny/cancel/timeout exactly once. Unattended turns use current no-wait semantics and late/durable outcomes; they do not wait on an absent person. No new approval system.
- Preserve `SessionStartResult`: canonical sessionId, title, markdown link, actual runtime/account, `permission {mode,label,callerMode,sameAsCaller}`, `status:started`. The stored granted mode, `session_started_by` and client `StartedByLine` must agree. Failure stays visible `isError` with code/reason and leaves no orphan settings, launch reservation, work claim or dispatch. No optimistic started-level line.

### Required domain-specific corrections

**Session count:** replace only-Claude `deps.transcriptReader.listSessions` with the existing runtime-owned aggregation/filtering pattern. Include nonzero chats from all four runtimes, canonical alias handling and permitted home scope. If a runtime/account fails or times out, expose partial-count warnings rather than falsely complete zero. Preserve existing count/cwd/agent_id contract and add explicit completeness information; SPECIFY freezes exact additive shape. Do not read another runtime's transcript files or introduce a shared transcript database.

**Accounts:** `accounts_usage` already reads every runtime's memory-backed usage store; keep unknown distinct from zero. `accounts_probe` is explicitly a **Claude account target operation**, regardless of the caller's runtime; move its neutral handler behind an injected Claude probe edge so SDK ownership stays confined. Do not manufacture Codex/OpenCode/Doe probe support. Existing supported target behavior, throttle and no-charge guarantee remain; unsupported targets return honest unavailability. This target distinction needs explicit coordinator disposition in SPECIFY, not a silent caller-runtime omission.

**Tasks and notifications:** extract neutral task provenance from verified home, canonical chat/aliases, actual desk, current chosen mode/marks and ceiling. Preserve file-first atomicity, task pause/approval, lazy registrar and account/model/credits payer behavior. Notification identity is server-resolved and the canonical session is counted; no real external note is sent by proofs.

**Extensions:** extract handler ownership from the Claude module without changing generated-code trust. Full/marked/held provenance and approval logic call the current shared helpers; lower/held callers cannot fake authorship or auto-approve code. `get_extension_api` remains available when the extension manager is absent. Creation/reload/test use toy files and an execution edge in tests, never arbitrary foreign execution or new credential authority.
