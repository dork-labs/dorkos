The one open question: what absorbs a chip when it ages out of the live window?

Both demos below: new chips pop in on the right when a tool touches something (bursty, event-driven — motion only on arrival, never continuous). The oldest chip doesn't slide off into nowhere — it visibly folds into the thing on the left, which is clickable and opens the tray.

Option A

Ledger — chips fold into ticking counters

Absorption target is the kind-counters. When a chip ages out it shrinks toward its counter, which pulses and ticks up (watch the 📖 number). Reads like instrumentation: "the count just went up because that went in."

Research receipts, briefly: every serious product dedupes to one entry per file with net diffstat (Copilot's panel, Claude Code's /diff Current view); Claude Code additionally offers a chronological per-turn lens as an opt-in toggle — hence the "kind ⇄ chronological" switch in the tray. The two documented anti-patterns we're avoiding: Copilot's expanded panel eating the chat by default, and Codex refusing to show even a file list when the diff is big. Cursor has a confirmed bug from deduping by "currently tracked state" — we'll dedupe by append-then-merge over the event stream instead, so an edit can never be silently dropped.
