### Task 1.1: Add sticky main HTTP admission and prove the early request boundary

Size: medium. Priority: high. Dependencies: none.

Implement DOR-2551 — Refuse new main server requests once shutdown begins — only for the selected admission-only phase A1–A5. DOR-2481 remains the completed design delivery; this phase does not mark the full specification implemented. Add one passive MainRequestAdmission class under apps/server/src/services/core/lifecycle with monotonic synchronous idempotent close(), a query for its state, and no domain or process effects. It cannot reopen. Fresh instances are permitted in tests; production must share one root-owned instance across HTTP and upgrades. Add middleware/terminal-admission.ts and inject the admission instance into createApp. Follow existing construction conventions without creating a separate production fallback instance.

Install the gate as the first Express middleware, before first-contact callbacks, CORS, host/auth controls, signed webhook dispatch, JSON/body parsing, sessionGate and every route. While open it calls next() and leaves downstream security behavior unchanged. Once closed, refuse every method/path with HTTP 503 JSON carrying stable code SERVER_STOPPING and generic message “The server is stopping. Try again after it restarts.” Set Cache-Control: no-store, Connection: close and X-Content-Type-Options: nosniff. Add no Retry-After, health/OPTIONS exception, path allowlist or selected-operation/error detail. Refusal precedes CORS, so cross-origin terminal callers may see a network error. Admission occurs at this synchronous gate for each request, including each request on an existing keep-alive connection; passing it permits an already-admitted request to proceed even if later waiting in auth or body parsing.

Prove A1–A3 through real loopback HTTP and the actual Express app, with purpose comments, exact handler counts and positive controls. Running requests reach handlers; requests after close never do, including later-mounted routes and reuse of the same TCP connection. Enumerate actual main-app mounts to cover auth, signed webhooks, API, MCP, A2A, health, SSE, static and OPTIONS rather than relying only on a fixed literal route list. Assert terminal response code/headers and refusal before a parser or dispatch can act. Preserve running-state auth/origin refusals. Hold one admitted handler and an established SSE stream, close admission, prove a later request is refused, then release the original work and demonstrate it survives and can finish. Use controlled events/promises, never sleeps or negative polling.

No cancellation, response-finish accounting, active-socket destruction or drain wait is added. Existing sockets, handlers, detached turns, separate listeners and background producers remain outside this admission guarantee. Do not add TerminalOperationOwner, alter admin reset tokens/actions, add dependencies/config/schema, or change DB/lock policy.
