# Reliable Codex sessions: tasks

### Task 1.1: [codex-session-reliability] Run a compatible Codex and discover selectable models from its account

Update CLI, SDK, desktop platform packages and provision pins together to a verified current stable version. Replace the static model catalog with bounded model/list discovery using the executable and authentication context DorkOS actually uses. Preserve explicit binary overrides and user-selected models; do not silently switch model or billing. Test subprocess lifecycle, pagination, malformed output, unavailable discovery, caching and changed identity. Prove a real browser can start and resume a Codex turn.

### Task 1.2: [codex-session-reliability] Make Codex failures actionable and keep warnings out of error cards

Translate known model/version rejection envelopes into short recovery guidance with raw details available. Preserve existing sign-in repair, unknown error messages, terminal verdicts and replay. Known nonfatal metadata and model-switch warnings must be calm notices. Test mapper, persisted history and browser rendering.

### Task 1.3: [codex-session-reliability] Restore agent-scoped DorkOS tools when app login is enabled

Production with app login enabled withholds DorkOS tools without a global environment bearer. Implement secure agent-scoped access using existing identity and capability architecture. Never grant a human/global credential, enable local tokens under login, or broaden A2A access. Preserve room membership checks, owner-only operations and explicit feature disable. Verify discovery and tool calls through real HTTP; denial tests cover forged/revoked identity and forbidden operations.

### Task 2.1: [codex-session-reliability] Verify combined behavior and deliver reviewed PR

Integrate the three branches without dropping changes. Run affected verification and browser smoke coverage. Send bounded real Codex turns from the browser in the disposable data directory, including resume and read-only DorkOS tool use with app login enabled. Inspect screenshots at desktop and mobile sizes. Independent adversarial reviewer receives base/head diff, REVIEW.md and this specification, fixes converge before PR. Commit one curated changelog, push, PR, green CI and authorized delivery. Preserve evidence outside removed worktrees. Close tracker items only after delivered; remove only clean pushed worktrees.
