Names, verbs, and the avatar signal system

Answers to your three questions, with the code audit behind them.

1 · Does "Agent › title" fit on one line?

🧭Marketplace Compatibility Auditor›Verify Claude Code superset compliance for all plugins2h
Real flexbox, not a drawing — resize your window and the same rules hold. Row 3 is the worst case: both names absurd, both ellipsized, row intact.
  • Yes, it fits — with a budget. ~175px of text space per row at our density. The agent name is capped at 42% of the line and ellipsizes past that; the title flexes into the rest with a guaranteed minimum (~6 chars) so it never vanishes entirely. Time/status never gets pushed off.
  • The name wins the tie — attribution is the anchor you scan by. The title is recoverable from hover (full "Agent › Title" tooltip — already our row pattern) and from the open conversation itself.
  • Two system-level assists: session titles are auto-generated today — we bias the generator toward ≤4 words. And agent display names already run through disambiguateDisplayNames, so we lean on that instead of long names.
  • Working rows put the verb on line 2, so line 1 never competes with status text.

2 · Can we really know what an agent is doing?

LadderShowsWhenReliability
1"editing RoomRow.tsx", "running pnpm test"Live tool event with a recognizable name + inputClaude Code: always · Codex/OpenCode: generic form ("running a command…", "editing files…")
2"working…"Turn is streaming, tool unknownAll runtimes, guaranteed — lifecycle is part of the runtime contract
3"waiting on you"Blocked on approval/questionAll runtimes (that's a Now item anyway)
4nothingIdleAbsence = calm
The honesty ruleDegrade down the ladder, never guess. If we can't name the tool, we say "working" — the verb is an upgrade, not a promise.
  • The data already exists. Every session streams live tool_call events carrying the tool name and its input (the file path is on the wire), and getToolLabel already turns those into exactly these labels — the chat transcript uses it today. Nothing new to invent.
  • One gap to close: the sidebar listens to the fleet-wide stream, which today carries only idle/streaming/blocked — no tool info. Fix: the server piggybacks a throttled activity label onto that stream's status events. Small, contained server change; this is the one real engineering task behind the feature.
  • A found absurdity: the chat status strip currently shows randomized joke verbs ("Droppin' Science") while the real tool name sits unused in the same stream. Same ladder fixes chat too — one verb system everywhere.

3 · The avatar signal system

You were right: the lower-right corner is already claimed. The audit found the full picture — and five inconsistencies to fix.

🐙
Top-right = status. What's happening right now. Dot only.
Bottom-right = identity. What this is — bot mark, Telegram logo. Static, permanent.
Trailing in the row = origin. How a session started (timer, paper plane, #). Never on the avatar.
🐙idle — no dot 🐙working — green, pulsing 🐙needs you — amber, still 🐙error / wedged — red, still 👤bridged human — logo, circle
Three layers, three homes, no collisionsStatus never touches the identity corner; origin never touches the avatar at all. Only working pulses — urgency is shown by color + the Now zone, not by more motion. Square = agent, circle = person (already our system — keep).
What the audit found (to fix during the overhaul)
"Working" renders 5 different ways today — static dot, pulsing dot, a different color token on group headers, dot + words, and an avatar ping. One fact, one rendering: the avatar-corner dot (+ verb text where there's room).
Most avatar pulses are lying. The dot lights when the agent was heard from within ~an hour — a liveness proxy, not "working now." New rule: the dot means a turn is streaming right now, full stop. Heartbeat-freshness moves to the hover card.
Two greens for one fact (health ring at 60% + status dot at 100%, 2px apart), plus raw green-500/amber-500 spellings alongside the proper status tokens. One token set; the health ring retires from list rows.
The Bot glyph lives in two unrelated systems (avatar corner badge + inline origin mark) with no shared registry — they can drift. One glyph registry feeds both.
The corner is triple-booked in one spot: the Agent Hub hero stacks a hover pencil on top of the identity badge. Edit affordances move off the avatar.
