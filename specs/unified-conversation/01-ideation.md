# Unified conversation surfaces — one tree, approvals anywhere, a live lane

## 1) Intent & Assumptions

- **Task brief (Dorian, 2026-08-17):** DorkOS has three messaging surfaces — the direct agent session chat (`/session?dir=…&session=…`), rooms/channels (`/channels?id=…`) and DMs (also `/channels?id=…`). Three asks:
  1. **All surfaces use the exact same components**, composed differently (React composability + `cva`/`tv` variants), not duplicated.
  2. The room notice _"Meeting Notes is waiting for you to approve something before it can carry on. Open Meeting Notes's session to answer — it gives up if nobody does."_ is an awful experience: the person hunts for the session, answers, comes back; if they cannot find it, the prompt auto-denies after ten minutes and the agent gives no answer or a bad one. **10x it.**
  3. _"Meeting Notes is working on it"_ is good but should sit **above** the composer, be **clickable**, show every state, and be worth a 10x pass (progressive disclosure, delight, actions).
  - Everything updates the Dev Playground; restructure sections as needed.
  - Bar: what an S-tier product designer + motion designer would ship; Jobs/Ive/Rams filters (`meta/website-copy/process.md`); Calm Tech; `writing-for-humans` copy.
- **Design session (2026-08-17, visual companion):** `design/01-messaging-exploration.html`, picks in `design/picks.jsonl`. Dorian's choices:
  - **unify-B** — unify the _whole_ tree in one programme (row, timeline, live lane, composer host), not a partial.
  - **ask-B** — inline Ask in the room **plus** one global "Needs you" tray built by extending the queue that already exists (header pill, sidebar Heads up, home triage). Tier C (notification actions, park-instead-of-deny on timeout, scope options) is the named follow-on.
  - **place-A** — a **reserved, fixed-height lane** above the composer (Slack model, zero layout shift), not the floating pill.
  - **peek-2** — click peek (who / how long / what it is answering / Open its session) **plus Stop plus the amber needs-you state**. Tier 3 (the verb glimpse "is reading standup.md") is a follow-on.
- **Assumptions:**
  - Local rooms are single-identity today (one human on this machine); multi-human rooms exist only via Telegram/Slack bridges. The privacy rule (detail only to who can answer) is designed in now, enforced structurally, but the multi-human path is exercised only where the bridge already carries approvals.
  - The DM surface **is** the room surface (`RoomKind = 'channel' | 'dm'`; kind changes naming only) — so "three surfaces" is two implementations to merge, three presentations to keep distinct.
  - The session chat's `ChatStatusStrip` (elapsed · tokens · mode · waiting · operation progress · activity) folds into the same live lane so all surfaces share one status vocabulary; the session-only extras (tokens, permission mode) become lane content variants, not a second strip.
  - Operator pre-authorised gate progression for this run (project creation, PR opening, merge) — decisions are made, disclosed here, and open to reversal in review.
- **Out of scope (deliberately, follow-ups filed at DECOMPOSE):**
  - Approvals tier C: desktop/Telegram/Slack notification **actions**, park-instead-of-deny on timeout, "don't ask again for this file/folder/agent-in-room" scope options.
  - Presence tier 3: the verb glimpse on the room presence wire shape.
  - Human typing indicators in rooms (spec `room-presence` §5.2 keeps that a separate row, if ever).
  - Codex/OpenCode approval parity beyond what the runtime interface already carries (DOR-803 stays its own item).
  - Rewriting the Obsidian embedded mode beyond keeping `DirectTransport` parity for the new transport methods.

## 4) Root Cause Analysis

Not a bug fix. The one incident-shaped fact worth stating: DOR-784 (2026-07-31) — agents sat silent 20–41 minutes in rooms because their prompt only showed in their own session; the fix then was the late notice. This programme is the real fix: the prompt reaches the person wherever they are.

## 5) Research

Prior research covers this ground (see §2); no new external research needed. Options weighed in the design session, with the operator's picks:

1. **Component unification shape**
   - A) Row + live lane first, then list, then composer host (incremental) · **B) Whole tree in one programme (picked)** · C) Live lane only.
   - Recommendation implemented: B, with an internal PR train ordered row → live lane → timeline → composer host so each PR is reviewable, nothing landing half-migrated to `main`.
2. **Approvals surface**
   - A) Inline Ask in the room · **B) A + one global Needs-you tray extending the existing queue (picked)** · C) B + notification actions + park-on-timeout + scope options (follow-on).
3. **Presence placement**
   - **A) Reserved lane above the composer (picked)** · B) floating pill · C) composer strip.
   - The lane answers the spec's objection by construction: it never changes height, so nothing is pushed. Its cost (one blank line in a quiet room) is accepted; the session chat already pays it for `ChatStatusStrip`, so consistency improves.
4. **Peek scope** — **tier 2 (picked)**: names, times, jump-to-triggering-message, Open its session, Stop, amber needs-you. Tier 3 verb glimpse deferred.

**Recommendation:** proceed to SPECIFY with the decisions below; the spec designs the `Conversation` compound, the `Ask` model + wire, the live-lane state machine, and the Dev Playground page.

## 7) Risks

- **Regression surface is the whole chat.** Mitigation: the PR train order (row → lane → timeline → composer host), the shared conformance of `Feed`/a11y, `apps/e2e` chat + rooms suites, and adversarial review per `REVIEW.md` before every PR.
- **Virtualizing the room timeline** changes scroll/stick-to-bottom behaviour rooms have tuned by hand. Mitigation: port `useStickToBottom` semantics into the shared list behind the same tests; browser-verify unread cursor + thread open.
- **Ask authority in bridged rooms** — a wrong default here is a security bug. Mitigation: fail closed, reuse `approver-allowlist`, and add the route-level authority check system B already has.
- **Global fan-out churn** — `interaction_pending` must not carry per-second countdown; the client seeds from `startedAt + timeoutMs` (server-authoritative), same as today.
- **Reserved lane on mobile** — 22 px is fine on a phone but must never wrap into two lines; the lane truncates and the peek carries the rest.
