# Agent computer MVP tasks

Three implementation tasks and one independent verification/shipment task.

Shared contracts and ownership: Task 1.1 owns services/computers/backend/types.ts and private backend contracts. Publish types before parallel integration: ComputerManager create/start/status/stop/exec/endpoint; immutable computerId and observed generation; explicit ready/stopped/failed/uncertain phases; private authenticated runtime/display/bridge endpoint handles; current-generation checks; lifecycle subscriptions. Endpoint secrets never enter public schemas. Task 1.3 owns packages/shared/src/computer-schemas.ts and public Transport methods. Task 1.2 owns runtime registration/bindings and exports a composition factory consumed by Task 1.3. All public operations use computerId plus generation where action authority requires it; no caller-selected URL/path/executable/runtime id. Backend exposes guest project /home/agent/project and host metadata anchor; Task 1.2 owns exact wire translation. Each task supplies focused tests in its owned directories. Coordinate interface changes explicitly; do not edit another task's files. Task 2.1 alone integrates necessary cross-owner repairs after implementation writers finish.

The three implementation tasks may proceed in parallel after publishing their contracts. Backend readiness and runtime admission must exist before real UI acceptance. Task 2.1 depends on all three. No estimates or new research programme.

### Task 1.1: Build the managed Linux computer and guest

Phase: Implementation. Dependencies: none. Parallel with: 1.2, 1.3.

Own apps/server/src/services/computers/** including private backend contracts, lifecycle storage, Lima/VZ backend, installer, guest source, desktop/control service, guest computer/browser tools and tests; own new scripts/agent-computer/** and reproducible guest asset manifests. Do not edit runtime registration, shared public schemas, routes, server entry or client UI. Read existing lifecycle and subprocess patterns before implementation. Publish the private contract first.

Provision exactly one persistent darwin/arm64 Lima/VZ Linux computer using pinned, SHA-256-verified managed Lima and Linux inputs, bounded downloads, argument-array subprocesses, explicit scrubbed environments and DorkOS-owned instance names/Lima home. Install no global host dependency. Supply a reproducible guest with non-root agent user, Node/git, unmodified OpenCode, visible Chromium with one persistent profile, Xvfb/Openbox, an authenticated bounded PNG/input helper and a visible terminal. Do not require customer terminal, Docker, compiler or separately managed daemon. No host mounts (explicit empty mount configuration), SSH-agent forwarding, host auth-store copying, inherited model keys, credits or inference during bootstrap. Keep privileged guest administration separate from agent shell.

Persist owner-only symlink-guarded record/disk and lifecycle journal: intent before entry, outcome after observed completion. Singleton create is idempotent under concurrency; start reconnects retained state; stop/server shutdown/disable retain disk. Exact ownership/generation governs all processes and endpoints. Interrupted observation or ownership mismatch becomes uncertain, preserves resources and prevents automatic replacement; process absence alone never proves clean stop. Bound outputs/deadlines, expose truthful progress and safe errors, and prevent stale completion publishing readiness.

Enforce guest firewall outside agent privilege against host-loopback, private/LAN, link-local/metadata and unsupported IPv6; explicitly allow only needed DNS and authenticated DorkOS bridge access. Bind forwarded OpenCode/display/debug services privately, authenticate endpoints and expose no LAN listener or arbitrary reverse forward. Build guest screenshot/input/browser tools against the same display/profile, never host Chrome. Backend takeover service accepts only live generation-bound lease authority, pauses/interrupts conflicting agent input, revokes earlier controllers, releases held inputs and rejects queued stale messages. Viewer disconnect does not stop computer.

Acceptance: focused lifecycle tests cover concurrency, interrupted/restarted journal, ownership refusal, stale generations, bounded failure and data retention. Negative tests cover mount/auth/env exclusions, private endpoints, lease revocation and exact instance ownership. Provide actual non-inference guest proof of boot, shell write/read, real desktop/Chromium frame, stop/start persistence and actual guest network/privilege denial. Record timings and logs without secrets; no fixture-only VM readiness claim.

### Task 1.2: Route admitted sessions to the computer OpenCode runtime

Phase: Implementation. Dependencies: none. Parallel with: 1.1, 1.3.

Own new apps/server/src/services/runtimes/opencode/computer/**, required existing runtimes/opencode/** changes, runtime registry and durable session binding code/tests; narrowly scoped session directory admission/resolution helpers where needed. Do not edit services/computers/**, public computer schemas/Transport, Hono route mounting/server entry or client surfaces. Export a composition factory accepting Task 1.1 manager contracts and explicit enabled/generation authority. Preserve existing host OpenCode registration and behavior.

Create a distinct stable computer-scoped OpenCodeRuntime instance through the existing registry/settings path, backed only by the authenticated guest endpoint. Use existing HTTP session/history/event/approval mapping; keep global event hub and peekClient scoped to this instance. Bind each created session durably to computerId, generation, runtime id and exact directory. Use a host metadata-only workspace anchor for existing host agent identity/path admission, with an exact narrowly scoped wire mapping to /home/agent/project. Translate structural canonical directory fields in HTTP requests/replies/history/events only; never string-replace prose, tool content or arbitrary paths. Refuse unknown/foreign directories and caller-specified endpoint/credentials/runtime identity. Ensure session aliases, listing, settings, resume/reconnect, interrupt and subscriptions route to the same retained computer after host restart.

Computer provider refuses DorkOS credits and host model environments/keys. Audit credits-sidecar preparation and model discovery so they cannot start/restart a host process or choose a different bill. Unauthenticated/login-expired state yields Sign in; endpoint loss visibly ends affected turn without replay or host fallback. Experiment disable fences all new work and subscriptions before joining exact owned stop; stale generation endpoints cannot accept a turn.

Provide an authenticated reachable guest MCP bridge with current actor identity, permissions, audit, pause and Rooms limits. Do not project arbitrary host localhost URLs or stdio configurations into the guest. Advertise only implemented reachable tools and explicitly refuse unavailable managed tools; do not grant general host shell/files. Guest computer/browser capabilities use Task 1.1 same-display service and obey takeover fencing.

Acceptance: meaningful runtime tests prove two independent host/computer providers and event hubs, exact structural directory round-trip, untouched text, foreign anchor refusal, durable binding/restart history, interrupt/approvals/audit/pause continuity, unavailable tool refusal, provider loss and disable fencing. Negative tests prove no host fallback or subprocess, no credits/key adoption, no foreign computer endpoint or broad boundary exemption. Through actual guest sidecar, prove session/history APIs and runtime shell/file tool capability without inference; retain an explicit unverified real-model reply gate until separately authorized.

### Task 1.3: Compose the authenticated computer API and app experience

Phase: Implementation. Dependencies: none. Parallel with: 1.1, 1.2.

Own packages/shared/src/computer-schemas.ts plus required exports/Transport slices; computers.enabled config/experiment declarations; apps/server/src/routes/computers.ts and route tests; server Hono mounting/entry composition; client computer entity/feature UI, HttpTransport and relevant Team/Experiments entry points/tests. Do not edit services/computers/** or runtime/provider/binding implementations. Consume Task 1.1 private manager and Task 1.2 runtime composition exports; keep endpoint credentials and raw host paths out of public schemas.

Add a default-off Agent computer experiment using existing config/settings path. Authenticated /api/computers operations have closed shared schemas for singleton create/start/status/stop, session creation, sign-in, viewing and exclusive takeover. Responses include safe id/name/platform/phase/observed generation/runtime-session anchor/readiness/error data only. No customer URL, executable, credential, mount or runtime id inputs. Use real Hono ApiEnv/readJsonBody/request facts and existing authority chain; no extra unauthenticated server. Disable atomically fences runtime/view/control, revokes leases and joins manager stop while retaining data.

Provide app flows from Team/agent or experiment action: enable, truthful download/setup progress, retryable failure/uncertain state, Sign in, normal Chat, View, Take over, Return control, Stop and retained Start. Sign in launches actual unmodified vendor program inside guest and shows its terminal/browser; tokens remain guest-owned and never copied/logged. Chat creates the computer-bound normal admitted session through runtime registry/settings. Observe is default; host desktop proxy requires current authority and generation, and input requires live exclusive lease. Close previous control channels on takeover/revocation; release held inputs and refuse delayed messages. Closing viewer leaves computer running. Use same displayed guest desktop/browser as agent tools and support real touch/keyboard/pointer interactions.

Follow FSD/shared UI, writing-for-humans and writing-app-copy; each app text block at most 15 words. Unsupported hosts receive concise honest reasons, no fallback. Show explicit Sign in/provider loss and uncertainty without claiming VM success from fixtures. Never expose guest OpenCode/display ports to LAN.

Acceptance: route tests through real Hono chain cover unauthorized access, unknown fields/foreign ids/generations, closed responses, idempotent creation, disable race and no credential leakage. UI/viewer tests cover progress/error/retry, normal chat navigation, observe rejects input, exclusive takeover/revoked queued messages, held-input release, stop/start and viewer-close retention. Browser acceptance on built app must create/sign in/view the real guest surface with mobile/tablet/desktop layout and meaningful pointer/keyboard/touch proof.
