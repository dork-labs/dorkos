# Your activity first: Today, agent clicks and chat lists follow what you touched

**Status:** Specified
**Author:** Claude (SPECIFY for Dorian Collier)
**Date:** 2026-10-08
**Linear:** DOR-2789 (approved by Dorian 2026-10-08; the diagnosis and rules are his and are not re-litigated here)
**Ideation:** [`01-ideation.md`](./01-ideation.md)
**Amends:** `specs/sidebar-now-today-library` BC-15..BC-21, BC-34, BC-35; `specs/sidebar-simplification` D6; `contributing/sidebar-model.md`

## 1. Overview

The sidebar, the agent click and every chat list follow **what you did first, and what agents did second**. Today, the agent click and the chat lists answer from one server-held fact per chat, "when you last touched it", and from one rule about whose a chat is: what you did in it, not how it started. The two chat lists (an agent's profile, and Switch session) become one component. Everything people read says "chat", never "session".

**Words:** a chat started by another chat is a **spin-off** (Dorian, 2026-10-08). "Helper" means a subagent inside a chat; never call a spin-off a helper.

## 3. What changes, by PR

1. **Server (this spec's PR)**: `@dorkos/db` migration for `session_touches`; `services/session/origin/session-touch-store.ts`; the overlay step (D5); `POST /:id/opened`; the write hook in `POST /:id/messages` (D4); `touchedSince` on `/recent` (D6); `Session.lastTouchedByYouAt` in `packages/shared` and `Transport.markSessionOpened` on every transport.
2. **Today and the agent click**: D3's chat-page hook, D7, D8, D9, D10.
3. **One chat list**: D11, D12; Switch session and Profile → Sessions render `ChatList`; whatever they replace is deleted.
4. **Wording**: D13.

## 4. Tests that pin the ticket's scenarios

- Leave a chat you typed in and it stays in Today (`today-rules`, with a window wider than 10 in which agents outrank it).
- A busy spin-off chat never wins an agent click (`resolve-session-for-cwd`).
- A room-born chat you typed in counts as yours (server: route write → overlay; client: `chatOwnership`).
- Opening by deep link counts as touched (chat-page hook test, plus the route).
- A relayed room turn, a task fire and an agent-identity POST never set `wrote_at`.
- Profile → Sessions and Switch session render the same `ChatList` component.
- The vocab gate is green with the new wave.

## 5. What is not done, and why

- **No backfill.** Chats you used before this ships have no server touch until you open or write in them again. A room-born chat like the #dorkos coordinator becomes yours the first time you open it. Reading old transcripts to guess which user records were typed by a person is exactly the guess D5 refuses.
- **The `/session` URL keeps its name.** Renaming it would break every saved link; it is a separate follow-up if wanted.
- **One person per install.** D2 is deliberate; do not add a person column until there is a second person.
- **Do not "fix" D4 by trusting any POST.** Coordinators wake chats by POSTing to this route from a shell; counting that as you is the bug this spec removes.
