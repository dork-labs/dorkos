## Earlier answer

There is **no existing runtime-neutral “this session is failed, reset it” fact**. `lifecycle:error` is a projection of a failed turn, not native session invalidity. The source-confirmed recoverable condition is a **verified existing native conversation that can no longer be continued**. Native reads can establish this without running a model, but the current convenient getters lose important distinctions. Use strict adapter-owned continuation probes, not historical error text. Unknown historical error, account, active state or store health cannot authorize replacement.

For Claude Code and OpenCode, add a narrow read-only continuation method backed by the exact native store/API. Codex already owns real native replacement and must not receive a second room-layer recovery. Doe has no proven session-invalid error and remains unsupported/unknown for automatic replacement; ordinary sends and truthful declines still work. This is bounded recovery of verified stranded seats, **not a claim that every prior failed room chat self-heals**.

## Minimal typed seam and ownership

Add optional runtime-neutral **read-only** `inspectSessionContinuation(sessionId,cwd)` via a small shared contract (separate module/interface to respect max-lines), implemented inside adapters only. Suggested discriminated result:

- `resumable`: native exists; no authority to reset.
- `stranded`: source `claude-transcript-absent` or `opencode-session-404`, exact expected native identity and verified owner/runtime/config anchor. This is the only new room-reset grant.
- `runtime-owned`: Codex already handles native replacement; run normal aside once and preserve its outcome, no room-reset fallback.
- `unknown`: unsupported/missing provenance/inspection failed. Optional method absent also means unknown.

Never expose raw account path, key or recovery payload to model tools. Room composition injects an opaque adapter-held recovery plan or a private verified account launch hint; caller can't supply it. New shared typing includes only source/expected-native identity, not a client-writable `safeToRetry` boolean. No historical `lifecycle:error` grant and no new failure ledger/migration needed. A current authoritative protected refusal or unresolved interaction vetoes replacement even when native absence is proven; native loss never overrides permission, pause, account/sign-in/usage or crash-loop policy.

Retain RoomTurnReply.failure and start evidence into AsideResult for truthful reason and **negative** policy checks. This is distinct from native continuation proof. If a running attempt yields a typed session-loss failure, re-probe native state while claim remains held and recover only if no effects/active work and runtime says its own recovery was not already consumed. For this first implementation, safer concrete scope is **preflight stranded recovery only**; post-attempt generic failures report honestly. Claude/Codex already do internal resume recovery, so do not add automatic fallback after their exhausted result. Any future post-attempt grant must carry explicit adapter recovery-consumed/effect facts; no regex or “no text” shortcut.

Probe while the room claim is held, then recheck original binding, authoritative in-flight lock (`isTurnInFlight`), holdsBackgroundWork, pending interactions, pause/Stop, room membership, budget and same runtime/account/inference before applying one compare-and-rebind. No `beforeTurn` usage-failover call. Missing mapping/native state or unprovable account continuity is an honest recovery refusal, not a launch under a fresh default.

The original DOR-3556 phrase “failed state or failed before turn_start” is preserved as a problem/acceptance target, but raw historical error is not reset authority. The approved guard exclusions require this precise classification. If product expects recovery for a prior failed session that is neither native-stranded nor already recovered by its adapter, it needs a new positive runtime-owned failure contract; do not mark that wider behavior complete from synthetic test data.
