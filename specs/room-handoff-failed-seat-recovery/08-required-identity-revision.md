## Responsibility and atomic owner

The first authoritative native move remains `RuntimeRegistry.rekeySessionSettings`, awaited by the real SessionStore rebind before SDK event yield. Its initial database acquisition and source/destination reads currently escape mandatory classification; its ancillary moves currently precede required ownership validation. Both are unsafe.

Required correction:

1. Read both metadata markers AND direct requirement records through `RequiredRoomLaunchStore.forSession` before any mutation. Do not return because source metadata is absent. A missing direct-record marker, corrupt requirement, unknown connection/read result or failure to establish responsibility becomes `RequiredSessionIdentityError` with the original cause. Optional legacy persistence-loss behavior applies only after positively establishing that both ids are unconstrained. A genuine conflict/refusal is never optional decoration loss.
2. For a required move, one synchronous immediate SQLite transaction owns strict responsibility/occupancy reads, requirement/reference/native/metadata changes and the relevant SQLite aliases: ancestry (including children), context, limits, touches, task runs and beat chats. The transaction must use the actual Registry database connection throughout. Add only narrow `moveWithin(tx, ...)`/equivalent contributions to existing stores where necessary; their required path must not catch-and-log failures. A callback after commit is not an atomic participant. No new identity service or report feature is introduced.
3. Existing ancillary ordinary-session policy remains on the positively ordinary path. Required path in-memory aliases/context caches/SDK index/projector/turn keys publish only after SQLite commits. If a mandatory contribution fails, its transaction rolls back and no optional `moveAlongside` swallows the error.
4. The projector-first path must execute the same required ownership leg, or recognize an already committed matching immutable requirement move. It cannot remain a second weaker callback that independently blesses a target. Repeated already-owned announcements are idempotent; a refused operation stays refused.

The eventual checked DOR-3816 transaction participant must compose with this actual required owner; no unreviewed source is copied. One transaction owns native identity. This branch cannot rely on that later feature to fix its current responsibilities.

## Occupied destination and actual live SDK object

Matching agent, runtime, cwd or account root does not establish conversation identity. A required move refuses an independently occupied destination, including same-agent/same-root native bindings and metadata. An already committed alias with the same immutable requirement id and consistent destination is positive proof. Vacancy means no independent metadata/native/ancestry/history ownership AND no independent live SDK object or projector/history; DB absence alone is insufficient. Existing SessionStore and projector owners reject their local live collisions before any durable publication. A truly vacant destination can be adopted. Existing metadata-only/scanner pre-seeding must not be treated as alias proof merely because its fields match. If a genuine first-announcement pre-seed needs a positive exception, its exact server-owned producer witness and absence of independent ownership/history must be proved by a separate regression before enabling it. Current schema alone supplies no general logical-conversation id. This remains an explicit architecture decision, not a permissive fallback.

`SessionStore.rebindSdkSession` captures the exact original object and map owner before await. Actual SDK init has already changed that object. On a mandatory refusal, restore its prior SDK id only if that exact object still owns the captured map key; retain the exact typed error in an object/operation-owned quarantine. Later provider-affecting ensure/send/rebind on that refused object must throw before native transcript or provider lookup. getInternalSessionId remains read-only and returns its restored original id; sticky canonical operation state owns throwing, without broadening UI/control lookup contracts. Never mutate a successor/replacement object at the same map key or the independent target. Failed persistence never publishes the target reverse index. Quarantine must not become an evict-and-cold-resume escape: durable requirement/reference remains authoritative for later cold sends.

`createCanonicalRekey` retains its first mandatory refusal, rethrows it on final/repeated observation even after the SDK id is restored, and marks successful resolution only after mandatory projector ownership succeeds. No chain link, target lock, canonical response or turn-key publication can precede that success.

## Task ownership and truthful terminalization

`claimRunTurn.finish` closes/drains projection and attempts final canonical ownership, then unconditionally withdraws the original projection's pending interactions and releases the lock/queue claim it actually owns. It must preserve a mandatory finalization refusal. Repeated finish is bounded/idempotent and cannot release an independent target. The prior “never rejects” contract must be amended rather than silently contradicted.

The direct scheduler owns its accounting release in its own unconditional finally, even when projection finish rejects. It records a pending result while consuming the body, finalizes identity for every outcome, selects the final truthful status/id, and writes one terminal row afterward. Body failure remains the primary error if finalization also refuses; final-only mandatory refusal produces failed under the original id. Stopped/cancelled and stream-error outcomes also pass finalization before terminal persistence. No early success/cancel/failure terminal or target association may be committed first and patched later; TaskStore's monotonic guard stays intact. Terminal hooks/notifications therefore observe only the validated identity and final outcome.
