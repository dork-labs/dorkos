## Findings saved from independent review

1. Native-stranded-only preflight does not meet DOR-3556's failed-seat acceptance. Deleting a transcript changes the reported bug and cannot prove recovery of a failed seat with an intact transcript.
2. Do not claim every acceptance requirement is covered or infer that four runtime probes are the smallest sufficient change.
3. Reuse/strengthen `RoomSeatMover.reseat` at `seat-mover.ts:492+`; do not duplicate settings/marks/binding/Activity logic. `beforeTurn` is too broad because it also does usage/account failover.
4. A prior terminal failed turn is different from retrying work that is currently failing. Unknown historical, auth/usage, crash-loop and active states do not authorize recovery.
5. Source remains gated on DOR-4472 review. Root explicitly approved the following narrow structured server_error candidate, keeping generic historical failures open and requiring Code live QA to match the observed report shape before closure.

## Concrete intact-transcript classifier

**Positive witness:** the most recent complete prior **Claude room dispatch** has an actual structured SDK assistant `error:'server_error'`, ends as failed, has no mixed/protected/unknown diagnostic, and is not followed by any new turn. The transcript remains readable/intact. Before replacement all current room/runtime guards must allow new work; actual runtime/account/inference choice is proven and preserved. This authorizes one fresh seat for the **new hand-off draft**, not a replay of the prior failed turn.

### Exact decision rule (design, not implemented)

1. Resolve canonical current seat and runtime from room binding/runtime registry; runtime must be Claude, unchanged from actual old session. Capture exact old seat id and last durable/live turn watermark.
2. Read the latest complete prior room turn through strict parser with both boundaries. It must be the latest session turn, have an actual `server_error` assistant witness and failed terminal, not successful/interrupted/stopped. A new/current hand-off must not have started on that old session yet.
3. All diagnostics in the prior turn must be classified. Exact server_error is the positive cause. A terminal SDK result `error_during_execution` can be a wrapper **only when a typed producer-side fold proves it closes that same server_error failure and adds no other cause**. It never qualifies by itself. Without that provenance, mixed/generic wrapper is unknown, not presumed safe. Raw strings such as “server error” grant nothing.
4. Any protected or unknown code/category/refusal vetoes recovery. Includes rate_limit, auth/billing/account-hold/verification/credentials/model-selection/invalid_request/safeguard, max turns/budget/output retry caps, turn_not_started protected reasons, Stop/pause, crash-loop, usage and current pending interaction. Unknown diagnostic is not “probably a server error.”
5. Verify intact transcript under the **known actual** account and bound cwd. Missing, unreadable or ambiguous transcript is outside this failed-with-intact-transcript slice. Never delete/rename it to manufacture eligibility; retain it as old history after replacement.
6. Recheck current pause/halt, no dispatcher/runtime/projector live turn (`turn-probes.ts:162-172`), no pending interaction/capability hold, no holdsBackgroundWork/helpers, current usage/sign-in/account-policy/crash recovery gate and room membership/liveness/archive/budget. Read crash gate from the actual existing Claude SessionCrashRecovery (`session-crash-recovery.ts:183-195`); a narrow read-only adapter accessor is permitted if not exposed. Do not move to a fresh id to escape willAutoResume:false. Unknown current guard answer vetoes.
7. Root-approved policy: start one fresh seat for this _new_ hand-off through the existing mover primitive, preserving account/runtime/inference/settings/marks, with expected-old-binding CAS and same watermark. Revalidate after any asynchronous summary/account read. CAS/watermark mismatch aborts rather than superseding later work. One recovery per hand-off, no fallback after that fresh attempt fails.

The producer correlation is exact: within one SDK turn, retain the typed assistant server_error witness and its raw notice fingerprint; veto any other assistant error/refusal or protected result. A final result wrapper may be marked `reason: claude-server-error-terminal` only when subtype is error_during_execution, it was not stopped, every result.errors entry is either absent/empty or an exact echo of a witnessed server_error notice, and no other diagnostic occurred. A different/new error string is unknown; never regex-classify it as safe. Persist this server-emitted marker through existing ErrorEvent.reason (schema already supports it; session-stream includes ErrorEvent shape and normalizer preserves reason). Historical unmarked wrapper remains unknown. This marker is descriptive evidence, not a tool-input authorization field; room classifier still requires the entire prior-turn witness and current guards.

**Scope limit:** this concrete source-backed witness supports one type of prior terminal failed Claude seat. It does not identify the actual Nov14/Oct31 incidents from ticket text alone. Generic historical failed states and pre-start failures lacking typed affirmative evidence remain open. DOR-4328/3556 closure requires Code live QA (or equivalent preserved incident-shaped evidence) matching the reported failure shape and demonstrating the post lands; synthetic flags cannot close broader acceptance.

## Reuse the mover, don't build a second one

- Existing `rooms/reseat/seat-mover.ts:492-551` already copies settings via reseatSettings, carries marks, rebinds, records old seat, creates pending launch, emits Activity and logs. New handoff recovery method validates the narrow evidence/guards then invokes this strengthened common primitive.
- Existing `:292-304` beforeTurn and subsequent nearly-out branch are **not** the entry point; ranking/pickReseatAccount and afterLimit are not called.
- Current common primitive `:525-528` only pins accountHint when `plan.target` is set. Add an explicit same-actual-account/inference launch plan for failure recovery; copying settings alone is insufficient. It must preserve source session's actual account root/registered id and credits-vs-own-inference choice, not use ranking, active-account fallback or current manifest defaults. If the source choice cannot be proven, refuse recovery.
- `room-store.ts:2234-2252` existing rebind checks retired destination but updates without expected old id. Strengthen shared primitive/store seam with compare-and-rebind expected old id and current runtime/evidence watermark guard. No transient clear-then-bind. Keep existing consumers' behavior explicit; tests cover concurrent normal re-seat and old-id callbacks.
- `seat-mover.ts:518-529` retains carrySessionMarks and recordSeatMove. No rename alias: old transcript remains old. Recovery seed uses a fixed reason and room context; no auto-resubmission of prior userMessage/task or summary text instructing it to redo prior work.
- Existing pending launch is in memory. If the server restarts before fresh launch and same account/inference cannot be proven, the new failure recovery must not silently launch on today's defaults. Preserve the launch authority through existing durable session settings/account-binding contract where possible, or abort replacement before publishing it. Designing a new general persistent recovery queue is out of scope.
- `create-seat-mover.ts` owns adapter/composition dependencies; add only narrow evidence/current-guard/actual-account readers and expected-binding rebind. No new four-runtime inspectSessionContinuation API or OpenCode source expansion. Codex native recovery remains unstacked and unchanged.
