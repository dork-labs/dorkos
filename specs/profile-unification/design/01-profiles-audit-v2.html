Profiles: what we have today

Two things are both called “profile”. They share almost nothing. Neither links to the other.

1 · Profile drawer — ?profile=<id>from Team cards, sidebar face, mention pills, hover card, account menu
  • Face · name · @handle · 3 chips · “Joined”. That is all.
  • No description, no model, no directory, no owner face, no “what is it doing”.
  • No actions for an agent. “Open a session” exists in code but never draws (project path is stripped server-side).bug
  • “No recent activity” = mesh hasn’t heard from it in 60 min. Not the real live signal.
  • Same component for people. Your own row: “On this machine” + Edit profile. Nothing else.
2 · “Agent Profile” tab — right panel on /session⌘⇧A · sidebar “Agent hub” · Team “Manage” · palette
  • Really the Agent Hub: hero + tabs Sessions · Config · Toolkit + ⋮ (default / block / unregister / delete).
  • Says “Offline” for every agent, always — health never arrives on this endpoint.bug
  • No @handle, no owner, no description in the hero. “✨ Custom” pill is a personality picker that reads like a status.
  • Sessions tab opens with two schedule presets before any conversation.
  • Inner tab isn’t remembered; hubTab=toolkit deep-link silently fails.bug

What’s weird or confusing

Two “profiles”, zero overlapClick a face → identity card. Open the panel → settings. Both say “profile”. Users must guess which one they got.
Contradicting status wordsDrawer: “No recent activity”. Hub: “Offline”. Neither is the true “working now” signal that rooms already have.
Dead-end drawerYou look someone up and can’t do anything: no Message, no Manage, no copy-handle, no “go to its sessions”.
Empty bodyAgent = one fact (“Joined”). Person = no body at all. Your own = no handle shown, no photo nudge.
Manage vs Open profileTeam table says “Manage” (→ Hub). Team card click → drawer. Sidebar row has both “View profile” and “Agent hub”.
Hero mislabelsPersonality pill looks like a status. Rename/face/personality offered on DorkBot, then the server says 403.

How others do it (in one line each)

SlackOne profile panel from everywhere. Big face, name, title, local time, Message button up top, then details. Bots: “About this app” + admin link. Full-screen on mobile.
DiscordPopout on click (peek), full profile modal on “View Full Profile”. Bot profiles show what the bot can do.
LinearProfile is a page; edit in Settings. Agent accounts show owner + what they’re working on.
GitHubHover card → full page. Page = identity + activity + what they own. Sharable URL.
BuzzAgent is attached to a human owner (vouch). Owner shown on the agent, agents shown on the owner.

The fork: how many “profile” things should exist?

Pick one. This decides everything after it.

A

Align & link — keep both, make them agree

Same header in both (face, name, @handle, owner, one true status). Drawer gets Message + Manage → (opens Hub). Hub gets @handle + owner. Rename the tab to “Manage”. Fix the bugs.

drawer: card
+
panel: manage

Pros

  • Cheapest, lowest risk
  • Keeps both mental models where they are

Cons

  • Still two things called profile
  • Two components to keep in sync forever
  • Doesn’t 10x anything
B

One profile, two homes (recommended)

There is one Profile. It has a header + tabs. On /session it is docked in the right panel. Everywhere else it slides over as a sheet (still ?profile=<id>). Tabs adapt to who you are looking at: Overview for everyone; Sessions · Config · Toolkit only for agents you manage. The Hub stops being a separate thing — it becomes the Config/Toolkit tabs of the profile.

/team → sheet
⇄
/session → docked

Pros

  • One word, one component, one mental model (Slack’s model exactly)
  • Every entry point lands in the same place; “Manage” = the Config tab
  • Docked ⇄ sheet is a delight moment (same header morphs)
  • People, DorkBot, bridged folks fit the same shell

Cons

  • Biggest refactor: fold Hub into Profile
  • Overview must be great or the sheet feels heavy
  • Two keys (member id vs path) need one resolver
C

Profile page — /team/@handle

A real page per identity (GitHub/Linear style): identity + activity + stats + config. The drawer shrinks to a peek with “Open full profile”. The Hub keeps living on /session for quick tweaks.

peek
→
/team/@wing

Pros

  • Room for rich stuff later (activity graph, cost, rooms)
  • Clean shareable URLs

Cons

  • Now three depths + the Hub = four surfaces
  • Leaves the session context to look at the agent you’re talking to
  • Most work; least “control panel” feel

My pick: B. It is what Slack does and what the identity spec already wanted (“one component, every identity kind”). C can come later as an “expand” of B if we ever need a page. A is a patch.
