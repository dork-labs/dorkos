# Runtime policy initialization feasibility

**Status:** Proposed design note. Source/API investigation with a separately owned, rejected feasibility experiment; not an approved implementation or production gate.

This note refines candidate implementation seams for [06-production-specification](06-production-specification.md), which remains untouched. The original investigation performed no dependency patch or Chromium probe. The later private experiment below changes only an isolated package copy; installed dependencies and production engines remain unchanged. Default threat model remains trusted pinned Chromium with its native sandbox enabled and untrusted pages. This does not add OS containment or protect against browser RCE.

## Investigation baseline

Installed Playwright core is 1.63.0. Its `browsers.json` identifies full Chromium revision 1243 as version **153.0.8010.12**. Read exact Chromium tag `153.0.8010.12`, exact Playwright tag `v1.63.0` and installed `lib/coreBundle.js`; source support is a candidate, not evidence that the packaged executable behaved as required. Preserve the recorded executable hash when later running fixtures.

## Sandbox and mandatory proxy

Production Playwright launch and persistent launch options must explicitly set **`chromiumSandbox: true`**. Installed Playwright adds `--no-sandbox` unless that option is true. The frozen fixture runtime currently supplies executablePath/headless only; its successful tests do not establish production sandbox-enabled launch. Reject attempts to reintroduce `--no-sandbox` or silently retry without the sandbox. Verify actual argument/config provenance and a separate sandbox-enabled fixture on every supported runtime/platform; successful option validation alone is insufficient. [Pinned Playwright Chromium launcher](https://raw.githubusercontent.com/microsoft/playwright/v1.63.0/packages/playwright-core/src/server/chromium/chromium.ts)

Use a browser-wide mandatory manual HTTP proxy to the validated broker, no DIRECT fallback, no PAC/system inheritance and no positive bypass entries; subtract implicit loopback bypass with `<-loopback>`. Apply before any external Page or worker exists. Keep the broker's DNS/IP binding, private endpoint denial, exact local-dev grants and public admin hostname rules in 06. Proxy failure never enables direct requests. Context-specific proxy APIs are not permission to weaken the browser-wide policy.

## Identity initialization limitations

Pinned Chromium's launch-wide `--user-agent` override returns blank or low-entropy-only UA metadata before full-version/architecture population. Therefore launch-string replacement alone cannot retain the native high-entropy identity required by 06. [Pinned Chromium UA implementation](https://raw.githubusercontent.com/chromium/chromium/153.0.8010.12/components/embedder_support/user_agent_utils.cc)

Playwright's ordinary `userAgent` option also does not copy native metadata. Its `calculateUserAgentMetadata` initializes architecture as x86 and derives macOS platformVersion from the frozen legacy UA. It sends that inferred structure to Emulation rather than preserving the actual native full-version/architecture descriptor. Native mode avoids an override; Chrome-compatible mode requires a different initialization path. [Pinned crPage implementation](https://raw.githubusercontent.com/microsoft/playwright/v1.63.0/packages/playwright-core/src/server/chromium/crPage.ts)

Keep legacy reduced conventions, native distribution/GREASE brands and native high-entropy metadata. Do not replace MacIntel with host arm64, invent Google Chrome brands or change unrelated locale/mobile settings. HTTP, JS UA/appVersion and negotiated hints must agree under the defined native conventions. This is not fingerprint indistinguishability or challenge bypass.

## Preferred candidate: narrow pinned metadata option/patch

Prefer an upstream-supported native-metadata context option if available in a reviewed release. For pinned 1.63.0, the following is a **proposed auditable patch surface**, not an existing public API. A DorkOS-private typed option such as `chromiumUserAgentMetadata` carries the validated native descriptor alongside the normalized legacy `userAgent`. It is not a free-form UA product surface. Reject use on non-Chromium engines and metadata without a matching UA/policy descriptor.

Type it for `newContext` and `launchPersistentContext`; do not use an unvalidated `Record<string, unknown>`.                    |

### Obtaining the native descriptor

Collect a fixture-only native baseline using the exact executable with sandbox enabled and no override. Read legacy UA/platform plus available native `userAgentData.getHighEntropyValues`; map the protocol descriptor without reconstructing reduced strings from host hardware. Bind cached descriptors to executable hash, OS/runtime and policy version, regenerate after updates, and refuse stale/missing descriptors for Chrome-compatible mode. The baseline Page is never an external authenticated website. GREASE ordering follows the native result, not a hard-coded brand list. Policy installation still must precede the first external request of each target.

## Alternative: private single-owner CDP bridge

If no narrow patch can prove full target coverage, a private engine-owned transport bridge could gate Playwright's target-resume messages until Emulation installs explicit metadata. Playwright would connect through its public `connectOverCDP` API to a token-bound private endpoint; the engine owns the browser/debug pipe and one target policy controller. This avoids competing autoattach clients and late page-event mutation, but adds launch/transport/session ownership and error propagation responsibilities. It is a fallback candidate, not the preferred default or an approved additional process/API.

Even a bridge must prove first popup network requests and worker script requests did not escape before the target event. A before-script-execution gate is not automatically a before-network gate. If neither patch nor bridge can establish the matrix, report the exact gap and reconsider a supported runtime/API option. Do not silently relax native metadata coherence or ship Chrome-compatible mode based only on HTTP header replacement.

## Smallest identity acceptance fixture

Use two owned trustworthy HTTPS origins and a native baseline. Each logs its first request UA/low-entropy hints, then sends Accept-CH and records subsequent high-entropy headers. Actual Pages/workers report legacy JS UA/platform and supported UAData fields. Compare first request, negotiated request and JS metadata for clean/persistent contexts, initial Page, reload, same/cross-origin navigation, popup first request, OOPIF, dedicated/nested/shared workers, service-worker install/restart/detached fetch and persistent reopen.

Negative controls: ordinary UA-only context override, launch-only override, metadata application after target resume, omitted worker installation and protocol rejection. Deliberately hold the metadata acknowledgment; no first external request may reach a fixture until acknowledged. That control tests a real ordering failure rather than comparing an intentionally wrong expected value. The unpatched identity path must fail the native-high-entropy comparison when it actually differs. Native mode needs its own unchanged-baseline positive.

Sample fields that the browser does not support are unavailable, not invented. A target failure must close/refuse that target and invalidate its pending actions; it cannot expose an uninitialized fallback tab. Subject counts reflect observed requests/targets, not a requested test matrix count.

## Review outcome and next step

At the original source-only checkpoint, protocol switches/proxy checks were source-confirmed candidates and runtime observations remained unverified. The experiment below subsequently observes sandbox-enabled launch and bounded Page/popup identity behavior; native WebRTC/WebTransport/QUIC destination policy remains **unobserved**. The preferred next slice is a separately owned metadata-option feasibility patch plus the smallest exact-runtime fixtures, with independent compliance and quality review. No readiness or approval claim follows from this note.

## Private metadata experiment outcome

The bounded [runtime-policy experiment](../../scripts/browser-control-prototype/runtime-policy/README.md) concretizes five exact distributed-runtime replacements against pinned Playwright1.63.0 and actual Chromium153.0.8010.12, with exact before/after/executable hashes, native sandbox enabled, two fake HTTPS origins and fixture-only exact SPKI trust. The installed dependency, manifests and frozen prototype remain unchanged.

Initial Pages/popups passed native/normalized first HTTP UA/low hints, negotiated high-entropy headers and JS metadata comparisons. The ordinary UA-only negative mismatched native metadata; malformed explicit metadata was refused before a request. Holding installation before the CDP command blocked the popup's first request until acknowledgment. Removing the await allowed an actual stale HeadlessChrome request during that hold: the ordering mutant failed.

**Full candidate rejected:** dedicated-worker identity inherited correctly in this one fixture, but shared-worker JS retained HeadlessChrome despite a Chrome first script request. Service-worker first script request and JS identity retained HeadlessChrome. Native metadata remained intact; a late override cannot repair an already stale script request. The final retained failure observes thirteen targets and six distinct owned PID/birth identities, all gone. The first introspection acquisition failure and ordering-mutant failure remain separately retained in the experiment notes.

OOPIF, nested workers, persistent/restarted contexts and worker update/restart/detached operation remain unverified. The smallest next supported candidate is an unchanged native-mode full-target proof, explicitly disclosed rather than a silent fallback. Chrome-compatible mode still needs a pre-script-request context-wide policy seam; no complete pinned API has been established. Any future attachment work must preserve Playwright's single existing target owner. This result does not approve a private CDP bridge or production identity activation.
