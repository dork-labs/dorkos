# Computer panel resources — tasks

Canonical task list: `03-tasks.json`. Three sequential tasks; no parallel execution.

Critical path: `1.1 → 2.1 → 3.1`.

## Phase 1: Computer viewer and PiP

### Task 1.1: [computer-panel-resources] [P1] Share the computer viewer across panel and PiP

Size: large. Priority: high. Dependencies: None. Parallel with: None.

Implement the agent-bound Computer view and pinned computer PiP using the existing React, transport, FloatingPanel and PiP architecture. The local computer is relevant only when its confirmed cwd matches the selected agent/workspace. Extend the serializable PiP resource descriptor with local computer ID, generation, cwd and agent path. Resolve PiP from that descriptor, never ambient chat identity. Support desktop PiP and the existing phone sheet/mini-bar. When PiP owns the computer view, the panel offers Bring back; returning requests the original agent's Computer view without creating a session or guest. Moving or closing a view must never call computer Stop, reset a guest or stop its task.

Create a transport-scoped external viewer session owned by the computer entity. All presenters for the same transport/computer generation subscribe to one capture loop and shared framebuffer, lease and ordered input queue. Preserve the current 500 ms capture cadence; do not add streaming or server API changes. Observation sends no input and never acquires control automatically. Only the presenter that explicitly acquired Take over may enqueue input. Release must synchronously clear local ownership before its network request. Unmount, transfer, window blur, visibility loss and phone minimization release control. A late acquisition response after closure or transfer must return the acquired lease. Disconnect clears stale frames; generation mismatch fences old captures and input. Invalidate queued input when ownership/generation changes, and prevent a second presenter from using the first presenter's lease. Use existing authoritative server lease fencing.

Acceptance: an agent with a matching confirmed computer cwd can open Computer and observe; an unrelated agent cannot acquire that resource by switching chats. Pop out preserves resource identity while the user switches chats. Bring back selects the original agent's computer view. Closing panel/PiP leaves the guest and task running. Stopped or unavailable states describe reality and allow reconnect observation without starting a guest; pinned PiP requires reconnect after a generation change. Duplicate subscribers produce one capture loop, and observation/control transfer preserves exclusive input ownership.

Test scenarios: mount two subscribers for one transport/computer/generation and assert one frame request schedule; distinguish another transport or computer generation. Assert no acquire/input call on observation. Acquire explicitly from presenter A, reject presenter B input, release locally before a delayed network reply, and invalidate queued input on transfer. Resolve acquisition after A unmounts and assert lease release. Resolve stale captures after disconnect or generation change and assert no stale image or input. Exercise panel-to-PiP-to-panel transfer, chat switching, phone minimization and PiP close with mocked transport; assert no lifecycle Stop/Start/reset calls. Preserve the personal guest, active takeover and user data; perform no inference or personal app restart.

## Phase 2: Relevant concrete resource tabs

### Task 2.1: [computer-panel-resources] [P1] Replace crowded category rows with relevant concrete tabs

Size: large. Priority: high. Dependencies: 1.1. Parallel with: None.

Refine the right panel into one header row of relevant views and concrete resources with a reachable + menu, using existing route, transport capability, mini-app placement, layout, Radix tabs and menu contracts. Apply existing route/capability/placement predicates before deriving any tabs or menu entries. Profile, Files, Room and the agent-bound Computer are contextual defaults; Pulse is fallback only when no contextual default exists. Optional categories are added explicitly or through existing open commands. Preserve existing open-command activation and standalone previews.

Add a bounded, versioned local view-preference schema recording opened categories and closed views per agent/room. Keep preferences client-local, free of credentials, and cap retained contexts and IDs. Closing a view is reversible through +. Concrete document/page IDs remain shared canvas-store server IDs and terminal IDs remain PTY IDs, scoped to session/room. Derive concrete document tabs from shared canvas stores and terminal tabs from the mounted terminal owner's ephemeral projection. Retain the terminal owner mounted but hidden after first use within its current session/cwd scope; hidden instances cannot focus or send input, and context changes detach retained shells. Suppress Canvas/Browser instance rows only under a shared panel-chrome context; keep their rows in standalone previews. Distinguish local Close view from the separately named destructive Stop terminal action. Never use view close to stop a PTY or guest.

The + menu lists every eligible view/resource, including tabs outside the visible overflow region, and offers New terminal. Keep + outside the scrolling tab strip so it remains reachable at narrow widths. Use roving keyboard navigation and Delete to close eligible views. Preserve the existing phone full-width panel and sheet/mini-bar behavior. Maintain accessible tab/menu names, selected state, focus restoration and keyboard access to overflow resources.

Acceptance: irrelevant always-visible categories no longer crowd a new agent panel; contextual defaults appear and Pulse appears only for a context without defaults. Browser, document/page and terminal instances occupy one shared header row; standalone previews still display their own chrome. Every eligible view can be opened or restored through +. Closing then restoring a concrete tab keeps its resource ID. Closed/open preferences persist within the correct agent/room and do not leak across contexts. Opening a resource through an existing command makes its tab visible and active. New terminal creates one terminal through the normal owner; closing its view retains it, while Stop terminal remains explicit. The row and + menu work on desktop, tablet and phone widths.

Test scenarios: verify the existing predicates suppress unsupported routes/capabilities/placements; test defaults and fallback with matching and nonmatching computer cwd. Close/reopen views, reload valid versioned preferences, handle malformed/old preferences safely and bound retained entries. Switch agent, room, session and cwd and assert preference isolation and correct terminal detachment. Add and activate concrete canvas/PTY IDs; close a view and assert no backend deletion or stop call. Render shared chrome versus standalone previews and count header rows. Exercise tab arrows, Delete, menu keyboard selection, narrow overflow and focus restoration; ensure hidden terminals cannot receive focus/input.
