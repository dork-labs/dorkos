DorkOS sends us no usage data unless you turn it on. If you choose to help, you can share a little anonymous data so we can see roughly how many people run it. It is anonymous, not personal: no prompts, no code, no file paths, no chat content, ever. This page shows the exact data, word for word, and how to switch it on or off.

<Callout type="info">
  The three anonymous channels (a daily heartbeat, marketplace install counts, and a few named
  feature-usage events) are off until you turn them on. DorkOS prints a first-run notice explaining
  what it could share. Crash reporting is separate and also stays off until you turn it on. You can
  change any of this anytime.
</Callout>

## The short version

- Three anonymous channels are available, all off by default: a daily heartbeat, marketplace install counts, and a few named feature-usage events.
- On first run, DorkOS shows a notice explaining them. If you do nothing, no usage data is ever sent.
- It is anonymous. No prompts, no code, no file paths, no chat content, ever.
- Turn it on any time in the Privacy & Data settings tab, or with `dorkos telemetry enable --channel <name>` one channel at a time, and back off the same way. A bare `dorkos telemetry enable` turns on every channel it knows, crash reports included. `DO_NOT_TRACK=1` keeps every channel off no matter what the settings say. A few other requests are not telemetry and keep going; [the list is below](#what-the-kill-switches-do-not-stop).
- The full payload is documented here and enforced in code and tests.
- The public version of this page lives at [dorkos.ai/telemetry](https://dorkos.ai/telemetry).

## What the heartbeat sends

DorkOS sends one small message to dorkos.ai about once a day. This is how we can even roughly count how many people actively run DorkOS. Here is the whole payload:

```json
{
  "instanceId": "a1b2c3d4-e5f6-...",
  "dorkosVersion": "0.47.0",
  "os": "darwin-arm64",
  "runtimesConfigured": ["claude-code", "codex"],
  "tunnelEnabled": false,
  "cloudLinked": false,
  "counts": { "agents": 4, "tasks": 2, "relayAdapters": 1 }
}
```

| Field                | What it is                                                                                                                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `instanceId`         | A random id created once on your computer and kept. Every channel and feedback use the same one, so we do not double-count you. It is not tied to your name or account unless you link analytics to your account (below). |
| `dorkosVersion`      | Which version of DorkOS you are running.                                                                                                                                                                                  |
| `os`                 | Your platform and chip type, like `darwin-arm64`. Not your hostname.                                                                                                                                                      |
| `runtimesConfigured` | Which agent runtimes you have turned on, like Claude Code or Codex.                                                                                                                                                       |
| `tunnelEnabled`      | Whether you use the tunnel to reach DorkOS from your phone. True or false only.                                                                                                                                           |
| `cloudLinked`        | Whether this install is linked to a DorkOS account. True or false only.                                                                                                                                                   |
| `counts`             | Rough totals of your agents, tasks, and chat apps and other bridges. Just numbers, never their names or contents.                                                                                                         |

## What it never sends

The list above is the complete payload. It is enforced in code and in tests, so nothing sneaks in. It never includes your prompts, your code, file paths, your hostname or username, IP address, or anything from your chats. This is what makes it anonymous rather than personal. If we ever want to add a field, we update this page first.

## We tell you before any usage data sends

The first time DorkOS starts, it prints a plain notice in its log: what it could share, a link to the payload, and how to turn it on. No usage data is sent on that run, or on any run, until you say yes. On top of that, the code holds the three anonymous channels shut until the notice has actually been shown, so even switching one on cannot send before you have seen what it covers. Crash reports and AI run summaries are separate choices: each sends only after you turn it on.

## Marketplace installs

The marketplace install-count channel is off by default too. Turning it on helps rank packages and spot broken installs. It sends no account, hostname, username, file path or link, only the package name, its marketplace and how the install went; the [marketplace privacy page](https://dorkos.ai/marketplace/privacy) lists every field.

## Feature-usage events

DorkOS can send a short list of named, anonymous events so we can see which features actually get used and where people drop off. These are curated events, not a firehose: DorkOS never auto-captures your clicks or screens. Every event is defined in one place in the source (the shared event registry) and validated against a strict allowlist, so an event can only ever carry the exact fields listed below.

Four events ship today:

| Event                 | When it fires                                             | What it carries                                                                                                                    |
| --------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `app_started`         | Once when the DorkOS server starts.                       | `os` (your platform and chip type, like `darwin-arm64`) and `runtimesConfigured` (a count of how many agent runtimes you have on). |
| `session_created`     | Once when a new chat with an agent is first run.          | `runtime` (which runtime owns the chat, like `claude-code`). Never the folder, the prompt, or the chat ID.                         |
| `first_run_completed` | Once per install, the first time it can after setup ends. | The install tag, if your install command carried one (see below): `installRef`, `utmSource`, `utmCampaign`. Otherwise nothing.     |
| `instance_active`     | At most once a day while DorkOS runs.                     | Nothing beyond the envelope.                                                                                                       |

Each event is wrapped in the same anonymous envelope as everything else: your random `instanceId`, a timestamp, and your DorkOS version. Like the heartbeat, it never includes your prompts, your code, file paths, your hostname or username, or anything from your chats.

Each usage event also asks our analytics tool (PostHog) not to build a profile from it. The one exception: you linked this install to a DorkOS account and chose to link your usage data to it (below).

Like the heartbeat and install counts, this channel is off until you turn it on. Two things still hold once you do: nothing sends until after DorkOS has shown you the first-run notice, and you can turn it back off three ways, the same as every other channel:

- Flip `telemetry.usage` to `false` in `~/.dork/config.json` (or use the **Privacy & Data** tab, or `dorkos telemetry disable --channel usage`).
- Set `DO_NOT_TRACK=1` or `DORKOS_TELEMETRY_DISABLED=1` to silence this and every other channel at once.
- Preview it first with `DORKOS_TELEMETRY_DEBUG=1`, which prints the exact events to your terminal instead of sending them.

If you already answered the first-run consent prompt on an older version, an upgrade leaves this channel off for you: an explicit choice is never widened without asking again.

### The install tag

When someone who allows analytics cookies on dorkos.ai copies the one-line installer or the `npx` command, the copied command ends with a short tag, like `--ref=k3j4mnb8x2qa.hn.launch`. The first part is a random code made for that one copy. The rest is the campaign tag of the link they arrived from, if it had one. It lets us count which copies led to an install that someone actually set up.

- DorkOS saves the tag once, in `~/.dork/install-ref.json`, and never replaces it. Saving it sends nothing.
- It leaves your computer only inside `first_run_completed`, and only when this channel is on.
- It names one copy of a command, not a person or a computer. We match it against the same tag on the website's copy event to count which copies led to an install.
- Matching the tag ties one copy to one install. Nothing merges this install with a website visitor or an account. (Linking analytics to your account, below, is a separate choice.)
- The desktop downloads and `npm install -g dorkos` never carry a tag: neither has a way to pass one into DorkOS.
- Don't want it kept at all? Delete `~/.dork/install-ref.json`, or remove the `--ref=…` part before you run the command.

## Feedback (only when you press Send)

DorkOS has a **Send feedback** button in the help menu, and there is a feedback form on the website too. This is not telemetry. It is a message you write and choose to send: general feedback, a bug, or an idea. Because you are deliberately sending it, it does not follow the anonymous-telemetry rules above.

- It is sent **only when you press Send**. Nothing about feedback goes out on its own.
- It carries exactly what you chose to send: your message, your email if you gave one so we can tell you when it's fixed, and any picture you attached. If you pointed at part of the app, it names that part too. Under **Also send**, you can add diagnostics or the recent messages of the chat or room you are in. It also notes which screen you were on and your DorkOS version, so we have context.
- It includes this install's random `instanceId`, the same id the channels above use. That is how **Your reports** in the help menu finds the reports you sent.
- It ignores the telemetry switches. `DO_NOT_TRACK`, `DORKOS_TELEMETRY_DISABLED`, and the Privacy & Data toggles turn off tracking, not the Send button. If you press Send, your message reaches us, because that is what you asked for. If you never press it, nothing is sent.

Prefer a public thread? At the bottom of the feedback form, **Open one instead** opens a prefilled GitHub issue you review and edit before submitting.

## Error reporting (a separate opt-in)

DorkOS can also send a crash report when something breaks, so we can fix it without asking you for your log files. It is off until you turn it on:

- It goes to dorkos.ai, which passes it to PostHog Error Tracking, the service we use to group and read crash reports. There is nothing to set up.
- It sends the error type and a cleaned-up stack trace (which function, file, and line) and nothing else. It does **not** send the error message text, because a message can contain anything your code put in it. No prompts, no code, no file paths, no chat data.

Before anything leaves your machine, home directories and full file paths are stripped so no username can leak, and anything shaped like a key, token, or password is redacted. To turn it on, use the **Privacy & Data** tab, run `dorkos telemetry enable --channel errors`, or set `telemetry.errorReporting: true` in your config. All three change the same setting. Leave it off (the default) and nothing is reported.

<Callout type="info">
  Want to see exactly what a crash report looks like before it sends? Set `DORKOS_TELEMETRY_DEBUG=1`
  and DorkOS prints the crash payload to your terminal instead of sending it.
</Callout>

## Linking analytics to your account (a separate opt-in)

When you link this install to a DorkOS account, you can also tie this install's usage data to your account. Like crash reports, this is off until you turn it on.

- It is off by default. You turn it on with a checkbox in the account-link flow, right before you link, in Settings under DorkOS account.
- It only takes effect at link time. If you link first and turn it on later, the connection happens the next time you link, not retroactively.
- The environment kill switches turn it off too: with `DO_NOT_TRACK=1` or `DORKOS_TELEMETRY_DISABLED=1` set, nothing is connected even if the checkbox is on.
- It sends one more thing: this install's random `instanceId`, with the link request. Our analytics then treats your install, your account, and your visits to dorkos.ai while signed in (if you allow analytics cookies there) as one record. The counts themselves are the same ones described above, but they are no longer anonymous to us.

Turning the checkbox off takes effect from the next event DorkOS sends: usage events ask for no profile again. It does not undo a link already made. To remove the joined record, delete your DorkOS account, which asks PostHog to erase it, or email us.

## AI run metadata (a separate opt-in)

Every time an agent finishes a turn, DorkOS knows a few plain facts about it: which model ran, how many tokens it used, how long it took, and what it cost. You can choose to share a short summary of those facts with us, so we can see how the different runtimes compare. Like crash reports, this is **off until you turn it on**.

- It goes to dorkos.ai, which passes it to PostHog, the analytics service we use. Feature-usage events take the same path. The heartbeat and install counts stay in our own database.
- Each turn sends one small summary: the model, the runtime (Claude Code, Codex, OpenCode, or DorkOS's own engine), the input and output token counts, the turn's time, and its cost.
- It carries **no** prompt, **no** code, **no** file path, and **nothing** you or the agent said. It is counts and a model name, full stop.

This is the same AI data DorkOS can already put on your own traces (see [observability](/docs/self-hosting/observability)). That side is always yours and never reaches us. This setting is the opposite direction: it, and only it, shares those counts with DorkOS, and only when you turn it on.

To turn it on, set `telemetry.aiMetadata: true` in your config (or use the **Privacy & Data** tab). To preview it first, run with `DORKOS_TELEMETRY_DEBUG=1` and DorkOS prints each summary to your terminal instead of sending it. `DO_NOT_TRACK=1` and `DORKOS_TELEMETRY_DISABLED=1` turn it off along with everything else.

## Debug tracing (a separate, local-only flag)

`dorkos --debug-trace` is a diagnostics tool, not part of the telemetry above, and it isn't covered by the opt-in dialog: it's a per-run flag you choose to add when you're troubleshooting something, most often because we asked you to when you report a bug.

When it's on, DorkOS writes a local file recording how long things took: chat turns, agent calls, relay messages, and task runs, plus counts. It never records your prompts, your code, file paths, or anything else you typed. The file is written to `~/.dork/traces/` and never leaves your machine unless you attach it to a bug report yourself; there is no network sender for it at all.

```bash
dorkos --debug-trace
```

<Callout type="info">
  You can also set it with an environment variable: `DORKOS_OTEL_DEBUG=true`. Either way, it's off
  by default and stays off unless you turn it on for that run.
</Callout>

## Turn everything off from the environment

Two environment variables force **every** channel on this page off, no matter what your config says. They beat the config, so they are the fastest way to quiet DorkOS in a shared image, a CI runner, or a locked-down machine:

- `DO_NOT_TRACK` is the universal, cross-tool convention. Set it to `1` (or `true`) and every channel stays off.
- `DORKOS_TELEMETRY_DISABLED` does the same thing but only affects DorkOS.

```bash
export DO_NOT_TRACK=1
# or
export DORKOS_TELEMETRY_DISABLED=1
```

Either one on its own is enough. When a kill switch is set, no channel sends anything even if its config flag is `true`. Either one also:

- stops the update checks, both the one the `dorkos` command runs at start and the server's, which asks when it starts, then at most once an hour while it runs (sooner after a failed check);
- is passed on to the agents: DorkOS passes `DO_NOT_TRACK=1`, `DISABLE_TELEMETRY=1`, and `DISABLE_ERROR_REPORTING=1` on to every Claude Code, Codex, and OpenCode agent it starts. What each of those programs does with them is up to that program.

On the Mac app, DorkOS reads these variables from your login shell, so setting them in your shell profile works there too. On Windows, set them as a user or system environment variable.

### What the kill switches do not stop

These requests are not telemetry. The kill switches leave them alone, so here is each one, what it sends, and how to stop it. Feedback you send by pressing Send is one of them, on purpose: the switches stop tracking, not a message you chose to send.

- **The desktop app's updater.** Asks GitHub for a newer version when the Mac or Windows app opens and every 4 hours after, only in the downloaded app. It has no switch: use the `dorkos` command instead of the desktop app.
- **A font you pick.** The default font (Inter) ships with the app. If you pick another font in settings, other than **System default**, your browser loads it from Google Fonts each time the app opens. To stop it, keep Inter or pick **System default**.
- **The linked-device check-in.** While this computer is linked to a DorkOS account, it tells DorkOS Cloud every 15 minutes that it is still online, with the computer's name, its platform, and the DorkOS version. To stop it, unlink the computer from your account.
- **Feedback.** Only what you send when you press Send (see [Feedback](#feedback-only-when-you-press-send)). To stop it, don't press Send.
- **The agents' own AI service.** Your prompts, code, and chats go to the AI service each agent uses, under that service's terms. You choose which service each agent uses.

## See and change it from the command line

`dorkos telemetry` shows and controls the same channels without opening the app:

```bash
dorkos telemetry status                     # show each channel and any env override
dorkos telemetry enable                      # turn on all channels, crash reports included
dorkos telemetry disable                     # turn off all channels
dorkos telemetry enable --channel heartbeat  # turn on just one (install | heartbeat | errors | usage)
dorkos telemetry disable --channel errors    # turn off just one
```

`status` tells you each channel's state, whether a kill switch is overriding it, and whether you have already made a choice. `enable` and `disable` write your choice to `~/.dork/config.json` so the first-run dialog never asks again.

## Preview the exact payload before it sends

Set `DORKOS_TELEMETRY_DEBUG=1` and DorkOS prints the exact JSON payloads for the heartbeat, install, and feature-usage channels to your terminal (stderr) **instead of sending them**. Nothing goes over the network in debug mode, so you can read, word for word, what would leave your machine:

```bash
DORKOS_TELEMETRY_DEBUG=1 dorkos
```

## How to turn it off (or back on)

The first time you open DorkOS, a dialog asks whether you want to share anonymous data and shows you the payload above, with a **No thanks** and a **Share anonymously** button. Nothing is sent until you pick one. To change it later, open settings (there's a **Privacy & Data** tab with a switch for each channel), use `dorkos telemetry` above, or edit `~/.dork/config.json`:

```json
{
  "telemetry": {
    "heartbeat": true,
    "install": true,
    "errorReporting": false,
    "usage": true,
    "aiMetadata": false,
    "userHasDecided": true
  }
}
```

Set a value to `true` to turn a channel on, or `false` to turn it off. Every channel defaults to `false`, and each one's flag is the only switch it needs.

<Callout type="info">
  Plenty of developer tools collect anonymous usage by default. We decided not to: no usage data
  leaves your machine unless you say so. When you do turn a channel on, we keep it genuinely
  anonymous and show you the whole payload. Your code and your chats never reach us as telemetry
  either way. They go only to the AI service your agents use, and to us only if you include them in
  feedback.
</Callout>

## When this changes

DorkOS moves fast. If what the heartbeat sends ever changes, we update this page and the public [dorkos.ai/telemetry](https://dorkos.ai/telemetry) page before the change ships. No quiet edits.
