# Sleep and wake

Agents keep working after you walk away. Your computer might not. Left alone, most computers fall asleep after a while, and a sleeping computer stops every agent on it until you come back.

So DorkOS keeps your computer awake while agents are working. When they finish, it lets go, and your computer sleeps on its normal timer.

This is on from the start. You don't need to set anything up.

## What keeps it awake

Any agent at work on this computer counts:

- a chat you started
- an agent replying in a room
- a scheduled task while it runs
- a message an agent is answering from another agent or a chat app

Background work counts too. When an agent hands a job to a background helper and says it will report back, DorkOS keeps the computer awake until that work is done, and while the agent writes its report. A helper counts for as long as it works. Other background work, such as a server left running or a timer, counts for at most 20 minutes after the reply ends.

About 3 minutes after the last one ends, DorkOS lets go. The wait covers the gap between one reply and the next, so a run of replies doesn't let the computer doze off in between.

## When it stays awake

You choose one of three modes:

- **While agents work.** The default. Awake while any agent works, as above.
- **Always.** Awake the whole time DorkOS is running, whether agents work or not.
- **Off.** DorkOS never keeps the computer awake on its own.

You can also keep it awake **for a while**: for the next two hours, say, or until 6 pm. This works in any mode, even Off, and ends on its own at the time you set. It lasts at most a day, and it keeps going if DorkOS restarts before then.

## The screen

Normally only the computer stays awake. The screen turns off on its usual timer and usually locks.

You can ask for the screen to stay on too. That applies whenever DorkOS is keeping the computer awake. On a Mac this also stops the screen from locking on its own. Windows keeps the screen on too. On Linux, DorkOS can't promise the screen, so it keeps only the computer awake there.

## On battery

Keeping a computer awake uses more battery. Two settings let DorkOS step back when that matters:

- **Only when plugged in.** On battery, DorkOS lets the computer sleep as usual.
- **Stop below a battery level.** On battery, DorkOS lets go once the charge drops below the level you pick, between 5% and 95%.

DorkOS checks the battery about once a minute while it's keeping the computer awake. When you plug back in, it picks up again on its own. If DorkOS can't read the battery, as on a desktop with none, these settings change nothing.

## How to tell

While DorkOS is keeping your computer awake for agents at work, a small cup shows in the top bar. Click it to see why, for example "Keeping awake: 2 chats running". The Control Center says the same thing.

When nothing is running, the cup goes away. For now it doesn't show when the computer is kept awake only by the Always mode or for a while.

## What it can't stop

Keeping your computer awake only stops it from falling asleep on its own. Some things still put it to sleep:

- **Closing the lid.** Most laptops sleep when you close the lid. A Mac stays awake with the lid closed only when it's plugged in, connected to an external display, and has an external keyboard, mouse or trackpad. On Windows and Linux, it depends on your lid settings.
- **A low battery.** When the battery runs low, the computer sleeps to protect itself. Nothing can stop that.
- **Choosing Sleep yourself.** If you put it to sleep, it sleeps.

Unless you asked for the screen to stay on, the screen still turns off on its usual timer, and usually locks. Only the computer stays on, so agents keep working behind the lock screen.

Keeping a computer awake uses more battery. If that matters more to you than finishing the work, turn it off, or use the battery settings above.

## Change it

Open **Settings → Tools → Sleep** and switch off **Keep this computer awake while agents work** to set the mode to Off. Switching it back on sets it to While agents work. You can also get there from the cup in the top bar.

The change takes effect at once. If agents are working when you switch it back on, DorkOS keeps the computer awake right away.

The other choices on this page don't have a place in Settings yet. Until they do, set them from the command line, then restart DorkOS:

```bash
dorkos config set keepAwake.mode always        # or: agents, off
dorkos config set keepAwake.keepDisplayAwake true
dorkos config set keepAwake.onlyOnPower true
dorkos config set keepAwake.stopBelowBatteryPercent 20   # or: null for never
```

To keep the computer awake for a while without a restart, ask the running app. Use your own port if you changed it:

```bash
curl -X POST http://localhost:4242/api/keep-awake/session \
  -H 'Content-Type: application/json' -d '{"minutes": 120}'

curl -X DELETE http://localhost:4242/api/keep-awake/session   # end it early
```

If you turned on Require login, the app only takes this from a signed-in browser. Use `dorkos config set keepAwake.manualUntil` with a time instead, such as `2026-10-14T18:00:00Z`, then restart.

DorkOS refuses agents that try to change any of these. They can still see them, so an agent can tell you how long the computer will stay awake. [Action approvals](/docs/guides/action-approvals) explains the limits of that refusal and how Require login closes them.

## Where it works

DorkOS uses the sleep tool your computer already has:

- **Mac:** the built-in `caffeinate` tool. This is the one that has been checked on real computers.
- **Linux:** `systemd-inhibit`. Best effort, not yet confirmed on real installs. On a computer you reach over SSH, the system may refuse the request.
- **Windows:** a built-in Windows setting, through PowerShell. Best effort, not yet confirmed on real installs.

If DorkOS can't keep your computer awake, the Sleep setting says why. Your agents still run as usual.

If your computer refused the request, DorkOS tries again on its own: after 30 seconds, then waiting longer each time, up to every 10 minutes. To try again right away, switch the setting off and back on. If the refusal never goes away, as on Linux reached over SSH, the retry every 10 minutes is harmless.

If the sleep tool is missing, or this system has none, the switch is greyed out.

In a container, such as Docker, there's nothing to keep awake: the computer running the container decides when it sleeps. The setting says so.

## If DorkOS stops

DorkOS ties its hold to its own process. If DorkOS quits or crashes, the hold ends with it, and your computer goes back to its normal sleep timer. It is never left awake by a DorkOS that isn't running.
