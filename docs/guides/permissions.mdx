# Permissions

Your agents can do more than chat. They can open rooms, schedule tasks, set up other agents, install packages, and change settings. Permissions decide which of those things an agent does on its own, which ones wait for your yes, and which ones it cannot do at all.

You set them once for everyone. If one agent needs to be different, you set that one agent differently.

## The three states

Every permission is in one of three states:

- **Allowed**: the agent does it without asking.
- **Ask**: the agent asks first. A request card appears, and the action runs only after you say yes.
- **Blocked**: the agent cannot do it. It does not even see the tool. It is told the area is blocked, and that it can ask you with a request if it really needs something there.

<Callout type="warn">
  Blocked stops an agent that plays by the rules; it isn't a sandbox. An agent that can run terminal
  commands or edit files on your computer can still act outside DorkOS, and that includes editing
  its own settings file. See [What permissions can't stop](#what-permissions-cant-stop).
</Callout>

## Areas

Permissions come in areas, so you decide about a kind of work rather than about every tool one at a time:

| Area                  | What it covers                                                                |
| --------------------- | ----------------------------------------------------------------------------- |
| **Rooms**             | Make rooms, add or remove people, rename them, leave them, put them away      |
| **Tasks & schedules** | Create, change, and delete scheduled tasks                                    |
| **Other agents**      | Set up, change, and remove agents, and sort the sidebar                       |
| **Messages**          | Message other agents, and message you                                         |
| **Chat connections**  | Turn Telegram and Slack connections on or off, and change where chats go      |
| **Tools & packages**  | Install or remove packages, add or change MCP servers, build extensions       |
| **DorkOS settings**   | Change your everyday settings, like notifications and the sidebar             |
| **Safety limits**     | Change reply limits, message caps, and an agent's safety boundaries           |
| **Permissions**       | Change what any agent is allowed to do                                        |
| **Reach & secrets**   | Open this computer to the internet, change login, sign-ins, keys, and folders |

Putting a room away (archiving) is not deleting: the room and everything said in it are kept, and you can bring it back from the room's settings.

Talking in a room is not part of any area. An agent in a room can always post and react there, whatever you set here, because nothing should be able to mute an agent in the middle of a conversation.

Three areas are never Allowed: **Safety limits**, **Permissions**, and **Reach & secrets**. The most they can be is Ask, and their rows show a lock.

### Single actions

Each area is made of actions, like "Delete a schedule" inside Tasks & schedules. Under a row, **Show individual actions** lists them, each with its own switch. A single action you set on its own beats its area, and shows under the row even when the list is closed, for example **"Except Open a room: Allowed"**.

A few actions always show you exactly what they would change, before and after, such as changing which model an agent runs on. Those always ask: their cards never offer **Always allow**, and they can't be set to Allowed.

An action that deletes or removes something asks even when its area is Allowed. Its line says **"Always asks unless you set it here"**: it runs without asking only if you set that one action to Allowed yourself.

### Files & commands

**Files & commands** is how often an agent stops to check with you while it edits files and runs commands in a conversation. It doesn't use Blocked, Ask, or Allowed. It uses the same three positions as the dial in a conversation:

- **Ask first**: it asks before it changes anything.
- **Act**: it gets on with the work and stops for the risky parts.
- **Full autonomy**: it edits files and runs commands on its own. It will not stop to ask you.

The first time you move something to Full autonomy, DorkOS asks you to confirm what that means, and remembers that you did. DorkOS's own risky actions, like deleting a schedule or removing an agent, still stop for you whatever this is set to. The areas above decide those.

An agent's own Files & commands setting beats everything else for that agent: its conversations, its scheduled runs, and its turns in rooms. Without one, the agent follows the setting for its runtime in **Settings → Runtimes**, if you set one, and otherwise the setting everyone has.

## Presets

A preset sets every area and Files & commands at once. You pick one when you first set up DorkOS, and you can change it any time in **Settings → Permissions** or in the Control Center (the ⚡ button in the top bar).

| Area              | Careful   | Balanced | Full power    |
| ----------------- | --------- | -------- | ------------- |
| Rooms             | Ask       | Allowed  | Allowed       |
| Tasks & schedules | Ask       | Ask      | Allowed       |
| Other agents      | Ask       | Ask      | Allowed       |
| Messages          | Allowed   | Allowed  | Allowed       |
| Chat connections  | Ask       | Ask      | Allowed       |
| Tools & packages  | Ask       | Ask      | Ask           |
| DorkOS settings   | Ask       | Ask      | Ask           |
| Safety limits     | Ask       | Ask      | Ask           |
| Permissions       | Ask       | Ask      | Ask           |
| Reach & secrets   | Blocked   | Ask      | Ask           |
| Files & commands  | Ask first | Act      | Full autonomy |

Anything you change on top of the preset counts as a change, so the picker reads, for example, **"Full power, 2 changes"**. **Reset to Full power** takes the changes away. Choosing a preset replaces those changes; agents you set differently keep their own settings unless you tick them in the question DorkOS asks.

If you have not picked yet, your agents keep working exactly as they did before permissions existed, and Settings → Permissions says so.

## The request card

When an agent does something set to **Ask**, or asks for something that is **Blocked**, a card appears. It shows in the top bar's inbox, at the top of Home, in the conversation the agent is having with you, and, when one of your rooms caused it, inside that room. It says what the agent wants to do, in DorkOS's own words, and has three answers:

- **Allow**: this one time.
- **Always allow**: this time, and from now on for this agent and this one action. It becomes that agent's own setting for that action, which you can see and reset on the agent's Permissions page.
- **Deny**: no.

After a yes, the agent carries on by itself. If it was waiting in the conversation, it continues in the same reply; if nobody was watching (a scheduled run, say), DorkOS tells it your answer and it picks up from there.

Safety limits, permissions, and reach and secrets never offer **Always allow**. Their cards show Allow and Deny, and one line: "Always allow isn't offered here. Changing this needs your yes every time."

If you keep saying **Allow** to the same thing, the card offers to remember it. After you allow the same action for the same agent three times in a week, the next card for it shows **Always allow** a little more clearly, with one line: "You've allowed this 3 times this week." It stays highlighted until you answer **Always allow** or tap **Not now**, which turns it off for that agent and that action. **Not now** shows in the history, and its **Undo** turns the suggestion back on. Allow stays the first answer, and the card never offers this where Always allow isn't offered at all.

When an agent asks for something that is Blocked, the card says so and quotes the reason the agent gave. An agent can only ask about one thing per area at a time, cannot ask for the same thing again for a day after you say no, and can ask at most five times an hour. [Action Approvals](/docs/guides/action-approvals#when-something-is-blocked) has the details.

## Change what everyone may do

1. Open **Settings → Permissions**.
2. Find the area and pick **Blocked**, **Ask**, or **Allowed**. For Files & commands, pick **Ask first**, **Act**, or **Full autonomy**.

Before you change anything, each row says how many agents it reaches, for example **"affects 33 agents"**: every agent that follows that setting instead of having its own. The preset, each single action, and Files & commands say the same, and the count is the same one the question below and the `dorkos` command use.

If some agents are set differently, DorkOS asks before it changes anything. Nothing is checked for you: tick the agents you want to follow the new setting, then choose **Update selected**, or choose **Keep their settings** to leave them as they are.

A **"2 agents differ"** link under a row lists who is set differently. Each has its own **Reset**, which puts that agent back on the setting everyone else has. The Control Center lists every agent set differently too, each with a one-tap **Reset**.

## Why is it set this way?

Next to every state there is a **Why?** link. Click or tap it to see where the state comes from, for example **"Allowed, from the default (Full power)."**, and who last changed it, when, and where: **"Changed by someone on this computer on Sep 23 from a request card."** A locked area says it can never be Allowed. An action that deletes or removes something says it always asks unless you set it on its own. On a phone, the answer opens from the bottom of the screen.

The Control Center's list of agents set differently has the same link on each row, and the **"2 agents differ"** list shows who set each one and when.

## Set one agent differently

1. Open the agent's profile.
2. Choose **Permissions**.
3. Pick a state for the area, or a position for Files & commands.

A row that says **"Same as everyone (Allowed)"** follows your default. Once you change it, the row shows a dot and a **Reset to default** button.

An action you answered **Always allow** for shows under its area, for example **"Except Open a room: Allowed"**, with its own **Reset**.

If the agent runs on a program that cannot use DorkOS tools, the page says so: those settings do not change anything for it.

## From a terminal

The `dorkos` command changes the same settings, through the same checks, and the history records them the same way:

```bash
dorkos permissions                              # the preset, every area, and who differs
dorkos permissions set --preset balanced        # choose a preset
dorkos permissions set tasks ask                # one area, for everyone
dorkos permissions set tasks_delete blocked     # one action, for everyone
dorkos permissions reset tasks                  # back to the preset
dorkos permissions history --agent dorkbot      # recent changes, each with its id
dorkos permissions undo <id>                    # undo one of them

dorkos agent permissions dorkbot                # what one agent may do, and why
dorkos agent permissions dorkbot set rooms ask  # give it its own setting
dorkos agent permissions dorkbot set files ask  # its own Files & commands
dorkos agent permissions dorkbot reset files    # back to the setting everyone has
```

Choosing Full power or Full autonomy from a terminal needs the same confirmation as in the app. If you haven't given it yet, the command tells you to run `dorkos config acknowledge-autonomy`, which shows you what it means and asks.

## Who can change them

In DorkOS, only a person can. The permission pages, the `dorkos permissions` command, and your answer on a request card are the ways in. An agent can ask you to change a permission, or one of the settings only you may change, like turning on remote access. That always raises a card, and it never offers **Always allow**: the change happens only after you say yes, every time. An agent can ask you; it cannot answer for you.

## What permissions can't stop

An agent's own settings are kept in a file in its folder (`.dork/agent.json`). Anything that can edit files on your computer can edit that file, and that includes an agent that has file tools. DorkOS can't prevent that, and turning on login doesn't prevent it either, because login guards DorkOS, not your files.

A new agent is different. When DorkOS first adds an agent from a folder, whether you add it, an agent adds it, or DorkOS finds it on its own, the permissions already written in that folder's settings file were never your choice. So DorkOS keeps only the ones that are stricter than your defaults, drops the rest so the agent follows your defaults, and says so in the history. If DorkOS can't write the file back, it still ignores the dropped ones, and the history says it couldn't apply the file. You can give the agent more afterwards, in DorkOS.

For an agent DorkOS already knows, what it does is notice. The next time it checks that agent's permissions, it records the change in the history as **"Changed outside DorkOS"**, with what it was before and what it is now. The change takes effect, because you may have edited the file yourself on purpose. The agent's Permissions page marks the row too, so you can see it and set it back.

If an agent should never be able to do something, don't rely on its settings alone: give it no way to edit files in its own folder, or keep a close eye on the history.

## The history

Every change DorkOS makes or notices is recorded, and the history is kept for good rather than for 30 days. So is every answer you give on a request card. Settings → Permissions shows all of them; an agent's Permissions page shows the ones that touched it. Each line says what changed, who changed it, and when.

### Undo

Every change in the history has an **Undo**. It puts things back the way they were before that change, and it is recorded as a change of its own, so you can undo an Undo too. A line you undid says **Undone**; if you later undo that Undo, the line is in effect again and offers its Undo again. If something is already back the way it was, Undo says so and changes nothing.

- **If something changed since**, Undo asks before it overwrites it, with the value it would put back: "This has changed since. Set it back to Ask anyway?" Choose **Set it back** to go ahead, or **Cancel** to leave it.
- **A change that reached several agents** at once (a new default, with the agents you chose to bring along) puts back everything that still matches and tells you what it left alone: "Undid 3 changes. 1 had changed since and was left alone."
- **Undoing a preset switch** puts back the old preset, the changes you had on top of it, and its Files & commands position, together.
- **Undo never makes a locked area Allowed**, or anything that always asks. If putting something back would do that, Undo leaves it alone and says so.
- **The line saying DorkOS didn't apply a new agent's own settings has no Undo.** Those settings were never chosen in DorkOS; set any you want on the agent's page.
- Undo that would put Files & commands back on **Full autonomy** asks you to confirm what that means first, like every other way to choose it.

An answer on a request card has no Undo, because the action already happened. An **Always allow** answer also records the setting it created, and that line does have an Undo.

With login off, DorkOS cannot tell you apart from any other program running on your computer, so it records a change as made by **"Someone on this computer"** and says why. With login on, it names your account. Changes made when DorkOS upgraded itself are labelled **"Upgrade"**, and edits to an agent's settings file are labelled **"Changed outside DorkOS"**.

## After an upgrade

If you already told DorkOS to run at full power, your agents get the Full power preset. If you chose to keep being asked, they get Careful. The history records each of these as an upgrade.

Careful now covers more than rooms. On a Careful install, agents ask before they touch tasks and schedules, other agents, chat connections, or rooms, where before some of those ran without asking.

Two older settings are gone, and what they said carries over:

- **The per-agent limit** ("observe", "act"): an agent limited to observe now has every area Blocked. It can still post and react in conversations.
- **The Agent context switches** for tasks, messages, other agents, and chat connections in Settings: a switch you had turned off becomes that area Blocked for everyone.

An agent you had switched **Manage rooms** on for keeps rooms; one you had switched it off for has Rooms blocked.

Standing permissions (the old "stop asking about this for 8 hours" answer) are gone; **Always allow** replaces them. Any that were still running when you upgraded were ended, not made permanent, and the history has a line for each.
