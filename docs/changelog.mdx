## [0.134.1] - 2026-11-08

> DorkOS 0.134.1 gets Codex chats starting again for people signed in to Codex with ChatGPT, and shows your mini apps as soon as you sign in.

### Note for people upgrading

- On Linux, Codex at Full access doesn't start if Claude Code has run on the same machine, and that includes the Docker image. Use Ask first or Workspace write there for now. We're fixing it (DOR-3965).

### Fixed

- Codex chats start again for people signed in to Codex with ChatGPT. They broke in 0.133.0: each message failed, usually with an error about "failed to load workspace requirements".
- Your apps and extension Settings show after you sign in, without reloading. With login on, your mini apps appear in the sidebar's Add-ons section, and their tabs appear in Settings, as soon as you sign in. Before, they stayed missing until you reloaded the window.
- When your mini apps can't be loaded, the sidebar and Settings → Extensions now say "Couldn’t load apps." with a **Try again** button. Before, it looked as if you had none installed.

### Going back

This release doesn't change the database. To go back, install 0.134.0.

## [0.134.0] - 2026-11-08

> DorkOS 0.134.0 gets Codex chats starting again on Linux computers that also use Claude Code, and keeps the signed-in browser DorkOS gives an agent signed out of DorkOS itself. Blocked and Ask on agents' to-dos now apply, and Connections gets an MCP servers tab.

### Note for people upgrading

- On Linux, Codex at Full access doesn't start if Claude Code has run on the same machine, and that includes the Docker image. Use Ask first or Workspace write there for now. We're fixing it (DOR-3965).
- Agents' to-do tools now follow a new **To-dos** permission. It starts as Allowed, so nothing changes until you set it. If a Blocked or Ask was already saved for them, for example in a settings file, it now applies. Before, it did nothing. Set it in **Settings → Permissions**, or for one agent in its profile under **Setup → Permissions**. (DOR-3936)
- This release changes the database. Read Going back below before downgrading.

### Added

- Connections now has an **MCP servers** tab. Add a server once and every agent can use it. You can keep it from some agents, turn it on or off, or remove it. Values you hide are typed by you and don't show on the page again. Agents that get the server can use them. Changes reach new chats, and open ones may keep a server until they stop. A server reached over SSE doesn't reach Codex or OpenCode agents, and its row says so. Agents can't list or change these servers. (DOR-3213)
- In a chat or room, the **Agent browser** panel now has a **Profiles** list. **Forget sign-ins** clears every site's saved data in a profile, and **Delete profile** removes a named profile and its agents' access to it. Only you can do either, not an agent, and neither can be undone. Forgetting the Default profile's sign-ins also clears the ones saved with `dorkos browser login`. (DOR-3887)
- Groundwork for mini apps that read a connected app themselves: the database and the public DorkOS Cloud contract can now name one extension as the holder of a read-only grant. Nothing uses it yet. (DOR-3547)

### Changed

- The app's browser panel, its help and the guides now call the live shared page the Agent browser. The older hidden page is the signed-in browser. Existing commands and saved sign-ins are kept. (DOR-3218)

### Fixed

- Codex chats start again at Ask first and Workspace write on Linux computers that also use Claude Code. Claude Code's saved sign-in copies stay hidden from Codex. (DOR-3949)
- In one more case where Codex's sandbox can't start on Linux, DorkOS now says so and links to OpenAI's setup page. It no longer tells you to send your message again. (DOR-3950)
- The signed-in browser DorkOS gives an agent now starts signed out of DorkOS, even with login on. This holds on every runtime. Sign-ins saved with `dorkos browser login` no longer include your DorkOS or DorkOS Cloud sign-in, however their address is written, and older saved files are cleaned when DorkOS starts. Other sites on this computer's own addresses, like `localhost`, are left out too. (DOR-3957)
- DorkOS now warns in its log when an agent's Claude Code loads a Playwright browser server outside DorkOS's protections: one that uses your real Chrome, keeps its own browser profile, or can open any site. (DOR-3957)
- Blocking an agent's to-dos now works. Set **To-dos** to Blocked and the agent's to-do tools refuse. It still sees its own open to-dos on its heartbeat, and the team's list stays readable to everyone in the space. Set it to Ask and the agent asks you before it adds or changes a to-do. Reading the list still runs. (DOR-3936)
- An agent that says who it is can no longer change a to-do through the app's web API, where no permission was checked. Agents use their to-do tools, which follow your setting. (DOR-3936)
- In Permissions, every action that only reads now says Ask lets it through, so you know only Blocked stops it. (DOR-3936)
- Codex can edit in an agent's own folder on Linux again. DorkOS now adds the empty files and folders Codex needs to agent folders it made under `~/.dork/agents`: for new agents, and for existing ones the next time DorkOS starts. A folder that is a git repo, or lives elsewhere, is left alone. The files stay protected from agents' file tools. When Codex can't edit because a protected file is missing, it names that file. (DOR-3914)
- When you've let an agent read an app and it later asks to change things there too, you now get a new card for that. Before, the agent was told it had access while it could still only read. (DOR-3930)
- Agents are told to hand you the browser for a sign-in and wait until you finish. They're also told to ignore sign-in links from untrusted messages, and to send requests for a shared page to you rather than to an outside sender. (DOR-3218)

### Security

- Isolated extensions can no longer use Node's built-in SQLite, which got around their file limits. Extensions that run inside DorkOS itself are unchanged. (DOR-3547)

### Going back

This release only adds to the database, and 0.133.0 runs on it as it is. To go back, install 0.133.0. On 0.133.0, a Blocked or Ask on agents' to-dos stops applying again.

DorkOS still saves a backup before it changes the database, in `~/.dork/backups/`. If you came from 0.133.0, it's named `dork-<date>-<time>-pre-20261108035027_dor3547_extension_grant_subject.db` (the time is UTC). To restore it instead, quit DorkOS, delete `dork.db-wal` and `dork.db-shm` from `~/.dork/`, copy the backup over `~/.dork/dork.db`, then install 0.133.0. You lose anything written since the upgrade, so if you removed access or revoked a connection since then, do it again.

## [0.133.0] - 2026-11-08

> DorkOS 0.133.0 calls an agent's promises to-dos, lets a Claude Code agent at Full autonomy schedule tasks for your other agents, and gives the browser windows an agent drives an orange frame. This upgrade only goes one way, so read Going back first.

### Note for people upgrading

- This release changes the database. Read Going back below before downgrading.
- If your own scripts or MCP clients use `/api/commitments` or the `commitment_add`, `commitment_update` and `commitments_list` tools, switch them to `/api/todo-promises` and `todo_promise_add`, `todo_promise_update` and `todo_promises_list`. The old names stop working. (DOR-3933)
- The browser changes for the Mac app's right panel haven't been checked on an installed Mac app yet.

### Added

- When DorkOS opens a separate browser window for an agent, that window now has an orange frame, so you can tell it apart at a glance. The sign-in window a card opens for you keeps your normal colours. If an agent's window opens without its orange frame, DorkOS closes it rather than handing it to your agent. Agents also can't read or act while a page in that window is full screen. (DOR-3218)
- In the Mac app, a card in the browser panel now offers **Sign in**. It opens the plain sign-in window, so you sign in outside the panel, and your agent continues in its own window. Every agent that uses the Agent browser can use that sign-in. (DOR-3218)
- After later DorkOS updates, an agent's next chat or room turn starts with a short note on new features it can use. Its permissions don't change. Nothing shows yet: this release only records each agent's starting version. (DOR-3161)
- An agent whose chat runs at Full autonomy can now schedule and change tasks for your other agents, not only for itself. This works in Claude Code chats. Other runtimes can't do it yet. The task never runs above the other agent's own level, and Activity says who made it and for whom. A chat that DorkOS marked as reached by someone outside your team, such as a guest on your Wi-Fi, can't do it, and neither can an agent whose Tasks permission is Blocked. If a scheduled run changes another agent's task, the change waits for you. (DOR-3938)

### Changed

- An agent's promises are now called to-dos. The **Commitments** page on an agent's profile is now **To-dos**, and so is the section on the Team page. Every promise is kept, and settings saved for these actions move to their new names. Blocked on agents' to-do actions doesn't stop them yet; that's being fixed next (DOR-3936). (DOR-3933)

### Fixed

- Pressing **Disconnect** while an agent is waiting on you in the browser now ends its task, so the card no longer stays up over a closed window. While a card is open, the browser panel's address bar and tab list won't change the page until you answer it. (DOR-3805)
- If the agent's browser window closes while it's waiting on you, the card now says so, with **Open window** and **Stop task**. (DOR-3874)
- While an agent is waiting on you in the browser, the browser panel in any other chat points you to that chat, and can't resume the agent or close its window. Opening the browser for another chat is refused until you answer the card. (DOR-3875, DOR-3218)
- A schedule file with `permissions` in the wrong place now waits and tells you to move it under `schedule`. Its misplaced value never grants a mode, and agents can't run it. You can run it once by hand, at Accept edits. (DOR-3840)
- Before you approve a package's hooks, the review shows each whole command as written, with line breaks and hidden characters clearly marked, plus file fingerprints.
- The Inbox now lists packages whose hooks you declined, with **Ask again**. Your earlier decline stays in place until you answer the new review. A request DorkOS couldn't read no longer turns into a lasting refusal.

### Security

- Agents' file tools now stay away from private files and DorkOS settings on Codex, OpenCode and the DorkOS runtime, as they already did on Claude Code. On Codex this holds at Full access too. Below Full autonomy, an agent's MCP servers that changed outside DorkOS stay off until you approve them. (DOR-3595)
- If you set Codex to the older `exec` way, it now runs like other Codex chats and shows approval cards. If that can't start, the reply stops with an error. (DOR-3595)
- Codex says when Linux blocks its sandbox and links to the setup steps. When a file sits where Codex needs a folder, it names the file and says to rename it and retry. (DOR-3595)
- On Linux, Codex refuses to start if it can't read a folder in your home folder. Change that folder's permissions, or move it out of your home folder. A folder that disappears during a scan can also stop a command; run it again. (DOR-3595)
- On Linux, Codex may refuse to edit when some protected files are missing, which often happens when your home folder is the project. Choose **Ask first**, or use a folder inside your home. A home reached through a symbolic link may also be refused. (DOR-3595)
- Codex may not start in the standard Docker image. (DOR-3595)
- Once DorkOS has an owner account, adding or changing an MCP server for every agent, or letting more agents use one, asks you to **Confirm it's you** with your password. The confirm says what will run and never shows a secret, and nothing is saved until you confirm. The list of servers for every agent now hides what looks like a secret in arguments and addresses, and shows settings by name only. (DOR-3802)
- If you use sign-in, signing out now clears the sidebar's saved copy (agents, rooms, pins, recent chats and your settings) from every open DorkOS tab in that browser, including the automatic sign-out on a shared computer. Reloading another tab can't bring it back. (DOR-3902)
- If you tick **This is a shared or public computer** when you sign in, DorkOS clears any saved sidebar copy and keeps new sidebar data only until you close the page. (DOR-3905)

### Going back

This upgrade only goes one way. DorkOS saves a backup first, in `~/.dork/backups/`. If you came from 0.132.0, it's named `dork-<date>-<time>-pre-20261104081935_hook_decline_review.db` (the time is UTC).

To go back to 0.132.0, always restore that backup. Quit DorkOS, delete `dork.db-wal` and `dork.db-shm` from `~/.dork/`, copy the backup over `~/.dork/dork.db`, then install 0.132.0. You lose anything written since the upgrade. Without the restore, to-dos stop working, a hook request DorkOS couldn't read can count as a refusal again, and tasks one agent made for another run without the safety marks they carried.

Settings saved for agents' to-do actions don't come back on 0.132.0 after the restore. They had no effect on either version (DOR-3936), so nothing changes in practice.

Going back can undo things you changed since the upgrade. If you removed access or revoked a connection, do it again.

## [0.132.0] - 2026-11-04

> DorkOS 0.132.0 fixes the desktop app failing to open a saved page. Chats with one agent now open as direct messages.

### Note for people upgrading

- This release replaces the withdrawn 0.131.0 desktop build. If you installed 0.131.0, update forward to this version.

- This release changes the database, including when upgrading from 0.131.0. Read Going back below before downgrading.

### Added

- When an agent hands you the Agent browser, the Inbox shows the same card, so you can continue or stop it with the chat closed. On your phone, a note names the site and the agent and tells you to continue on your computer.

- When a site needs a person, your agent stops and a card appears in the chat. It names the site and the agent, tells you what to do, and has Continue and Stop task. If the page asks for a password, the card opens a plain sign-in window that no agent can reach, and tells you when your sign-in is saved.

### Changed

- A chat with one agent now reads like a direct message: the agent's face and name, its replies, and a message box like a channel's. Every way to reach an agent opens this same chat. Upgrading turns it on once, unless you already switched it yourself. To go back, turn off **Chats with one agent read like a DM** in Settings → Advanced → Experiments.
- The model, account and context move behind **Show sessions**, in the same place. If you opened a chat other than an agent's main one in the last 30 days, Show sessions is already on for you.

- Use a newer browser engine for agent work and sign-ins (DOR-3884).

### Fixed

- Fix the desktop app failing to start when reopening a saved page after an update.

- Other websites can no longer frame API replies or fallback pages. App pages already blocked framing. PDF previews and the pages you open in the canvas keep working (DOR-3615).

- When an agent creates a schedule, its notice names the permissions it will use and explains command limits. Open the notice to review that schedule. Commands needing approval are refused on timer runs because nobody can answer. An agent creating a task without a separate mode grant gets at most Accept edits, even when the default is Full autonomy.

- Schedules now say when a command was refused in their notices and run history. The notice opens its schedule; chat messages carry only the title.

- A schedule’s permissions notice now names the message that started the change, including Telegram and Slack. This also covers bridged rooms and keeps a later turn in the app from carrying the earlier source.

- When an agent's other chat hands a post to its chat in a room, that chat can now check how it went: still waiting and why, posted, or declined with the reason. Before, it heard nothing until the room chat answered, which could take an hour or never come.

- The plain sign-in window now opens only the page you're signing in to. It no longer brings back and reloads the tabs an agent left open.

- Review a schedule’s instructions and permissions before approving it from its row. Changed schedules need a fresh review (DOR-3758).

- Read long schedule instructions in one scrolling column. Reviewing a package switch offers approval that turns it on.

- A changed schedule stays blocked until you choose Review again. Background updates cannot silently replace an open review.

- Keep review controls focused when a schedule changes. Review again returns to the heading.

- Agents now get accurate guidance about text from outside your team. They were told that reading it always made a person approve their next send, but DorkOS mainly tracks that for messages sent over your Wi-Fi by someone other than you. Agents now know to treat chat apps, mail and web pages as untrusted and to ask before they send.

- Schedules awaiting review stay off after restarting. Shape schedules also wait for review when their file is invalid (DOR-3860, DOR-3861).

- Restarting preserves where a schedule’s words came from, so outside words still need your approval.

- Block approval of package requests with shortened or hidden commands, including requests saved before a restart.

- Replace unreadable package commands with a clear explanation and a Decline button.
- Block hidden control characters in package requests while allowing line breaks in global package details.

### Security

- MCP server settings, headers and sign-in tokens no longer appear on the Claude Code command line, where other programs on your computer could list them. A local server's own settings can still be read by programs running as you, and anything typed into its arguments can be read by every account on your computer, so put secrets in its settings (DOR-3882).

### Going back

This upgrade only goes one way. DorkOS saves a backup first, in `~/.dork/backups/`.

- To return to 0.131.0 after upgrading from it, use `dork-<date>-<time>-pre-20261104060919_package_approval_request.db`.
- To return to 0.130.0, use `dork-<date>-<time>-pre-20261102213849_dor3088_todos.db`, saved before leaving 0.130.0.

Quit DorkOS. Delete `dork.db-wal` and `dork.db-shm` from `~/.dork/`. Copy the matching backup over `~/.dork/dork.db`, then install that earlier version. You lose anything written since the backup. Going back without restoring can break agent promises and package approvals.

Going back can undo things you changed since the upgrade. If you removed access or revoked a connection, do it again.

## [0.131.0] - 2026-11-03

> DorkOS 0.131.0 fixes the bar at the top that stayed in place after you left a page, lets agents set how their own scheduled tasks run, and makes messages easier to read. This upgrade only goes one way, so read Going back first.

### Going back

This upgrade only goes one way. DorkOS saves a backup first, in `~/.dork/backups/`. If you came from 0.130.0, it's named `dork-<date>-<time>-pre-20261102213849_dor3088_todos.db`.

To go back to 0.130.0, always restore that backup. Quit DorkOS, delete `dork.db-wal` and `dork.db-shm` from `~/.dork/`, copy the backup over `~/.dork/dork.db`, then install 0.130.0. You lose anything written since the upgrade. Going back without the restore looks fine until an agent's promise fails.

Going back can undo things you changed since the upgrade. If you removed access or revoked a connection, do it again.

### Fixed

- The bar at the top now changes when you leave the page you first loaded. Before, clicking through to a chat left the old page's bar in place until you reloaded.
- A chat started from another chat now reports back when it finishes, even if it ran background commands along the way. If that work is still going after 15 minutes, it says so. A report that can't get through tries again for about 40 minutes, and follows an agent that moved to another account. A restart can still lose a report that's waiting.
- DorkOS checks that a linked copy of a project (a git worktree) really belongs to an agent's project before a chat there runs as that agent, and a chat's agent stays the same once it's set.

### Added

**Agents can now set how their own scheduled tasks run, up to their own level, and you can undo it.**

- On Claude Code on Trusted, when an agent raises its own task's mode or rewrites its prompt from its own chat, the task usually keeps running. A raise, or a rewrite above Never ask, gets a notice with **Undo**. On other runtimes or on Careful, it asks you first.
- It waits for you if another agent asks. It doesn't check who messaged the chat, so someone else on Telegram or Slack, or a page the agent read, can lead it to make this change, and the change lasts after that chat ends. If other people can message your agents, turn this off. Scheduled runs and heartbeats can't raise a mode.
- To turn this off: `dorkos config set tasks.agentModeControl false`. Agents then can't change a task's mode, and if one rewrites its task's prompt, the task stops and waits for you. Modes already set stay as they are.
- If a task's SKILL instructions change outside DorkOS, the task usually keeps running at no looser than Never ask, so some steps may fail. You get a notice.

Also added:

- On Claude Code, an agent can move its own seat in a room or DM to another Claude account, from another chat, not while it's answering there. Its account must be at 80% of its usage or more. It can't pick your main account or one you keep out of automatic moves, and it can't move when its usage can't be read. The room gets a line each time.
- A correction to the 0.126.4 note: adding an MCP server for every agent is by API, because there's no page for it yet. As the owner, send `POST /api/mcp-servers` with `enabled: true`, or the server stays off.

### Changed

- An agent's text is a little heavier, messages have more space between lines outside compact density, and long paragraphs stop at a comfortable width while code and tables use the full width.
- On a phone, messages have more room, because the side margins are smaller.
- Pointing at a message in a chat no longer tints it grey. Rooms keep their tint.
- Day labels are plain centred text, times lose their leading zero on a 12-hour clock ("2:03 PM"), and there's a little less space between turns.
- Menus, pop-ups, tooltips, dialogs and phone sheets now share one look.
- Menus have even rows with no lines between groups, and they're easier to tap on a phone.
- Tooltips wait a moment before showing, so they no longer flicker as you move past buttons. They don't show on touch screens, except the reason a button is greyed out, and they're no longer a bright white chip in dark mode.
- Phone sheets stand out from a dark page, with a real grabber on sheets you can drag away, and left-aligned titles.
- On a computer, dialogs open on their first field if they have one, and never on a Delete or Close button.

### Known issues

- With login off, a promise you add to an agent through the app can limit what that agent's heartbeats may do, and nothing says why. It also can't be dropped from its row. **Mark kept** closes it and lifts the limit.
- Approving a task from its row doesn't show its mode. Use its approval card, which does. Turning on a package's schedule that shipped off doesn't show its mode either.
- A task an agent makes can start at a mode where commands that need approval get refused, with no card. It looks ready, then its runs show **Needs attention**. If you expected those commands to run, you can change its mode under **Edit**, then **Advanced settings**.
- New schedules start at Full autonomy unless you've changed your default. The mode is under Advanced, so check it before you save.
- The notice can say you started a change that someone else's Telegram or Slack message led to. If you don't recognise it, check the chat.

## [0.130.0] - 2026-11-02

> DorkOS 0.130.0 lets you choose a scheduled task's permissions when you approve it, gives agents a work queue, lets an agent hand the Agent browser to you when a page needs you, and keeps each agent to its own chats and schedules.

### Added

- Agents can now have a work queue: an ordered list of work and a number of chats to run at once. It is off until you turn it on for an agent. Once on, when one of its queued chats ends, the next item starts on its own, on the account with the most room. It waits while the disk is low, the computer is busy or the accounts are near their limits, and picks up again when that clears. You can see the list, reorder it, set a daily limit, and stop every queue at once from the agent's profile. (DOR-3462)
- When a page needs something only you can do, like a password, your agent can now pause and hand the Agent browser to you. That chat can't see or use the browser until you give it back. Press **Resume agent** in the browser panel to give it back; more controls come in a later update. (DOR-3218)
- An agent's heartbeat now notices work that went quiet. If a chat the agent started in the last 3 days has done nothing for 2 hours, or the agent has an open promise and none of its chats has run for 30 minutes, the next heartbeat wakes the agent and names each item and when it went quiet. The same stall wakes it at most twice. A paused agent, or one whose heartbeat is off, is never woken. (DOR-3674)
- While heartbeats are on, if no agent chat has run on your computer for 30 minutes and work is still open, DorkOS posts one line in your team room. It says how long nothing has run, how many chats your agents started in the last 3 days, and how many promises are open. It posts once, and again only after a chat has run in between. It wakes no agent. To use another room, set `heartbeats.idleAlertRoomId`. Only you can change it. (DOR-3675)
- Control Center has a new Team view. It shows which agents are running, which are waiting on you, and how much room this computer has left. (DOR-3461)
- Owners and admins of a space now see how many messages are flagged, on the Manage button and the Members tab, without opening the queue first. (DOR-3625)
- A space's server can now take a report of a person, for when there's no single message to report. Owners and admins can mute or ban that person, or dismiss the report. The buttons come in a later release. (DOR-3624)

### Changed

- When you approve a scheduled task, you now choose its permissions on the approval itself, including Never ask on Claude Code. A schedule an agent proposes runs once you approve it, and one you switched off stays off. For Claude Code tasks, the approval also shows the folder rules you approved. If an agent changes a task's instructions or runtime, the task waits for your approval again, even on Trusted. (DOR-3651)
- An agent now runs at the level you set, wherever a message came from: an extension, the web, a connected chat, a stranger, a room, another agent or another person in a shared space. At Full autonomy, none of these raises a card or lowers what the agent can do. The one exception is a message sent over Wi-Fi by anyone but you, which stays limited. Anyone who can message an agent gets that agent's level, including its files, notes and your profile, so check your DM policy, and set an agent below Full if outsiders can reach it. This is a preview; separate protections come later. (DOR-3440)
- Schedules that were waiting for your OK because of who wrote them are now switched off. They show as normal schedules you can turn on, and none starts by itself. Switching one off rewrites its file once, which can drop comments from the top of that file. (DOR-3440)
- At Full, an agent that tries to loosen a permission, change its off-limits list or change a setting only you can change is refused, and nobody is asked. (DOR-3440)
- An agent in a room can now set up that room's shared files itself, as its Rooms permission allows. The room and Activity show which agent did it. To stop it for one agent, set its Rooms permission to Ask or Blocked. To stop it everywhere, set `rooms.repo.enabled` to false. (DOR-3468)
- An agent can now ask to install or update a large Marketplace package, such as Flow. Before, DorkOS refused because the full list didn't fit on one approval card. Now the card lists everything that gives the package more power, shows commands in full, and opens the whole list from "See everything it runs". (DOR-3070, DOR-3356)
- An update's card shows only what changed: each item is marked New, Broader (with what it was) or Removed, and things that stay the same are counted. If the installed copy's files no longer match what was installed, every item shows as New. (DOR-3070)
- A package with more than 40 things that run code or reach the internet still isn't asked about in chat. The message now says to review it in Marketplace, instead of telling you to update fewer packages at a time when there is only one. (DOR-3356)
- A new channel now opens on its empty conversation, even if you last left the side panel on Canvas. Its `ROOM.md` is still pinned there, and the empty conversation says so, with **Open** to show it. (DOR-3477)
- Saved Agent browser sign-ins move to a new private folder the first time you open the Agent browser. There is nothing to do on your side. (DOR-3218)
- The /flow plugin can now tell when a Claude Code, Codex or OpenCode chat runs in DorkOS. Its journal records which runtime ran the work, and DorkOS as what hosted it. (DOR-2405)
- Links and code in messages are no longer orange; orange now only means something is for you. A link is the same colour as the words around it, with a quiet underline that darkens when you point at it or tab to it. Inline code sits on a faint grey tint.
- "Needs you" shows in the sidebar as a small orange diamond, not an amber dot. The dot was hard to see on the light theme and looked like the green and grey dots beside it. An agent with live chats keeps the diamond next to its "live" chip.

- An OpenCode agent on a local model (such as Ollama) no longer gets cut off when its model takes more than 2 minutes to start answering. DorkOS used to read that wait as a turn that never started and end it with "the agent didn't start within 2 minutes". It now waits until the model answers or OpenCode's own time limit ends the request. A tool that hangs is still stopped after 10 minutes. (FB-68)
- Agents in rooms now read times in your time zone. Every time in a room turn used to be UTC with nothing saying so, so an agent could call your afternoon "this evening" and had no idea what day it was for you. Now each time is in the zone set in your profile, and each turn tells the agent which zone that is and the date and time there now (DOR-3253, DOR-3125)
- An agent listing scheduled tasks now sees when each one runs next. It used to see "no next run" for every task, even ones on a schedule (DOR-3125)
- Bug reports you send from DorkOS are easier to read. The same event repeated back to back now shows once with a count, the server log excerpt no longer has empty lines, and the report names where it came from as "DorkOS app" instead of an old internal name. (FB-49)
- An agent's Schedules page opens instead of crashing when that agent has schedules or runs to show (DOR-3124)
- A message started by a schedule or a heartbeat now says where it came from, instead of looking like you sent it. It shows once the turn has finished. (DOR-3019)
- The first time an agent opens Documents, Desktop or Downloads, macOS asks; your answer applies to all agents.
- When DorkOS stops and starts again, an open chat now gets its live updates back on its own, like a room does. Before, it kept saying "Live updates lost" until you sent a message or reloaded the page.

### Known issues

- At Full autonomy, a chat an extension starts, like one from a comment on an "Only you can do these" list, can still stop and show you a card.
- At Full autonomy, an agent that tries to loosen a permission is told no only if it has read outside words. Otherwise you get a card and you decide, the same as below Full.

## [0.127.1] - 2026-10-30

> DorkOS 0.127.1 asks you to confirm it's you before things only you can do, gives each agent one voice in each room, and cuts more waits at Full autonomy.

### Changed

- Each agent now has one voice in each room. If another of its chats tries to post there, the draft goes to the agent's own chat in that room. That chat is told to read the room first, then post the draft, reword it, or say why not. Posts through DorkOS's external MCP server aren't affected.
- A message passed on this way says where it came from, like "Shared from #team-product at Dorian's request". The room or chat it came from hears whether it was shared.
- An agent that isn't in a room can't post there, and DorkOS won't add it for you. From a DorkOS chat, it's told to ask the person who runs DorkOS.
- A package installed for all projects can now mark a scheduled task as project-only. It no longer shows up as a global schedule, or asks for approval there. Each project with the file the package names gets its own copy on its Schedules page, switched off. Turn it on where you want it. If a project drops that file, a copy you once switched on stays, and a change to the package's task can still pause it.

### Fixed

- Before DorkOS reads a git repository for you, it checks the repository's own settings. If it finds anything outside a short list of ordinary settings, it skips the read. The same check runs before DorkOS makes or removes a workspace. A chat set to Full autonomy still gets its workspace made, and Activity notes it. These reads don't use the network, your saved git logins or your own git settings.
- At Full autonomy, an agent that tries to open up a setting only you may change, like remote access or which hooks may run, is now told no, and Activity gets a line. Before, it put a card in front of you and waited. Many of these can still be turned off without asking, like switching the tunnel off, which also adds a line to Activity. Below Full, the agent still asks you when you're there to answer.
- A Claude Code agent set to Full autonomy no longer waits on a Needs you ticket because of settings in its folder. They now load, and Activity says so. This doesn't count as your approval: move the agent below Full and DorkOS holds any settings you haven't approved and asks you.

### Security

- Some things only you can do in DorkOS, like approving what an agent asked for, now need you to confirm it's you. In a browser on the computer DorkOS runs on, that means entering your DorkOS password once, and it stays confirmed for about a month after you last use it, unless you sign out. The desktop app confirms you by itself, and on other devices your normal sign-in counts. Most browsing doesn't ask, and nothing changes until you have an owner account.
- The DorkOS app now ignores `NODE_OPTIONS` (a setting that loads extra code into Node) and won't start with debugging switches like `--inspect`. It also won't start if its main app file changed after it was built.

### Known issues

- At Full autonomy, a package that wants to run its own commands can still put a card in front of you, including a package DorkOS didn't install. A later release changes this.
- A chat an extension starts, like one from a comment on an "Only you can do these" list, can still show cards at Full autonomy. That ends in the next release.
- At Full autonomy, an agent that has read outside words and tries to loosen a permission is told no. Without outside words, and below Full, you get a card and you decide. In the next release it's refused at Full in every turn.

## [0.127.0] - 2026-10-30

> DorkOS 0.127.0 makes agents better teammates in a shared room, and keeps more of what agents change waiting for your OK.

### Changed

- In a channel, the first @name in a message, and any names right after it ("@ana @bo" or "@ana and @bo"), ask those agents to answer. A name later in the message is a copy: that agent takes no turn, and it sees the message the next time it reads the room. Copied names show as grey chips, and while you type the composer shows a line like "Asks @ana · cc @bo". Direct messages work as before.
- An agent no longer posts over messages it hasn't read. If another member wrote in the room since the agent last looked, its message waits and the agent sees what's new first. It can then send the message as it was, change it, or say nothing.
- In a channel, an agent waits until the room has been quiet for about 20 seconds before it answers. Several quick messages get one answer, not one per message. It never waits more than a minute from the first message. Direct messages are not delayed.
- Agents in a room are now told four working rules. Speak only when asked or when you have something new, and react instead of repeating. Read the room again before you post. Name who does what, and by when. When you approve something, say exactly which version. These are instructions to the agent, not checks the app enforces.
- Your agents can have at most 8 chats they started on their own running at once. That number is now a setting, `runtimes.maxAgentChats` (1 to 64), so a computer with room to spare can allow more: `dorkos config set runtimes.maxAgentChats 12`. When the limit is full, the message an agent gets names the setting. Only a person can change it, never an agent.
- Your own messages from Wi-Fi now run at the agent's own permission level, not a stricter default. When you're signed in as the owner over Wi-Fi, a message, room post, answer or button press counts as yours, the same as at your computer. Anyone else on Wi-Fi is still held back, as before. From Wi-Fi you still can't raise an agent's permissions or change how DorkOS is reached. While Wi-Fi access is on, an agent below Full asks you first before an action in a connected app that can't be undone, like sending an email, and the card says why. You can't say yes to it from Wi-Fi. A chat set to Full autonomy never asks: its action waits 60 seconds that anyone else can cancel, as it does with Wi-Fi off.
- If your company's network uses its own certificates, choose the certificate file in **Settings → Server → Network**, then restart. The Mac app adds that file's certificates to the ones it already trusts, and shows how many. It no longer reads `NODE_EXTRA_CA_CERTS` or `SSL_CERT_FILE` from your computer, and neither reaches your agents. Agents that run on Node get the file you chose instead.

### Fixed

- An agent set to Full autonomy keeps working after it reads something from outside your team, like a web page or an email. It can make a promise and edit agent files such as SOUL.md and HEARTBEAT.md, and in Claude Code chats it can check account usage. Each of these adds a line to Activity, and so does starting a chat. Changing permissions, rewriting NOPE.md or MEMORY.md, and showing keys DorkOS keeps for you stay blocked.
- When you lower an agent's level, for example from Full autonomy to Ask first, its open chats follow right away.
- At Full autonomy, an agent that has read outside words and then tries to loosen a permission, or change a setting only you may change, is now told no, and Activity records it. Before, you got a card.
- When you let an installed package run commands automatically, your yes now covers the script files those commands name, not just the command. The card lists each file with a short fingerprint. If one of those files changes later, DorkOS asks you again. On the Full setting it doesn't ask, as before.
- In Claude Code chats, changes an agent makes to a project's settings wait for your OK before they take effect. A change to the local settings file that isn't checked in, like new hooks or allowed commands, keeps that file from loading until you approve it. A change to the project's checked-in hooks, the scripts they run, or the hooks a subagent or skill sets keeps all of the project's own settings from loading in that worktree until you approve it. Your own settings and hooks still run. A newly added command that the checked-in settings allow without asking still asks first. If `.mcp.json` changes, only DorkOS's own MCP servers and the ones from the default branch start. When DorkOS can read the change, an approval card shows it to you, and Activity notes what changed. Approve a change once and it runs in every worktree that has it. A project DorkOS hasn't seen before waits for your yes once, and so does a default branch that changes its hooks; projects you already had are trusted as they were. Undo the change and things go back to normal on their own. A chat set to Full autonomy has none of these limits: the project's settings load as they are, no card appears, and Activity notes what would have waited.
- In Claude Code chats, an agent's file tools can't change DorkOS's settings file, where your approvals are kept, at any permission level. Below Full, they also can't change the settings, MCP servers, agent file, skills, commands or subagents of any agent in DorkOS's data folder. A chat set to Full autonomy can change those agent files, and the Activity page notes it. Agents can still edit their own instructions, and skills in a project's own folders.
- When an agent goes quiet for 10 minutes, DorkOS stops its turn. In Claude Code chats, that stop used to look like a person's: the chat showed "[Request interrupted by user]", and a tool that was running read as declined. Now the chat says "DorkOS stopped this turn after 10 minutes with no activity," and the agent's next turn is told that no person stopped it.
- A connection paused until you confirm a setting no longer says "Stopped working" on the Connections page. It says "Paused", then the connection's own name, so two paused webhooks are easy to tell apart, with a Review button. In Needs you, its Confirm button is now full width and easy to tap on a phone.
- On Linux and in Docker, a new file you open in the canvas no longer shows editing turned off just because a different file, saved earlier, used the same file number. This needs a system that records when each file was created, which most do. Edits to the same file, or to another name for it, still wait until that save is resolved.

### Security

- When a Claude account starts using a different sign-in, you get one note in your inbox and one line in Activity. Your agents keep working. Until you keep the new sign-in in Settings → Runtimes, DorkOS won't pick that account for you on its own.
- Add a Never use list in Settings → Runtimes. Put a Claude account folder or an organization on it, and DorkOS won't run Claude there, even at Full. The list starts empty, and only you can change it.
