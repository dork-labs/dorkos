# Uninstall

Remove the app and its server data separately. Keep any chat history or project files you may want later.

## Quick uninstall

Quit the desktop app and stop your DorkOS server first. Then run `dorkos cleanup` from the same environment you use to start DorkOS. It lists the server data before asking what to remove:

```bash
dorkos cleanup
```

1. **Global data** (`~/.dork/`): your configuration, database, logs, and relay state.
2. **Project data found through the database** (`.dork/` directories): agent manifests and uploads. You can keep these when removing global data.

The command finds project folders from agent records in the database. It does not search your whole disk. A missing or unreadable database can leave project folders undiscovered. If you set `DORK_HOME`, cleanup uses that directory instead of `~/.dork/`.

Once that's done, remove the CLI itself:

```bash
npm uninstall -g dorkos
```

If you installed DorkOS another way, remove that installation too. Review any project folders you kept or cleanup did not find. Runtime-owned history and desktop browser data are separate from the server data.

## Docker

If you run DorkOS in Docker, remove the container and its volume:

```bash
docker rm -f dorkos
docker volume rm dorkos-data  # if you used a named volume
```

If you followed the Docker guide, your volume is named `dorkos-data` unless you changed it.

## Obsidian plugin

The Obsidian plugin is retired. Disable **DorkOS Copilot** in **Settings > Community plugins**. Then uninstall it, or remove only its copied plugin folder or symbolic link. Keep your vault, DorkOS data folder, and agent chat history. The plugin could use data outside the vault. See the [retirement guide](/docs/guides/obsidian-plugin) for migration and source recovery.

## Desktop app

The packaged desktop app uses `~/.dork` for server data. It also keeps window and tab state, browser storage, and caches in its own operating-system application data folder. `dorkos cleanup` removes the server data you approve, not that separate desktop data.

Quit the app before removing it. On macOS, remove it from Applications; on Windows, use the app uninstaller. If you also want to remove its application data, review that folder separately after quitting. Keep any data you still need.

## Manual cleanup

Prefer to remove things by hand, or don't have the CLI installed anymore? Start with your global data:

```bash
# Remove global data
rm -rf ~/.dork
```

Then find any per-project folders. This command searches your home directory for `.dork` folders and only lists them, it deletes nothing on its own:

```bash
# Find per-project agent directories (lists matches, doesn't delete)
find ~ -name ".dork" -type d -path "*/.dork" 2>/dev/null
```

Read the list, then delete only the folders that are actually DorkOS's. `.dork` is a popular name for reasons that have nothing to do with us, so double-check before you run `rm -rf` on anything it finds.

## What DorkOS stores

These are common locations to review. Paths can differ when you change the data directory or use a different runtime.

| Location              | Contents                                                           | Owned by    |
| --------------------- | ------------------------------------------------------------------ | ----------- |
| `~/.dork/config.json` | User configuration                                                 | DorkOS      |
| `~/.dork/dork.db`     | SQLite database (agents, schedules, relay state, room messages)    | DorkOS      |
| `~/.dork/backups/`    | Automatic spare copies of that database (see the warning below)    | DorkOS      |
| `~/.dork/logs/`       | Server log files                                                   | DorkOS      |
| `~/.dork/relay/`      | Chat app state and credentials (Telegram, Slack and other bridges) | DorkOS      |
| `<project>/.dork/`    | Agent manifest, uploads                                            | DorkOS      |
| `~/.claude/`          | Claude Code chats and config                                       | Claude Code |

<Callout type="warn">
  `~/.dork/backups/` holds the only spare copies of your channels, DMs, and threads. Deleting
  `~/.dork` deletes those too. If you might want that history later, move the newest file out of
  `backups/` first. Each one is a complete database on its own.
</Callout>

<Callout type="info">
  `dorkos cleanup` leaves `~/.claude/` alone. Claude Code owns that history and configuration. Codex
  and OpenCode also keep runtime-owned data outside DorkOS's server data directory. Review those
  separately if you want to remove their history too.
</Callout>
