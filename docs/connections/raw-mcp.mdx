# Raw MCP server

Some services run their own remote tool server that speaks MCP (the standard that lets AI tools talk to each other). You can point DorkOS at one to verify the connection and keep its account in Connections.

<Callout type="warn">This path is built but not yet confirmed end to end. It is in alpha.</Callout>

## What DorkOS checks

DorkOS does not run a sign-in flow for this setup. It connects to the configured server and asks for its tool list. DorkOS adds the connection only when both steps work.

If the server rejects the connection, times out, or cannot be reached, DorkOS shows an error and adds no account. A server that requires a new OAuth sign-in cannot connect through this alpha setup yet.

## What you get

This path verifies and inventories one account per configured server. It does not grant the server's tools to agents. A generic MCP tool list does not provide the immutable versions and safe classifications DorkOS requires for exact owner-reviewed access. If you need brokered actions now, use the [Composio](/docs/connections/composio) path.

## Set it up

<Steps>

<Step>

### Have a remote MCP server ready

You need a server you can reach over the web. The configured connection must already have access. This is usually a server you host or one that needs no sign-in.

</Step>

<Step>

### Tell DorkOS about it in your config file

Raw MCP servers live in DorkOS's config file at `~/.dork/config.json`, under `connectors.rawMcpServers`. Each entry names the service and where its server lives:

```json
{
  "connectors": {
    "rawMcpServers": [
      {
        "slug": "notion",
        "displayName": "Notion",
        "url": "https://mcp.notion.example/mcp",
        "transport": "http"
      }
    ]
  }
}
```

The four fields:

- `slug`: a short id for the service, like `notion`. Lowercase, no spaces.
- `displayName`: the name you want to see on the Connections page, like `Notion`.
- `url`: the server's address.
- `transport`: how DorkOS talks to it. Use `http` for Streamable HTTP (most servers) or `sse` for older servers that stream over SSE (server-sent events, an older streaming style).

DorkOS reads this list when it starts. After you add or remove an entry, restart DorkOS to pick up the change.

</Step>

<Step>

### Connect it

Open **Connections** in the sidebar. Your server now shows up as a tile in the Services grid. Click **Connect**. DorkOS checks the server before it adds the account.

</Step>

<Step>

### Check its status

The account appears under **Connections** after verification. It remains unavailable for agent execution in this alpha. DorkOS will not expose the remote server directly or turn its unversioned tools into broad agent access.

</Step>

</Steps>
