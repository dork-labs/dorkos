          **Preview.** This operation may change in any release.


          One stream for the chat list and everything else that changes: rooms,
          tasks, agents, settings, approvals, Relay, extensions. Each SSE frame
          is `event:` (the event type), `data:` (that type's payload, described
          below) and, on every event after the opening frames, `id:` (an opaque
          resume cursor; send it back whole). Every connect opens with
          `connected` (with `resumed: true` when it picked up from your cursor),
          then any missed events, then one `session_status` for each chat that
          is working, waiting on a person or stopped with an error; those
          opening frames have no `id:`. The server keeps the last 500 events (at
          most 512 KiB) for replay, filtered with the rights you have when you
          reconnect. Over SSE a `heartbeat` frame with empty data arrives every
          15 seconds. The same path answers a WebSocket upgrade, which is what
          the DorkOS app uses: each message a JSON frame `{ event, data, id }`,
          resuming from `?resume=`. An event addressed to a person (settings,
          the inbox, an ask's detail) never reaches a reader that presents an
          agent token.
