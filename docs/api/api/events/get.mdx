          **Preview.** This operation may change in any release.


          One stream for the chat list and everything else that changes: rooms,
          tasks, agents, settings, approvals, Relay, extensions. Each SSE
          frame's `data:` is one event, `{ seq, at, type, payload }` (described
          below): `seq` is its place in this stream (it only grows and may
          skip). `seq` is `null` on a frame outside the numbering (the opening
          frames, the cold-connect snapshot, the heartbeat): never store it as a
          position, and never use it to order or drop a frame. `at` is when the
          server emitted it, `type` the event type and `payload` its data.
          `event:` repeats the type and, on every event after the opening
          frames, `id:` is an opaque resume cursor (send it back whole; read
          `seq` from `data:`, never from the id). Every connect opens with
          `connected` (with `resumed: true` when it picked up from your cursor),
          then any missed events, then `tunnel_status` with remote access as it
          is now, then one `session_status` for each chat that is working,
          waiting on a person or stopped with an error; those opening frames
          have no `id:`. The server keeps the last 500 events (at most 512 KiB,
          so fewer when events are large) for replay, filtered with the rights
          you have when you reconnect; a replayed event keeps its first `at`. A
          `heartbeat` event arrives every 15 seconds. The same path answers a
          WebSocket upgrade, which is what the DorkOS app uses: each message is
          the same event, `{ seq, at, type, payload }`, with the cursor beside
          it as `id`, resuming from `?resume=`. Only a person reads it: an agent
          identity or an approval token, a page on another site and, with login
          on, an API key without a browser session are refused with
          `person_only` (a `4403` close frame on the socket). Who may read each
          event (a room, a read cursor) is checked as each frame is written,
          live or replayed; a cursor gives no rights of its own.
