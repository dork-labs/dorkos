          **Preview.** This operation may change in any release.


          One stream for the chat list and everything else that changes: rooms,
          tasks, agents, settings, approvals, Relay, extensions. Each frame is
          one `DorkOsEvent`: the SSE `event:` line is its `type`, `data:` is its
          `payload`, and every event after the opening frames has an `id:` whose
          last part is its `seq`. `seq` only grows within this stream and may
          skip numbers, since you are not sent events that are not yours. Every
          connect opens with `connected` (with `resumed: true` when it picked up
          from your cursor), then any missed events, then one `session_status`
          for each chat that is working, waiting on a person or stopped with an
          error; those opening frames have no `id:`. The server keeps the last
          500 events (at most 512 KiB) for replay, filtered for each reader
          exactly as live events are. Over SSE a `heartbeat` frame arrives every
          15 seconds. The same path answers a WebSocket upgrade, which is what
          the DorkOS app uses: each message a JSON frame `{ event, data, id }`,
          resuming from `?resume=`. For people, not programs: it carries what a
          person may read.
