> **Keep it true.** When something ships and passes its tests, the pull request that ships it moves it up here, in the order list and in the demo-claim gate.

## How we order work

We work toward the best product, not toward dates, and as fast as we can do it well (ADR `261124-150515`). The roadmap is one ordered list. An item sits where it does because of what it needs and what it unlocks, and the reason is written beside it. A milestone is an outcome with a short list of checks, such as "the Community Space is open". It is reached when its checks pass, and it has no date. Claims follow what is built: the demo-claim gate below says what any public surface may say.

## Now (in flight)

1. **One definition for every action.** The API becomes a projection of capabilities: one error shape, one event contract and a generated client (DOR-4977). Why first: every later way in (sending to an agent, the tools a computer calls, what a mini app may do) is defined here once. This is where "everything programmable" starts: a CLI, an SDK and API, one source of truth with every surface projected from it, and no raw database access.
2. **One name for every thing.** `dork:` references, signed outward writes, and the work graph: the links between agents, chats and work items (DOR-4966 and DOR-4973; the earlier DOR-2754 was canceled on 2026-11-10). Since 2026-11-21 "everything programmable" rests on this work graph. Why here: the run record, the computer record and the wake below all name things with it. State: part built. In: one reference type and the link route for it; the edge store with its writers so far (a chat that is re-keyed, a fork, a chat that starts a chat, and a pull request a chat opens with the tickets it names); the lineage query; and the read tools for an agent's chats, a chat's tree, and the pull requests and tickets of a chat or an agent (DOR-4967, DOR-5046, DOR-4968 for the store, DOR-5263, DOR-5264, DOR-4969, DOR-4970). Outward writes from this repo are signed with references. Left: worktrees and to-dos as edges (DOR-5265, DOR-5266), the views in the app (DOR-4971), claims as edges (DOR-4972), every surface generated from the registry (DOR-4973), and signed outward writes from the Flow plugin (DOR-5047).
3. **Agent teams that ship.** Hand-offs and reports that land, quiet rooms, and one work order (the "Agent teams that ship" project). Why now: it is how everything else gets built, and its failures are the test cases for item 5.
4. **Codex, OpenCode and Doe work like Claude Code.** Why now: the computer side must treat every runtime alike, and cloud agent computers run OpenCode or Doe. Part of it is Doe, our own agent engine (DOR-2782, state: To do). It is built in order: the engine package (DOR-2786), then plugging it into DorkOS as a runtime (DOR-2787); together they unblock onboarding and model choice. A Codex agent builds it. Reuse first from the Pi ecosystem before writing our own; tools load lazily; every DorkOS capability becomes a Doe tool. The app only ever says "Runs on: DorkOS".

Beside items 1 to 4, always: maintenance, release branches and analytics.

## Open risks

Each of these shapes what the docs may promise.

- **Model vendors' terms** decide how a person's own subscription sign-in may be used through DorkOS, and whether DorkOS may pay for model use inside hosted computers. The design keeps sign-in the person's own, through each vendor's own flow, and DorkOS never carries a Claude login. Docs promise nothing beyond today's behavior.
- **Laptop memory.** Each running agent desktop takes about 1.5 GB, so a 16 GB Mac runs about two or three at once.
- **US texting** needs carrier registration, and banks often reject internet phone numbers for login codes. Calls come first.
- **Lost laptop, lost identity**, unless the person keeps a recovery file or an optional backup.
- **Listing published pages in public** draws spam and phishing. It needs its own web address and abuse controls before it ships.
- **Agents can still read filled-in passwords.** An agent that controls its own computer can read a password field after it is filled in. "Agents use secrets without seeing them" holds for the vault's own path only.
